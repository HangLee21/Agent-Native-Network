# OLED 显示证据含义

以下是 H-005 显示接口的语义，不是新网络协议。E1 把实际执行事件映射到此接口，E2/C 按冻结实现核对来源。屏幕为单色，不通过颜色暗示成功。

| 事件 | 可接受的真实来源 | 屏幕含义 | 不能据此判断 |
|---|---|---|---|
| TX_QUEUED | 本地业务/转发队列明确受理 | QUEUED；目的端未确认 | 已上空口、已送达 |
| TX_SUBMITTED | 本次无线发送 API 返回受理成功 | SUBMITTED；目的端未确认 | MAC 成功、目的端收到 |
| TX_LINK_OK | 与该引用及实际下一跳关联的 MAC 发送成功回调 | LINK OK；目的端未确认 | 多跳终点交付 |
| TX_LINK_FAIL | 对应 MAC 失败回调 | LINK FAIL，保留错误；目的端未确认 | 目的端一定没收到 |
| TX_LOCAL_FAIL | 本地排队/发送 API 明确报错 | LOCAL FAIL，保留错误 | 已测得端到端丢包率 |
| TX_TIMEOUT | 已有执行逻辑真实发生本地发送/队列期限超时 | TIMEOUT，保留错误；目的端未确认 | 目的端一定没收到 |
| ANN_CONFIRMED | 原 ANN 的源端 endpoint ACK 匹配 origin/boot/seq | 仅 ANN：ANN ACKED / ANN CONFIRMED | MID 具有相同机制 |
| RX_RELAY | 合法接收且最终目的不是本机，交给中继处理 | RELAY ONLY | 已转发、终点收到 |
| RX_DEST | 合法、最终目的为本机，并经执行者判定为唯一交付 | DEST RECEIVED，本机接收计数增加 | 其他源端已知道收到 |
| RX_DUPLICATE | 最终目的为本机的重复接收 | DUP DEST RX，重复计数增加 | 新的唯一交付 |
| CFG_RECEIVED | 配置解码获得原发送者及序号 | RECEIVED | 配置已执行、全网已采用 |
| CFG_APPLIED | 本节点路由执行实际采用该配置 | APPLIED，显示该原发送者/序号 | 业务已送达 |
| CFG_STALE | 作者原发送者/序号规则判为重复或旧配置 | STALE，旧配置计数增加 | 创建新源或新版本提交协议 |
| CFG_REJECTED | 本地明确拒绝配置 | REJECTED；来源/序号未知则显示 -- | 真实来源可由上一跳推断 |
| COMMAND | CLI 解析和受理/拒绝结果 | CMD 名称和 OK/ERR | 无线发送或目的交付成功 |

MID 模式拒绝 ANN_CONFIRMED。模块没有发送函数，不新增端到端 ACK、无线重传、心跳、目的端反馈或探测流量。没有收到端点证据会一直显示 UNCONFIRMED；它不会因为等待一段时间自行创造 TIMEOUT。E1 不得为这个显示接口给 MID baseline 增加 ACK 等待定时器。

目的板的 DEST RECEIVED 是该板的本地观察。若电脑汇总多个节点日志，可在外部监测结果中关联接收记录，但不要伪装成源板已获得无线确认。必须说明日志通过 USB/串口还是占用无线资源；本模块本身不收集远端记录。

同一完整引用里的 source/boot/seq/flow 按存在位关联；不把不同消息或不同 boot 的事件互相确认。晚到的旧消息结果不改变新 TX 状态。TX、RX、CFG、CMD 为独立记录：例如本机收到来自别人的数据且 CMD OK，不会清除本机发往另一目的的 UNCONFIRMED 或错误。发送故障次数、最后故障和各类累计计数保留，计数饱和不回绕。

E1 负责提供真实下一跳和合法目的接收事件。Planner 输出的候选下一跳不能当作本次实际下一跳；中继收到不能当作目的交付。模型不是原始报文认证或去重算法，不取代 E1 的执行逻辑。

seq/flow/config seq 在屏幕显示十六进制，未知为 `--------`；MAC 未知为 `--:--:--:--:--:--`。完整字段、存在位、真实事件时间及屏幕快照应保存在 H 的后续采集记录，供 E2 比较显示和日志。

H-005 的 host/fake I²C 结果只证明软件分支；旧 H-004 的用户确认只适用于旧固件。新模块的最终目标构建、I²C 故障隔离实物检查、OLED 页面观察、显示开启/关闭影响和 MID RF 交付目前均未验证。所有相应测量留 null。
