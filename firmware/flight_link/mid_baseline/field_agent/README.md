# Five independent field nodes

This app is a separate fork of E1-026's sealed mobile telemetry source. Old packages/shared source remain. Radio routing remains on boards, normal payload0..160B, no PC route table. New agent config, bounded logs, OLEDAPI3, dynamic PC service extension and ordinary fixed-channel Wi-Fi/IP are documented in GATEWAY.md. All five boards run the same firmware and may independently become PC entries; no required entry MAC.

Pre-field, H records actual MAC/build/mode and rollback choice, flashes app-only, then applies prepare.jsonl when idle. The generated commands deliberately replace prior radio profile, so preserve any intended old config first. Supply actual2.4GHz channel/BSSID/PCIPv4 privately with configure_wifi.py; it verifies project MAC/idle before sending credentials, disables DTR/RTS, prints no SSID/password/rawTX. FIELD_SSID/FIELD_PASSWORD environment or hidden prompts, no credential CLI args/logs/repo files. Do not route ip_config through a generic raw-TX logger. Reuse actual source MAC labelsA..E only after H identification.

Then apply configure.jsonl separately to every board: field_gateway logicalPCid, field_config, route_config group/channel/autostart. Default example intervals5..10s, readable ASCII length20..128, rosterallfiveMACs (each excludes itself), PCservice also eligible, checkpoints60s. roster is a destination name list, not routes. Every round re-draws interval/target/length from each board's own esp_random; no host timer/read/relay/RNG service. Unknown destination continues to next timer. observed mode uses current confirmed neighbors plus8 identities learned from accepted SR01 paths/destinations for60s and route cache; it is not global service-name discovery. PC target is a bounded logical service query, not fixed board.

Generator pause/resume is independent of radio. start_on_boot is persistent reset policy; field_pause/resume are runtime only. Set start_on_boot=false while paused to keep it off after reboot for Pi integration. Default no field config is off, GPSunknown and MT01broadcast off. Position injection remains explicit and source-labelled if later required; no distance inferred from RSSI or GPS demo. Human field_mark(segment,note) supplies manual site/measurement label. Config field segment change resets per-segment counts; old dedup retained. Packets crossing markers must be joined by original identity, not compared using local segment totals alone.

OLED main page shows original business seq and TX/relay/RX stage, latest accepted physical RF peer/RSSI/age (can be HELLO, not necessarily that business origin), T=sourceRF actualsubmit/F=relayRFsubmit/R=destinationRF unique counts capped9999 on screen (full UART counts), and segment/agent running. Not end-to-end delivery for source. Driver/power/PRG baseline preserved in owned component copy; physical pixels still require H observation.

field_records(after,limit<=8) exports128-row RAM ring with originalMAC/boot/businessseq/dst/kind/bytes/local time/segment; overflow/truncated visible.16 originboot states x64seq perkind are dedup bounds; old-window and full identity drops counted. field_ip_records separately exports retained IP events, and PC UDP oprecord can export a board's RF journal while in AP coverage without USB. Receiver rawRF arrivals through different entries are different RF identities; PC application dedup uses stable(pc_id,pc_session,transaction) at final board, so do not equate rawrx_local duplicates with a second application delivery.

Checkpoints are small NVS summaries, not raw-byte logs: first write only after60s uptime, >=60s between attempts incl failed ones, auto checkpoint_s=0 disabled or60..3600s; never per-packet Flash. field_saved_summary is a prior/current checkpoint tagged boot/segment/uptime, never merged with newboot counts. Power loss erases RAM ring and loses counters after latest successful checkpoint (up to configured period plus deferred/failure window, potentially all if none succeeded). Exact endpoint bytes require powered export/PC log. Do not assume unplugging the only USB power connector preserves boot; use maintained power and wireless export or record the reset boundary. Summary alone cannot reconstruct missing source/receiver identities or prove all packets.

Wi-Fi association is not PC service eligibility; matching PC session lease is required. service cache<=3s, W200ms/absolute1.5s, stable path tie rules and alternative paths. IP loss and RF neighbor failure have separate causes. Unknown delivery is not automatically resent via another entry. Downlink PC seeks fresh board route evidence/valid direct registration; up/down may use different entries. At most16 request records/32 final PC-delivery identities/16 IP event rows; eviction/reset boundaries explicit. PC closes hotspot -> local standalone traffic continues, map/report gaps remain unknown. No Internet/Python process is required on a board.

H tests real USB-bank boot, simultaneous entries, Wi-Fi-direct vs ESP-NOW1/multihop, current-entry IP suspension, alternate selection, all entries absent, raw final bytes, channel preservation, RSSI and real OLED. E1 host/core/fakeI/O/ELF/image evidence is not any of those physical measurements. Build and rollback parameters in HANDOFF; all resource peak values not read from live boards remain unverified. Runtime field_status and IP status expose heap minimum/stack free and drift/error counters; compiled static object sizes are not peaks.

M-033 immediate IP neighbor snapshots are specified in NEIGHBORS.md. Deployed boards retain existing NVS configuration during H-only app updates; no initial-setup commands are needed for this upgrade.
