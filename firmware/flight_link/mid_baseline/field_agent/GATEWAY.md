# Field IP v2 / dynamic multi-entry contract (supersedes fixed-entry v1)

All boards run identical firmware and may concurrently register0..5 entries. No normal field config contains a required entry MAC. PC logical destination is stable pc_id (nonzero uint32); current PC process has pc_session (nonzero uint32). Entry STA MAC and board boot are independent identities. UDP/IPv4 entry8792/PC8793 configurable, JSON datagram<=1024B, schema field.ip.v2. PC source IPv4 restricted to configured address. Credentials remain device-local; never return/log SSID/password. Trusted hotspot protocol, no cryptographic authentication claim.

Entry announces registration request every3s while IP-connected: event register,entry_id,entry_boot,pc_id. PC replies op lease with pc_id,pc_session,entry_boot,lease_ms(1000..10000). Only matching current boot response creates/renews service eligibility; IP association alone is insufficient. Lease loss affects only this board. No automatic infinite connect loop: pin allowed country/channel range to configured single2.4GHz channel, known AP BSSID, roaming off, one bounded5s connect, retry>=60s; fail to pin disables association while ESP-NOW continues. H must verify actual radio behavior. AP channel changes require deliberate shared-channel reconfiguration.

PC ops: hello {pc_id,pc_session}; lease as above; route {pc_id,pc_session,entry_boot,transaction,dst}; send {pc_id,pc_session,entry_boot,transaction,dst,payload_hex}; poll {pc_id,pc_session,after}. transaction uint32 nonzero. send<=128 original application bytes. Old entry_boot rejected; duplicate retained identity with changed dst/bytes rejects id_reuse.16 source-request records,16 retained<=896B async events, explicit cursors/truncation/overflow; no RF business retransmission by poll. PC must not blindly reissue unknown delivery across reboot/eviction/change of entry.

Registration/status/event base: schema,event,entry_id,entry_boot,pc_id,pc_session. hello/status reports capabilities max_payload_bytes128,channel,lease_remaining_ms,IP availability,event retention. route result includes transaction,dst,reachable,path,expires_in_ms/evidence age; unknown times are null. Direct destination registered on this board gives Wi-Fi path[self],0ESP-NOW hops; else board performs bounded actual route query. PC queries currently valid entries when evidence absent, selects fresh reachable proof then hop count,full path MAC bytes,entryMAC. Previous ingress is only a hint. Normal user does not pick an entry. Up/down entries may differ.

accepted means source admission and contains transaction,original entryMAC/boot/business seq,dst. delivery means destination-board receipt with correlated logical PC identity and exact original bytes; it is not the PC inbox. inbox is remote-to-PC payload received by the entry, retaining remote origin/origin_boot/seq and transaction,logical_dst pc:<id>,RF_dst actual entry. E2 records PC actual receipt only when that UDP event arrives. Events event_cursor are deduped by(entry_id,entry_boot,cursor), push and poll replay same record. Logical destination separately dedups PC downlink by(pc_id,pc_session,transaction) across entries, rejects changed bytes, and never performs a second application delivery. Entry-side dedup alone is not claimed sufficient.

FG02 RF envelope20B inside SR DATA(160B unchanged): magic FG02 at0,kind at4(1PC->board,2board->PC,3destination receipt,4telemetry),reserved0 at5,body_len u16 at6,pc_id u32 at8,pc_session u32 at12,transaction u32 at16. Kind1/2 original app<=128B; kind3 body original entry boot4+source business seq4+original app<=136B,total<=156B. Kind4 report body<=52B. PC downlink identity is(pc_id,pc_session,transaction); remote uplink remains original sourceMAC/boot/transaction. No silent truncation. Plain board-to-board business still160B. Source admission, destination receipt, PC arrival remain distinct. No automatic resend of unknown business when changing entries.

Stable PC service address is reserved locally-administered MAC02:ff:<pc_id as4big-endian bytes>, never configured as a physical board. Extend the frozen SR01 header with types5SREQ,6SREP,7SDATA,8SERR (ordinary types1..4 unchanged). Same60B path header and160B body. Service dst is logical PC address, path ends at actual entry. Eligible entries answer SREQ only with unexpired PC lease. SREP body8B pc_session+lease_remaining_ms(u32LE). W200ms/absolute1500ms; expired evidence excluded, then fewest hops/full actual MAC path ordering. Store bounded alternative paths with at most3s proof/cache validity capped by reply lease; later new packet may choose another valid candidate or rediscover. Bound packet keeps one path. Service DATA at an entry without valid PC lease produces SERR with logical-egress edge index=n-1; RF edge errors remain distinct. Queue/neighbor checks still bind next-hop boot. No blanket network service advertisements or unbounded flood/retry.

field_gateway {pc_id,agent_to_pc,report_period_ms:0|30000..3600000} is persistent logical service config, no entry_mac required. An entry with current local PC lease sends its own PC-destined data directly over IP; non-entry searches service. Remote reports also resolve service dynamically. Receipt/report/ND/field business counters separated. Telemetry reports are partial,<=2 directed rows per source per>=30s; header uptime4,segment4,admitted4,forwarded4,received4,overflow4,row_count1,reserved3; each12B row peerMAC6,rssi_i8,channel,age_seconds_u16,state,valid_flags. sample_age is a lower bound at construction; transport_age_ms=null. No fake GPS or full graph. PC offline leaves every board's ordinary generator/routing running; finite retained entry queues eventually overflow with explicit gaps.

IP config before field use: ip_config {enabled,ssid,password,bssid,channel,pc_ip,pc_port,listen_port,pc_id}; all may use same hotspot configuration, only those actually within coverage+lease become entries. Runtime credentials are not embedded in examples, source snapshots or logs. Debug fixed entry is not a deployment prerequisite. Actual multi-entry/zeroUSB/power-bank/shared-channel behavior requires H evidence, not host fixtures or single-board IP echo.

Entry-retained events include event_created_ms and entry_event_age_ms; poll updates receiver-local queue age without changing event_cursor or RF business. Source report age remains a lower bound, transport_age_ms staysnull. field_ip_records(after) exports up to4 retained IP events over maintenance UART; last_ip_submit_ok/ip_attempts are local UDP submission facts, not PC arrival. Raw ESP-NOW field_records and IP records are distinct ledgers. Generated own-node direct-IP inbox includes source_admitted/transport=wifi_direct. E1-028 candidate: reports always attempt the bounded live UDP send before retention policy is applied. A full16-slot ring skips only report retention and increments event_overflow; it never evicts a business event for a report. Poll does not acknowledge or release slots. A skipped report cannot be recovered by poll, and a successful local UDP submit does not prove PC arrival. All gaps/size rejection increment event_overflow.
## Additional v2 operations and boundaries

lease success replies status; register/status include service_live and lease_remaining_ms, not just remembered pc_session. Last4 prior PC sessions are retired during this board boot; late old lease cannot overwrite the newer registration. A delayed destination receipt preserves original PC message session even if the entry now serves a different PC session.

With current pc_id/pc_session/entry_boot: field_status returns compact agent counts and runtime heap/stack fields; record {after} returns one RAM journal row (record_cursor namespace separate from event_cursor), including raw payload, original identity and overflow range; agent {running:bool} pauses/resumes only generator; suspend {duration_ms:1000..300000} acknowledges ip_suspending then disconnects only this entry's IP, keeps channel-pinned ESP-NOW/generator, automatically retries after the interval. This is an explicit fault-test control, not fixed-entry deployment. Status shows suspended_until/channel drift/restore failure counters. No op contains network credentials. Maintenance record export is directly available when that board is in hotspot coverage; out-of-coverage boards only send bounded partial reports, not magically full raw logs.

UDP response limit1024, oversized requests/binary-NUL/trailing JSON/duplicate keys rejected. Original app payload128B and normal board160B are never truncated. IP-retained records16x896B are separately exported by UART field_ip_records(after), containing UDP submit fact/attempt count and event age; PC actual arrival still belongs to E2 receiver logs. PC IP-destination own-board data is Wi-Fi-direct and does not fabricate an ESP-NOW submission. RF field_records and IP event ledgers must be analyzed separately, as must ordinary business/receipts/telemetry. Source summary is not a substitute for per-packet raw data.

Normal stop disconnects STA and restores world-safe auto country range before closing radio; H checks channel_restore_failures and actual intended channel before reverting old firmware. Explicit ip_clear removes this experiment's credentials; do not erase whole NVS/eFuse. Country/connection APIs are real SDK calls, but no hardware channel preservation, bank power independence, live AP association or failover is asserted by compilation or fake I/O fixtures.

M-033 candidate adds op neighbors with nonretained query-correlated compact full ND/RF snapshots (neighbors_api=1 in hello). See NEIGHBORS.md for exact tuple encoding, epochs, 500ms rate guard, age ceilings and required PC RTT/replay checks. It adds no RF transmissions or report-rate change.
