# E1-032 恢复候选与未完成项

2026-11-15。历史 18、29、14 号构建快照保留；当前 31 默认和 33 实验候选已完成目标构建，尚未经独立审查或实板通过。源码合同见 `CONTRACT.md`，最新 12 项主机夹具见 `simulation/outputs/E1-032/20261115-30-final-regression/`。

## 已实现并离线检查

- LoRa worker 遇驱动 RX 错误、ACK 或上报 TX 失败/超时、重听失败，关闭端口、丢弃待发旧帧，用原配置按 1、2、4、8 秒恢复；持续失败冷却 60 秒后继续尝试。恢复不会重置 LRC2 的去重表。`lora_worker` 夹具调用真实 worker，FreeRTOS 队列、时间和射频端口为假对象：分别注入以上错误，验证恢复后处理命令与回执、上报继续，以及重复命令不重复执行。调度器夹具另检查连续失败的退避/冷却。没有真实射频、SPI、NVS 或板端任务调度证据。
- FLW2 将本地路由提交拒绝与成功提交分开，前者按 100ms 重试且总寿命仍为 1050ms；回执超时仍为 unknown，带提交与拒绝次数。成功提交不等于空口发送。`reliable` 夹具注入两次本地拒绝后成功提交，也测试目标重启和 ACK 丢失。
- 可查询双向直邻或最近合法源帧中该源的 boot，10 秒过期、短期不同 boot 冲突隔离；这只是未认证观测，不保证目标仍在线。`boot_catalog` 夹具验证冲突、过期和容量。实际现场入口及跨节点发现可靠性尚未打通/验证。
- ESP-NOW 启动失败安排冷却重试；发送回调超时先记 unknown，不以同一外层包自动重放，再关闭会话并重启；已排队旧会话回调通过 epoch 拒绝。路由核心夹具检查 unknown 不重放，真正驱动回调、重启后链路和竞态未经过驱动级故障注入；不能据此称已经证明恢复。
- NVS 初始化错误退避重试，不自动擦除。现有配置载入缺少经验证的最后可用副本与写中断故障验证；LoRa 配置读取无有效值时仍落到关闭角色，不能称配置恢复已完成。

## 明确未完成

当前候选将软件任务推进监测与 ESP-IDF 任务看门狗分开：软件监测发现 LoRa 单侧停滞只报告；启用的 LoRa worker 真卡死可由 30 秒任务看门狗触发整机复位，连续 3 次后 RTC 策略抑制继续复位，最多三次 Wi-Fi 也会中断。LoRa worker 创建/队列分配失败后的有限退避重试已加入，假队列夹具覆盖。任务看门狗与软件监测不覆盖所有启动前或其他复位循环，真实 timer-group 计时、RTC 保留、复位后收发仍未验证。网络配置增加经过双向邻居确认的备份；其他配置及真实 NVS 断电验证仍缺失。ESP-NOW 启动/丢失回调恢复未做实际驱动级故障注入。生产入口、服务集成和无人机现场测试另由对应角色协调。上述缺口是 M-039 自主恢复验收条件，不能用提示用户手动排障代替。
