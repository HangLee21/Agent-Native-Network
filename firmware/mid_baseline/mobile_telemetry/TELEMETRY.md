# Mobile telemetry v1

Serial commands/events and ownership are frozen in E1-026 task card. MQTT/IP/GPS hardware are outside this board adapter. All event times are receiver/local board monotonic times; never subtract another board/Pi monotonic timestamp. Inject age instead. Missing RSSI/channel/position/accuracy are JSON null. Position sources are gnss, simulated, unavailable; gnss is the local provider's declared provenance, not independently verified GNSS hardware.

No-location frame uses fix0, coords0, accuracy unknown; position identity0 means provider unavailable. Stale>30000ms is fix0/coords0 on air; source remains declared source, age saturates60000. Position freshness cannot be renewed by replay or serial re-reading. Radio announcement seq differs from Pi position seq.

Receiver validates format/group/physicalMAC equality. In discovery/autonomous mode, current known heard/confirmed neighbor and boardboot must match; the position frame itself does not create/renew ND01 neighbor evidence. Same boardboot/announcement seq duplicates or older frames do not refresh age. A new boardboot retires prior boot (last4 held during this receiver boot). Peer table8; local RF sample table8; full table increments explicit counters, no unbounded allocation. Restart clears all volatile telemetry. No authentication or durable anti-replay claim.

Each RF input record is copied from esp_now_recv_info_t.src_addr and rx_ctrl inside callback, including callback receive time. No Wi-Fi callback pointer escapes. rf_rx is emitted from main task, sample_age_ms includes callback queue residence. Null rx_ctrl gives unavailable; RSSI0 remains a valid supplied integer. Channel invalid/outside1..14 is null. Frames rejected by link_filter still have physical rf_rx observations but filtered=true; they do not enter accepted RF neighbor summary or protocol state. Sampled RSSI is previous hop to this receiver, never inferred origin-to-destination or distance. Queue drop/overflow remains visible and protects the radio as before.

Short/oversize positive-length callback frames keep metadata and actual frame_bytes; only first250 payload bytes are copied and protocol length checks reject unsupported frames. Unknown Pi position identity is JSON null (wire0 sentinel). Position age includes receiver callback queue residence, but is a carried age estimate without synchronized clocks or measured RF flight time. Peer snapshot peer_boot_matches=false hides coordinates from a prior/unknown ND boot without fabricating an older age. RF aggregate_last_valid_age_ms ages historical mean/min/max separately when the newest metadata is unavailable. No GPIO/I2C/OLED changes accompany telemetry.

Default position/status broadcast interval10000ms (runtime config10000..60000), only active dynamic modes with shared group. Idle/static/MID do not add frames. Business/control queues and in-flight callbacks have priority; skip/defer telemetry when busy, no catch-up burst. One broadcast52B, no reply; generated/submitted/link callback counters separate. Normal rate0.1frame/s,5.2 application B/s/node; real 802.11/ESP-NOW overhead, hardware retry and airtime are not measured by this calculation. Existing ND01 HELLO and SR01/MID1 business encodings and160B limit remain unchanged. Telemetry disabled mode adds no application radio frames. Snapshot/query emits serial only.
