# E2-033 独立 LoRa 控制仿真

运行：`python -X utf8 simulation/uav_lora_control/run.py --output simulation/outputs/E2-033/NEW_RUN`；输出目录必须不存在。`verify.py --input RUN --output NEW_AUDIT` 逐事件交叉核对并调用 E2 独立规范化评价器。两者均为有限单进程，不访问硬件、网络或旧结果。

模型：30 个发送节点加独立八 RX 信道/单 TX 网关；频点 470.3 至 471.7 MHz，间隔 0.2 MHz。SF7/BW125/CR4/5、显式头/CRC、8 符号前导，128 字节上行、32 字节下行；符号 airtime 按 LoRa 整数公式计算。假设所有上行在无碰撞时可达，忽略传播、捕获效应、跨 SF 干扰和八通道额外硬件限制；同信道重叠全部失败。网关发射时所有接收通道不可用，切换额外占用 20 ms；发射单队列串行。此为保守半双工假设，未以真实网关下行校准。`uplink_airtime_sum_s` 为节点 airtime 之和，允许重叠；`downlink_airtime_s` 为单 TX 占用，不是实际 duty-cycle 合规证明。

三种模式：单频随机、八频随机、八频调度。初始所有节点随机；八频调度必须收到且执行目标专属 `schedule` 命令才采用每节点槽位和频道，未收到仍随机。槽位按每频道四个节点、0.8 s 间隔设置，非预先发放给节点。每节点初始 10 s，±0.25 s 抖动；100 s 对每节点发单独 `period=15 s` 命令。每个命令有 id、版本、目标、有效期、最多四次尝试；网关只能在收到该节点上行后排入 1 s 后的接收窗，若排队太久、漂移和窗口不符或下行随机丢失则不执行。接收窗宽 200 ms，要求完整 32 字节帧保守落窗；节点时钟偏差及窗口抖动为假设。网关 TX 不等于节点执行，节点执行不等于网关收到执行回执。模拟还假设 10% 的已承载在成功上行中的应用回执在网关侧处理丢失，以产生重试和重复命令；相同 cmd_id 不重复执行。帧长未因回执改变，是简化。

配对种子控制初相位以及独立的每节点抖动/频道随机流；自适应调度和命令接收改变以后的实际发送时刻和负载，故不同策略的 offered 数可不同。下行随机流按事件消费，策略不同会消耗不同数量，种子相同不保证逐次相同丢包。基准每模式种子 11/22/33，下行丢失 0.1、常量偏钟 0、每节点漂移 ±20 ppm；额外三例采用不同种子分别为 (丢失0.5,偏钟0)、(0.1,0.12 s)、(0.5,0.12 s)，是有限案例，不能将这些单例直接视为严格配对敏感性估计。调度组有 30 个部署命令加 30 个周期命令，随机组仅 30 个周期命令，比较应同时看下行开销和 offered 分母。

每个节点设 8 个合成环形邻居，每次上报轮换 4 行；邻居集合固定，不代表 Wi-Fi 移动拓扑或实际无线发现。逐节点报告 AoI、逐观察者/邻居 AoI 按源采样时间分别维护，每秒采样；仅已收到样本参与 AoI P95，未知另由覆盖率体现。覆盖率表示 240 个有向条目中年龄不超过 30 s 的比例，按秒求平均，未知视为未覆盖。原始 events.jsonl 同时每 5 s 输出 AoI 评价采样点，因此独立评价器的 AoI 样本密度与主 summary 的每秒采样不同。邻居 epoch 标识为 `node@boot`，模拟 boot 固定为1，未模拟重启。300 s 结束仍在途的帧计入 offered，记录 censored_uplinks；统计为模拟窗口结果。

原始事件逐 run 保存 offered/delivered、碰撞原因、邻居更新时间、命令发送、未收到原因、执行、重复接收与执行回执；commands.json 记录每个目标及处理时间、版本和有效期，nodes.csv 给各节点分母、接收、AoI P95 和覆盖率。没有将网关 TX 或上行链路回调当作目的执行。此实现仅是 LoRa 控制通道机制与容量假设的有限模拟，不是 RF 测量、下行实机证明、Wi-Fi 路由实验或高速 UAV 动态轨迹。

事件文件按模型追加顺序保存：初始化阶段的 100 s 命令声明可能出现在较早时间的事件前；消费时应按 t 稳定排序。重复命令使用相同 cmd_id，按节点去重执行；应分别统计重复收到和重复执行。
