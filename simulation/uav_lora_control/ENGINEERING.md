# 工程阶段：独立 Wi-Fi 分析与 LoRa 对照

## Wi-Fi 已保存结果

`wifi_v1_analysis.py` 针对 E1-030/05 的冻结 JSONL 生成逐包、逐run和逐种子配对 CSV；逐包键为源/boot/序号/目的，收件要求 E1 写出 bytes_match。针对 0.5/1/2 秒期限，`d*_eligible` 仅包含到仿真结束前有完整观察窗口的发包；逐包文件还记录提前收到或右截尾的状态。`unreceived_no_unique_cause` 包含未能归到具体业务包的未收到，不能用累计 no_route 控制事件的请求序号给业务包编造失败原因。四跳几何可达仅为发包时采样值，不是路径持续存在的保证。原54次模型的25 ms信道时隙及队列近似未校准，所有统计为该模型的诊断结果。

## LoRa 控制变量

`engineering.py` 独立于 Wi-Fi，不宣称重放真实 Wi-Fi 邻居轨迹；固定相同 seed 的外生发包时刻和 10 s 采样，三策略都用同一PHY/负载。调度模式从随机开始，须经有界串行命令真实执行后，使用 1 s 微帧、8 频、每频道4个0.25 s槽位；待发送缓存每节点1项，未获授权保持随机。容量对比中没有改周期命令；执行周期修改仅出现在独立的命令实验。

命令实验比较原先的上行后1 s接收窗和**假设已预装/时间同步**的每秒0.2 s周期接收窗；后者是模拟候选，并非现有固件特性。该候选需要准确时间基准，偏钟敏感性单独列出。两者的接受/执行回执均依赖实际模拟收件，重复按持久化命令id去重；最多4次尝试，超过60 s有效期失效。30目标在1.5 s内到达的突发与单目标分开。网关单TX队列和预测窗口受头部阻塞；没有预设所有节点成功收到配置。执行修改后本节点外生周期由10 s改15 s，故命令实验不能当固定负载容量对比。

`gateway_uplink_airtime_sum_s` 为节点发射时间之和（可重叠），`gateway_tx_s` 为串行下行占用。`total_node_rx_s` 为接收窗口预留秒数之和，是能耗代理；周期模式每节点每秒预留0.2 s，上行触发模式每次节点上报后预留0.2 s，即使该帧未到网关；预留可能与本板发射重叠，并非功耗、电池或实际接收时间实测。排队/节点发送中仍尝试下行会被计作失效。电源、同步、SPI和实际网关下行均未验证。

每节点单个待发缓存、每轮目标最多一条命令、最多4次重试；30目标和有限队列构成本场景的逻辑上界。模型中 `executed` 作为持久化幂等身份保存，重启清掉短期回执但保留执行记录；重启后显式注入的旧命令是模拟故障，不是RF注入或物理断电验证。模拟器本身使用 Python 容器，不是板端C实现；未测ESP32-S3 RAM/Flash、水位和能耗，不可把状态对象个数当字节数或工程部署通过。每60 s输出资源样本，最大值是采样观测，不保证峰值。

`audit_engineering.py` 独立核对 220 次事件、相同seed三策略每一发包的生成时刻完全一致、目标身份/去重/回执、失败原因和期限计数；两端事件时刻保留到微秒，期限边界以取整不确定区间核对。差值按20个种子做配对，并以种子为单位bootstrap 5000次，非以每包为独立重复。模型效应区间不反映信道参数或硬件不确定性。压力批次在0.2/1/2/5包每秒每节点分别用3个种子、300秒（上报128B，抽象合成业务）；长时批次两种容量和一种命令设置各3个种子、每次21600模拟秒。长时不等于实板耐久；这些LoRa测试不覆盖E1 Wi-Fi工程矩阵。

依赖E1继续提供 Wi-Fi 逐业务包终止原因和本地队列/peer拒绝关联、路径中断恢复时间、同一时钟可重放邻居/运动轨迹及新冻结事件合同。E2不改E1源码，不把请求序号当业务包序号，也不把几何图当可部署节点可用的全局知识。
