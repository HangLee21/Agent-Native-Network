# ANN v1 public interface checkpoint

2026-11-03; E1-014. Header/API checkpoint for H/E2 through M; implementation follows in the same directory. No board/target/RF validation yet. ESP-IDF candidate is exactly v5.5.1.

## Host CLI

Build: `cmake -S firmware/agent_native -B <new-build-dir> -G Ninja`, then `cmake --build <build-dir>`.
`ann_host --scenario <chain|ack_loss|echo|state|expiry|cancel|error|reboot|bounds|continuous|wire|serial|all>` prints JSON test evidence and exits nonzero on assertion failure. continuous performs 100 sequential low-concurrency transactions using the same C core, then rejects an old out-of-window sequence. This is synthetic event delivery, not RF or a performance simulation.
`ann_host --console` accepts newline-delimited commands below on stdin, emits replies/events on stdout, and runs no RF. EOF stops. External E2 tests may instead compile `src/ann.c` and `src/ann_console.c` against `include/ann.h` directly. All clocks are caller-supplied monotonic milliseconds; a reset requires a new boot ID and node initialization.

## Serial v1

115200, 8N1, UTF-8 JSON lines, request <=512 bytes excluding newline. Only flat JSON objects (strings, nonnegative integer values and booleans) are supported; nested objects/arrays, duplicate keys, invalid escapes, malformed/trailing JSON and unknown commands are errors. Nonce is required, 1..48 ASCII characters `[A-Za-z0-9_.:-]`; run_id uses the same alphabet. No shell execution. All replies carry `schema=ann.serial.v1`, `event`, `nonce`; errors carry `error` and `ok=false`.

`{"cmd":"info","nonce":"probe123"}` replies info with firmware=ann-espnow, protocol=1, node_id as lower-case 6-byte colon MAC, boot_id, build_id, chip, board=unverified, mode=idle/active. info/stats never start Wi-Fi or generate packets. Firmware boots idle. Host chip=host-synthetic, never esp32s3.

`{"cmd":"stats","nonce":"s"}` replies counters; RF retries, airtime and hardware measurements are null. `{"cmd":"stop","nonce":"s"}` stops bench/protocol, clears queued radio traffic and disarms. Source cancellations already in flight are best effort, not remotely atomic.

Explicit arming: `{"cmd":"arm","nonce":"a","node_id":"aa:bb:cc:dd:ee:ff","run_id":"r1","duration_ms":60000}` requires this exact node ID, duration 1..60000 ms. This is an operator interlock, not cryptographic authentication; the host must already have bound the physical board using H's configuration. Arming itself emits no radio traffic. `{"cmd":"start","nonce":"x","run_id":"r1"}` starts discovery only while armed for r1.

`{"cmd":"bench","nonce":"b","run_id":"r1","dst":"aa:bb:cc:dd:ee:01","count":10,"interval_ms":100,"frame_bytes":128,"echo":true}` requires armed matching run_id, count 1..1000, interval_ms>=1, span `(count-1)*interval_ms <=60000` and within remaining arm time, dst!=self. Frame bytes 112..250, or 120..250 for echo. `frame_bytes` is the **entire protocol datagram**, not payload or PHY frame; control/ACK frames may be smaller. Bench starts the protocol explicitly; after at most 60s it stops/disarms. No auto-run on boot. An error does not enable radio. No serial commands for flashing/erasing/installing.

Events generated/tx_submit/tx_result/rx/echo/stats use schema, run_id (null outside bench), node_id, boot_id, origin_id, seq, t_us, frame_bytes, payload_bytes; applicable status fields distinguish accepted-for-send, link callback, unique receive, duplicate, endpoint confirmation. tx_result success is **only a link callback**, never end-to-end PDR. All unobserved RF measurements stay null. Core event API also reports delivered/confirmed/expired/cancelled/rejected/duplicate; adapter maps them to JSON. UART/IDF startup logs may coexist; parse schema-marked JSON only. Events have nonce=null; command replies echo nonce.

## Wire v1 and core boundaries

All integers little endian, explicit serialization; never transmit C struct memory. Bytes 0..1 magic 0x41,0x4e; 2 version; 3 type; 4 flags; 5 TTL; 6 route length; 7 current route index; 8..15 origin; 16..23 final destination; 24..27 origin boot; 28..31 source seq; 32..35 remaining_ms; 36..39 state key; 40..41 payload length; 42 kind; 43 reserved=0; 44..107 eight uint64 route entries; 108..111 CRC32 (IEEE, CRC field zeroed); payload starts 112. Node IDs are lower 48 bits of MAC, 0 is broadcast sentinel only. Max path 8, frame 250, payload 138, tables 16, pending source transactions 8, outgoing/events 32. Live dedup entries are not silently evicted to admit more deliveries. Full tables/queues yield explicit rejection/counters, no unbounded allocation.

Types 1..7 HELLO/RREQ/RREP/DATA/ACK/ERROR/CANCEL; kinds transaction/state/echo. RREQ flood appends local ID, rejects loops and consumes TTL; RREP reverses the recorded path. DATA follows that path, endpoint ACK returns on its reverse. Each local pending transaction uses at most 3 discoveries and 3 DATA attempts, retry interval 500ms, source lifetime <=60000ms. Same origin+boot+seq is idempotent within the retained window; duplicate DATA re-ACKs without redelivery. DATA seen entries are **streams** keyed by origin+boot with a 64-sequence bitmap and cancellation bitmap, not one occupied slot per message. A sequence older than this window is rejected without ACK or redelivery; live streams are not evicted. Current windows expire after 63 seconds of inactivity, so no indefinite replay protection is claimed. RREQ duplicate entries separately expire after 400ms. ERROR from failed DATA link invalidates source route and permits bounded rediscovery. No free global topology. No fragmentation, no encryption/key provisioning, no guaranteed order across independent random boot IDs; latest state ordering is scoped to (origin,boot,key), with seq monotonic within a boot. A reboot needs new boot identity, not seq reset under the same boot.

Expiry is a hard local source deadline; nodes subtract local queue residence from remaining_ms. Unmeasured on-air/clock uncertainty prevents a strict global deadline guarantee; TTL and local remaining budgets still bound forwarding. No exactly-once claim across receiver reboot or dedup expiration. CANCEL is best effort for outstanding transactions, carries a destination tombstone; it does not retract already delivered effects, nor promise remote deletion during a partition. Core delivery marks protocol reception, not application side-effect commit. State values expire locally and older seq for the same boot/key does not overwrite newer state. Hardware absence never substitutes synthetic outcomes for measured PDR/range/RTT.

## Final telemetry additions (explicit v1-compatible fields)

`node_id+boot_id` identify the **current logging node**, including intermediates. `origin_id+origin_boot_id+seq` identify the original protocol transaction, including RREQ/DATA/ACK/error reverse-path logs. Do not join using logger boot as source boot. Endpoint echoes are new reverse-direction transactions with their own origin identity. `tx_attempt` is a positive **node-local submission ordinal in this boot**, shared by the matching tx_submit and tx_result; it is not an RF retry count or end-to-end application attempt number. Non-TX events have tx_attempt=null. Within the same run_id, match callbacks with node_id+boot_id+tx_attempt. ESP adapter keeps one outstanding SDK send, stops on missing callback/queue overflow, and locks further radio starts until reboot if stopped with an unresolved callback; it does not reuse that outstanding identifier for a later send.

Statuses: generated 0=accepted by core; tx_submit 0=adapter about to call transport (host console -1=no transport); tx_result 1=link callback success, 0=link failure, negative=adapter/SDK failure or unknown timeout. `rx` and core `echo` with unique_receive=true are first endpoint deliveries; `frame_rx` is any accepted wire frame before routing/idempotency checks and is **not** unique application reception. `confirmed` means source received endpoint ACK. `duplicate` status 0=already delivered, 1=cancel tombstone, 2=older state version, 3=outside sequence window. Cancelled status 1 means effect was already delivered, not rolled back. Rejected/expired status values are local protocol diagnostics; rejected status 2=capacity, expired 1=lifetime, 2=discovery exhaustion, 3=DATA attempts exhausted. Event overflow is counted in stats; counters do not pretend to be complete event traces after overflow.

Echo payload starts with little-endian original request boot_id:uint32 and request seq:uint32; bytes after offset8 preserve bench payload. No remote timestamp is included. `echo_correlation` is an additional **non-delivery** record with request_origin_id (the current endpoint), request_boot_id, request_seq, same_source_boot and receive t_us. Join against generated at that same source/node boot to compute a source-clock RTT; if boot differs or generation is missing, RTT stays unknown. t_us is monotonic milliseconds multiplied by1000, not microsecond-resolution RF timing. Firmware rtt_ms remains null; do not subtract timestamps from different nodes. `echo` unique delivery and echo_correlation must not be counted twice. Golden examples are synthetic copies of actual host harness logs, with provenance, not hardware evidence.

## C API usage and return contract

`ann_init(node,id,boot)` clears state and leaves idle, no queued radio. `ann_start(node,now_ms)` explicitly starts and queues HELLO once; `ann_stop` clears pending/outgoing traffic (remote cancellation is not guaranteed). `ann_submit(node,destination,kind,state_key,payload,payload_bytes,lifetime_ms,echo_flag,monotonic_now_ms,seq_out)` copies payload and accepts one bounded transaction: return0=accepted, -1=invalid argument/idle/backward time/full outgoing queue, -2=pending slots full. seq_out is optional and is assigned **only** on success. kind=1/2/3, state_key meaningful for kind2, echo_flag=0/1, payload_bytes<=138, lifetime_ms=1..60000, destination nonzero/nonself/lower48bits. Failure never means successful send. Sequence exhaustion requires a new boot, not wrap.

`ann_cancel(node,seq,now_ms)` returns0 only for an outstanding local transaction, -1 if absent/backward time; it best-effort queues CANCEL if a route exists. `ann_tick` advances retry/expiry at monotonic now_ms. `ann_receive(node,previous_hop,bytes,len,now_ms)` returns0 for processed/duplicate frames, negative for malformed/not accepted/routing or capacity rejection; endpoint delivery is determined by events, not return0. `ann_next_tx(node,out,now_ms)` returns1 with copied outgoing packet or0 if empty/expired/idle; caller encodes with ann_encode, sends to out.next (0=broadcast), then reports a link outcome through ann_tx_result. `ann_next_event` returns1 with a copied event or0 if empty. ann_encode returns112..250 bytes or-1; ann_decode returns0 or-1. No function allocates unbounded storage, opens a device or owns the supplied clock. The ESP adapter serializes calls in one task; the core is not thread-safe.

`ann_console.h` is unchanged from the first checkpoint. `ann.h` ABI changed to add the sequence-window bitmaps and named submit parameters; its revision is recorded in E1-014. The wire layout remains unchanged. Invalid/unparseable nonce returns nonce=null; valid nonce is echoed even on command errors. JSON string field values are ASCII in v1 (UTF-8 transport); Unicode escapes are intentionally unsupported.

## C-017 lifecycle correction (E1-01/E1-02)

The source deadline is exclusive: at now_ms>=deadline the transaction expires, including when ann_receive is called before ann_tick. Late RREP/ACK/ERROR cannot revive or confirm it. attempt checks the deadline before unsigned subtraction; source outbox dequeue independently checks that the matching pending transaction is still live. Expiration is recorded once and purges its unsent local DATA/RREQ; source confirmation also removes redundant queued retries. This does not alter the remote clock/on-air uncertainty boundary above.

Successful ann_cancel first removes all **not yet taken** local DATA/RREQ for that exact origin/boot/seq, preserving unrelated traffic/order and best-effort CANCEL. An expired pending at cancel time is expired and returns-1, rather than creating a fresh one-millisecond cancellation budget. Once ann_next_tx has handed a frame to the caller/adapter, ann_cancel cannot retract that copy; the best-effort remote/in-flight limit still applies. Relay traffic and other transactions are not globally cancelled. No command fields, public headers, wire bytes, or golden log format changed in this correction.
