# M-064：迁移正确性与功能完备性验证

验证日期：2026-11-23，用户 20:27 追加要求。被测 baseline `162665bf93265333e725486539a26098b1466a31`；冻结来源 lh `bdadc989decf4d383b49dff2def4aa1aa0aa59b5`。本报告是同一实施会话的软件功能复核，**不是 C 独立审查、物理设备验收或生产发布许可**。

## 结论先行

1. **框架源码迁移正确，未发现本轮覆盖范围内的迁入遗漏或意外产品代码变化。** 349 个来源文件的原始哈希全部匹配来源清单；347 个文件规范化行尾后完全一致；另外 2 个仅为已登记的测试输出目录/控制台编码适配及测试 EOF 空白清理。工作源码与已提交源码相符，原工程受保护代码未改。
2. **“新版已经完整替代原工程”不成立。** 多项工程功能仍只在原入口，Vue 网络工作台尚未接入，不能把 Mock 的来源切换/临时回放当成原服务能力已迁完。
3. **可以继续以 baseline 为开发源，但不能切换旧默认工程入口或据此同步 deploy。** 尤其仅部署静态构建并直接连接当前无 CORS 的旧网关，会失败；这次已用实际 HTTP 链路复现，而非仅由代码推断。

这些差距主要是被导入框架原有的阶段边界，不是漏复制文件导致。完整性通过不等于功能完备。

## 必须优先处理的差距

### F-01 / P1：真实来源管理未迁入

原接口为 `GET /api/v1/lora/sources`、`POST /api/v1/lora/sources/select`，见 [旧处理器](../../../../tools/mobile_gateway/studio.py#L186-L228) 与 [旧视图调用](../../../../research/agent_native_network/mobile_gateway/view.js#L81-L89)。

新版 [客户端](../../../../frontend/src/network/api.ts#L70-L80) 对旧协议固定关闭来源选择。网页“服务器/本地网关地址切换”不等于原接收器选择/回退已支持。默认入口切换前需接入原合同、epoch 隔离、错误与切换中状态，并验证旧来源不会残留。

### F-02 / P1：真实持久录制/回放未迁入

新版 [客户端](../../../../frontend/src/network/api.ts#L70-L94) 的旧协议会话为空，并且不提供旧 replay 合同；[页面按钮](../../../../frontend/src/views/NetworkView.vue#L119-L123) 因能力关闭而禁用。

本轮直接对 [原 Replay 模块](../../../../tools/mobile_gateway/replay.py) 在新 DB 中验证：重复 start 保持同一 session、故障记录 unavailable、关闭并重开后记录保留、旧 TEXT 可读，以及 101 帧强制分页。**因此模块保留成立，但新 Vue 的持久回放仍未完成。**

### F-03 / P1：工程诊断并非旧界面的功能对等替代

原 [Agent/逐包/方向/时间线界面](../../../../research/agent_native_network/mobile_gateway/index.html#L16-L18) 与新 [事件合同](../../../../frontend/src/network/types.ts#L24-L41) 不对等。原始载荷、目的实收证据、字节冲突、观察完整性等不能用最近六条网络事件替代；恢复状态、原 fleet/registry 也要专门适配。不能仅做外观替换后删除旧工程能力。

### F-04 / P1（部署前）：开发成功不能等同于静态部署成功

[开发 Vite 配置](../../../../frontend/vite.config.ts#L14-L23) 注入 loopback 只读桥，但 [静态配置](../../../../frontend/public/network-config.json) 不带该桥。[原服务响应器](../../../../tools/mobile_gateway/server.py#L34-L42) 没有 CORS 响应头。

本轮相同旧响应器/相同合成拓扑：

- 开发预览→开发桥→夹具：成功显示成员。
- 静态构建→不同端口的旧响应器：浏览器实际报 CORS，显示 Failed to fetch，0 成员。

需交付受保护的同源生产只读 API/代理或严格授权的 CORS 方案，并完成静态产物端到端测试。**不能把仅为 loopback 设计的开发代理原样公开到公网。** 该结论只针对当前直连组合，不是断言所有部署方式都必然失败。

### F-05 / 配套服务边界：Network v1 与平台后端

[客户端合同](../../../../frontend/src/network/api.ts#L37-L95) 与旧 Studio 的 lora/replay API 不同。对自有旧响应器探测 capabilities 得到 404；浏览器跨源还会先遇到 CORS。baseline 的框架导入不包含 Java 或 Network v1 服务实现，不能用有 mock 后端的 450 项测试推断生产业务后端完整。

### F-06 / P2：原 check_studio 自检入口已过期（迁移前已存在）

[旧检查器](../../../../tools/mobile_gateway/check_studio.py#L27) 给 Studio 传 3 个实参，但 [当前构造函数](../../../../tools/mobile_gateway/studio.py#L41-L55) 只收 2 个。已通过 AST 静态签名核验，未启动该过期检查器去触及现场。其文件在本次迁移中未改，因此不是迁移新引入的问题，但不能再拿它充当当前全链路验收。需要更新自检入口与当前 live-only 合同。
