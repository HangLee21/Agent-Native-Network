# M-064 连线状态显示修正（2026-11-25）

用户要求修正节点间粉紫线容易被当作过期的问题。仅改baseline前端及回归，不重启现有服务，不改设备、后端协议、固件、网卡或生产部署；原M-064仍review，不冒充独立C验收。

## 修正后含义

| 显示 | 含义 | 不代表什么 |
|---|---|---|
| 蓝色实线 | 报告窗口内的近期邻居采样；旧协议有效期仍未知 | 不证明当前仍可通信，更非端到端交付 |
| 绿色实线 | 有时效约束的新鲜双向互证 | 不把旧协议bidirectional直接升级为此状态 |
| 青色虚线 | 近期LoRa上行接收 | 不当作节点间Wi-Fi质量 |
| 灰色虚线 | 已知有效期到期、较早采样或报告超时；详情分别说明 | 未知TTL不被谎称“已过期” |
| 琥珀色点线 | 有效性未知或观测中断；详情分别说明 | 不等于明确失效 |
| 红色短虚线 | 节点明确上报lost，且仍在本次可展示的报告/采样窗口内 | 不因TTL缺失而显示红色；整机报告超时亦不等于该方向lost |

拓扑、悬浮/键盘标签、图例、邻接表和方向详情使用同一状态判定与文字。选中/聚焦仅加粗和光晕，不再盖成黄色而隐藏真实状态色；邻接表也不把单向接收误涂为绿色互证。详情新增原上报关系和链路有效期，并提示“近期不等于仍然有效，未知也不等于已经过期”。

旧协议`validForMs=null`继续保留。仅以报告者自身的reportTimeoutMs作为**显示新旧的窗口**，绝不冒充板间Wi-Fi有效期；较早邻居样本与报告者自身超时亦分别说明。原生IP/Wi-Fi层已有的明确deadline在已过期快照重载时也保留，避免已知过期被丢成未知。中断优先于旧失效色；新鲜采样变旧仍随浏览器时间推进，回放继续以原帧时钟判断。legacy性质未声明、来源/epoch、收件字节和覆盖缺口政策不变。
