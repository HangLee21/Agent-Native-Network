# 30 节点通信工程模型（工作版本）

当前主线是 Wi-Fi 多跳，LoRa 由 E2 单独处理。本目录 `engineering_run.py` 接受 `--output`，输出必须是 E1-030 或 E2-033 下不存在的新目录，保留每次模型、源码、参数、固件桥、事件和 manifest；调用方只应写自己拥有的任务范围。旧 `run.py` 的 25 ms/帧模型停止作为工程入口，05 快照保持原字节。

## 模型与板端映射

每节点使用同一份已快照 C 路由、邻居核心，Python 仅模拟环境/调度。源码 `candidate/source_route.c` 在 `ENGINEERING_RREQ_DEDUP=0` 时保留原始语义；置 1 后中继每个 `(origin, boot, request)` 仅首次转发，目的节点仍接受多候选。它不增加协议报文字段或发现等待时间，但可能让先到的一条路径阻止后续更好路径，必须比较交付与尾延迟。此 C 文件同时用于 ESP32-S3 隔离目标组件构建。

`candidate/peer_cache_mac.c` 是 20 项固定容量、广播项固定保留、其他项最近使用淘汰的 C 候选。基线模拟实际现有代码：发送前加入 peer，满表拒绝，不主动淘汰；此处按发送时约束，而不是把可见邻居直接截成 20。候选不改变无线帧，满表扫描最多两次各 20 项；并发发送被单在飞约束。`--policy` 按位组合：1 为泛洪抑制、2 为 peer LRU、4 为失联邻居回收；0 为基线，7 为三者组合。同源 C 算法已在隔离候选中接入 ESP-IDF 的 add/delete API 并完成完整目标构建；生产固件未修改。仿真理想化假设 API 成功，淘汰延迟由参数指定，默认零。SDK 失败、删除/重加开销、加密 peer 和真实运行期碎片均未测。不得把它称作可刷固件或上板成功。

模拟独立设定：帧 airtime 按载荷长度、192 μs 前导、43 字节额外封装、1 Mbps 计算；单播另计 ACK 近似时间。乐鑫文档提供的 ESP-NOW 默认速率为 1 Mbps（https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/network/esp_now.html），具体帧封装、前导、退避、重试与 ACK 的数值是实验假设，不是板上抓包。竞争使用 20 μs 退避粒度，帧允许不同时刻开始，重叠时按接收节点局部可见发送源模拟隐藏终端，单播失败限 3 次重试。ACK 合并在发送者的 airtime 中，不模拟 ACK 独立干扰；模拟 PHY 仍为理想半径/距离相关概率，不代表实测 RF。

软件处理近似每 10 ms，轨迹几何每 250 ms 更新，二者不是空口帧持续时间。固件实际通过输入队列回调驱动，空闲 xQueueReceive 最长等待 10 ms；模型的固定服务周期仍是近似，负载很高时可能偏慢。中继/发现每次直接调用 C 模型，出站帧在 C 队列出队时检查 250 ms，出队并交给下层后不再把其余空口等待算回源路由队列。ND 队列 16 项、按板端 `>1000 ms` 淘汰；不模拟回调丢失及 radio heal。

## 目标组件资源与边界

目标编译报告：`.local/mid/E1-030-engineering/20261114-03-target-component/target_report.json`，ESP32-S3 Xtensa GCC 14.2，`-Os -ffunction-sections -fdata-sections -Wall -Wextra -Werror`，基线/候选为可重定位最小组件，**不是完整固件**。目标类型 `sizeof(sr_node)=27144` B，`sizeof(nd_node)=2368` B，`sizeof(sr_out)=248` B，额外 peer 缓存 `sizeof(e1_peer_cache)=288` B；不能把 host sizeof 当目标值。两份组件都编入 peer 模块时，text/literal/rodata 汇总为 11740 / 11875 B；增量 135 B 只比较 RREQ 编译开关，不能当完整 app 最终 Flash 差值。SDK peer 内存、16 项 app 队列、回调队列、栈和系统其他数据还需完整目标链接及实板水位验证；不能用 4 MB Flash 当 RAM，不能假设 PSRAM。

RREQ 单次查重至多遍历 128 seen 项（路径最长 5 节点），peer 查找/替换各最多 20 项；周期同步最多 32 项邻居，各自进入最多 32 项的 SR peer 搜索。其他路由、轮次、待发和候选受固件固定表上限约束，实际最坏执行时间待目标实测。没有网络/串口/NVS 同步调用在这两个候选 C 热路径中。

## 指标与当前缺口

逐包结果按 `(origin, boot, seq)` 和目标、payload 核实；1 s 结果使用全部 offered 分母，另列运行结束不足 1 s 的右截尾量。几何可达只在发包时按四跳判断，不保证随后的路径存在；末尾未收到既可能失败也可能右截尾。控制统计和路由事件可重复关联多个包，不能直接拼成唯一失败原因。当前尚缺每包终结原因、路径恢复时间、逐节点公平性、真实 peer API 代价、时间参数敏感性、30 节点候选大矩阵和独立 E2/C 审核；不能宣布满足 95% 或部署上机。

稀疏场景仅拉开初始节点间距，保留每个节点原有位移，不通过坐标整体缩放改变速度。`20261114-16-v2-pilot` 稀疏场景因旧版本缩放错误不可用于速度比较；`20261114-17-v2-pilot-corrected` 是修正后初步检查（仍为编号版 peer、非最终 MAC 版本）。

隔离完整候选：`.local/mid/E1-030-engineering/20261114-05-full-target/`，目标镜像 954,576 B，factory 分区 4,128,768 B，剩余 76.88%；`.dram0.data` 19,304 B、`.dram0.bss` 105,304 B 为 ELF 静态节，不等于可用堆。实际最低可用堆、栈余量、碎片、API 时延和实机 RF 均未测。SDK 删除/添加失败路径使用假 SDK 主机测试，尚非板上验证。构建标识计算未纳入新 peer 文件，使用 `candidate_source_manifest.json` 和二进制 SHA-256 跟踪，不依赖 build_id 识别候选。

邻居同步周期模式是正式基线；事件触发优化在 12 组中有 3 组交付数不同，作为敏感性保留，不能当作等价加速。主机桥减少空转检查后 12 组事件和统计与旧周期版本完全一致。

同版本 SDK 和同一配置完整目标基线已构建于 `.local/mid/E1-030-engineering/20261114-06-full-baseline/`。基线镜像 953,520 B，候选 954,576 B，增加 1,056 B；`.dram0.data + .dram0.bss` 静态段从 124,312 B 到 124,608 B，增加 296 B。差值可复核 `target_comparison.json`；这不是运行期堆消耗。

长期成员更替候选：`neighbors_engineering.c` 在 32 项全满时仅回收状态已 lost 的最老条目，仍在线或 heard 的条目绝不为了新节点驱逐；`neighbor_sync.c` 先令对应 SR peer 和第一跳路由失效，再释放其 SR 表槽。两层固定容量不变，最坏需对 32 个 SR peer 各扫描 32 个 ND peer；其实际处理时间待板端测量。回收条目会丢失该条目的有限退休 boot 历史，可能影响陈旧重放处理，尚需安全设计和回归；不能将简单 HELLO 视为认证。`20261114-40-full-reclaim-fixtures` 对满表不驱逐存活节点、40 个轮替身份及 SR 槽复用、1/2/4 跳交付、5 跳边界作 host 检查；`20261114-41-full-reclaim-smoke` 检查周期和缓存同步时替换邻居后旧 SR 状态被清除。候选当前仍未经历真实成员重启/断电 RF 测试。

主机桥 cached 同步只是仿真执行优化：12 组常规场景及 16 组短/长包和 0.2–5 包/s 受控对照，原始事件和汇总与逐周期同步一致；另有 40 成员替换后同步检查。这些有限夹具不能证明所有输入严格等价，长时间成员更替仍需额外验证。

最终隔离目标候选为 `.local/mid/E1-030-engineering/20261114-08-final-target/`，镜像 954,768 B，相同 SDK 基线增加 1,248 B；静态 DRAM data+bss 增 296 B，应用分区余 76.88%。`e1_ensure_peer` 目标入口栈帧 368 B、`e1_clear_absent_neighbors` 48 B，不含下游调用；总栈峰值、堆和 SDK 动态分配未测。源路由、MAC peer、邻居、路由同步四个 C 文件的 hash 分别与冻结源码一致；以前的 05/07 构建只保留作中间证据。

每条 offered 在结束时有一条 `deadline_outcome`，分别记录 0.5、1、2 s 内收到、提交拒绝、无端点收件或右截尾；`observed_sr_tags` 只是相同身份和目的的观察性事件，不是已证实的唯一丢包原因。独立分析优先使用成熟期限分母，并同时报告全部 offered。

`engineering_campaign.py` 可在指定 UTC 截止前按 20 分钟内有限批次运行，最多两个子 worker；每批完成做独立事件核对，时间上限到达停止并留待续目录。长批运行期间仅临时申请系统保持唤醒，退出释放；不改电源计划。

规模批次优化：每个批次对每种策略先单独编译与跑语义检查，后续案例仅在策略、完整源码 hash 和二进制 SHA-256 全匹配时复制复用，且 manifest 指向准备运行；不同案例仍独立输出事件和结果。`20261114-55-reuse-smoke` 与逐案例编译对照汇总一致、去掉修正过的观察性标签后逐事件一致；`20261114-57-tamper-rejection` 人为篡改副本的二进制后被预期拒绝。复用不会把缓存测试结果当作案例产出，也不改变协议或模型。

当前版补充逐节点 SR overflow、RREQ 限流拒绝、SR 输入拒绝、事件队列 overflow、ND 满表以及 pending/out 出站队列峰值。只要固件事件队列发生 overflow，端点统计标记不完整且独立核对拒绝通过；这些累计计数仍不能一一对应到业务包。满 peer 拒绝数据帧时记录匹配业务身份的观察性事件，最终是否送达仍由目的端证据判定。
