# 实验性 RREQ 反向路径缓存

状态：隔离试验，尚非正式协议或生产固件。对照是已有 policy 7（RREQ重复路径抑制、peer LRU、lost 邻居/SR表回收）；policy 15 在此基础上加反向缓存。

节点实际收到普通节点目的的有效 RREQ 后，可把该帧中已经经过的路径倒序，构造成通往 RREQ 发起者的本机缓存路线；只使用该帧和本地已确认双向首跳，不查全网图或未来轨迹。不新增无线报文、等待时间或动态分配；原有最多32项路由表已满时不覆盖有效项，已有可用路线只有在新路径按原排序更优时替换。路由缓存期限 3 秒，首跳失效或 boot 改变沿用既有失效逻辑；若首跳之后变坏，依赖原有错误反馈，不能保证无损。

候选借用原有 `SR_SELECTED` 事件的 reason=9 表示被动路径安装；这改变了该事件在观测层的取值语义，只有明确版本化和消费者检查后才可进入生产。每次安装消耗本机的一个 request 序号并写本地事件队列；不新增空口控制帧，但会占用 CPU、日志和既有路由表槽，且可能导致事件队列压力。普通源路由路由目的不绑定最终目的的 boot，RREQ 路径来自收到的帧、没有额外认证；陈旧、中途重启、恶意伪造及回放风险必须另测/解决。3 秒只是初始模型参数，不是实测最优 TTL。

`20261114-66-reverse-boundaries` 验证反向业务、3 秒到期、满表不覆盖和首跳失效；`70-reverse-chain-fixture` 验证 1/2/4跳和5跳边界。`67-reverse-base` 与源62对应案例前60秒的6481个事件一致，属于单配置回归；`71-reverse-sync` 在3运动×2密度的6组中缓存和周期同步的原始事件一致。它们均是主机检查。

`69-reverse-trial` 为 3运动×2初始密度×3种子×2策略、每次60 s、25 m/s、1包/s/节点、32 B：18对业务输入严格相同，端点与0.5/1/2 s结果核对通过。候选1 s按期率差平均约+1.66个百分点，范围-0.28至+7.74个百分点：14对提高、3对下降、1对不变。18对的控制 airtime 差均为负，但这是各节点发送时长相加，不是实测单信道占用；候选的 peer 淘汰总数从7199增到8161。两策略固件事件队列 overflow 都为0；模型未校准、只有3个种子，不能宣称普适收益、也不能用来上机。

目标二进制仅隔离构建、不刷板；实际静态增量、运行时堆/栈、SDK add/delete成本和飞行信道仍需独立核对。当前主规模矩阵使用源62的原候选，并未混入此试验。

隔离完整目标 `20261114-09-reverse-target` 已构建：镜像 955,232 B，比 policy7 候选增加 464 B，比原基线增加 1,712 B；与 policy7 的静态 DRAM data+bss 相同，应用分区余 3,173,536 B。目标反汇编中 sr_receive 入口帧 592 B，调用的 reverse_cache 入口帧 384 B；这些是静态函数帧，既不含更深层调用，也不表示实板剩余栈。详情见目标 `target_comparison.json` 与 `candidate_function_disassembly.json`。未刷板；实际堆、栈水位和无线仍未测。

`73-reverse-600` 36/36完成，18对相同输入（3运动×2初始密度×3种子、25 m/s、600 s），E1四类脚本核对通过，全部 core event overflow 为0。按18个场景等权：policy7/15 的1秒成熟分母交付均值24.7%/26.0%，均值差+1.31百分点（范围-0.12至+5.85个百分点），15对提高、3对下降；控制 airtime 为各发送节点时长之和，候选全部18对降低，平均差-44.53秒/600秒。几何四跳提交时条件下场景等权1秒率40.7%/42.3%，不是实际 RF；各场景最差接收节点率等权均值19.1%/20.8%，不代表每个节点有保障。平均 peer 淘汰数约4115/4584，且SDK换表延迟默认0；目标运算/堆、API代价、事件语义和安全风险仍待解决。三个种子不能支持普适显著性，也尚未达到内部1秒95%筛选目标。
