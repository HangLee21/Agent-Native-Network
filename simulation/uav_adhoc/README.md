# E1-030 Wi-Fi 高速移动仿真

运行 `python -B simulation/uav_adhoc/run.py --run-id <新目录名> --suite diagnostic` 做 15 秒配对诊断，或使用 `--suite matrix` 运行 3 运动 × 3 速度 × 3 种子 × 2 策略，每次 300 秒。只创建新输出目录；入口先快照源码、编译实际固件核心、执行两节点端点收发语义检查，再保存配置、逐案例 JSONL、summary 和 RUN_MANIFEST。单进程、单批上限 1200 秒。LoRa 属于 E2 独立任务。

模型是合成二维轨迹和理想 150 m 距离阈值，不是无线或实飞测量。25 ms 时隙、250 ms 位置采样、距离相关合成接收概率、每节点 2–3 秒一条业务。节点只根据实际收到的邻居和路由信息决策；真实几何图仅供传播、载波侦听及提交时几何可达性评价。策略对比为固件默认路由缓存和节点本地缓存有效期上限 2 秒；后者会引起额外发现，不能假定收益。两策略采用相同运动和业务种子，退避与接收使用索引式随机数。

事件每行包括 time_ms、event、origin_id、origin_boot_id、dst_id、seq、reason；目的端 delivery 必须匹配来源、boot、序号、目标和原始 payload。offered_geometric_4hop 是提交瞬间理想几何四跳可达，不保证之后可达，也不是 RF 上界。summary 同时列 admitted、端点收到、提交时几何可达、成功时延、控制/业务 airtime、碰撞和队列累计数；完成链路寿命与结束时右截尾链路分开。低交付不能仅归因某一机制，队列溢出/过期等是整体计数，不是每个未交付包的唯一原因。

信道采用同槽随机排序、邻居互斥、隐藏发送者碰撞、前一槽载波感知和单播最多三次重试（重试退避 1–8 槽），每帧统一占用一槽；并非精确 ESP-NOW PHY/MAC。ACK 队列容量 16、过期 250 ms；peer 上限以扫描时截断模拟。源路由出队后如果等待竞争，实际适配器没有继续执行出站队列的 250 ms 过期检查；此差异可能影响结果。无 RF 校准、无实物测试、不预测实际性能。
