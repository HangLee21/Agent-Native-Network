# Experimental monotonic origin epoch guard (v3)

Prototype, not production or security. Wire version is 3, so it refuses v2 peers. On RREQ, remember one 32-bit epoch per origin. A newer epoch (serial arithmetic) clears that origin reverse route before its reset sequence is learned; an older/ambiguous epoch is dropped. RREP carrying an older origin epoch is ignored at intermediate nodes. `ma_set_boot` sets an externally supplied nonzero epoch before traffic. Assumptions: each origin persists a monotonically advancing epoch through reset, never reuses an ID with stale epoch, and peers agree; no authentication, secure storage, or identity provisioning exists. This only guards source-origin reverse-route epoch; destination restart and stale business execution remain unsolved because destination epoch is not carried in this frame. Old origin DATA/RERR are not authenticated and can still be injected/replayed. Memory is bounded by 40 origins, and the epoch table itself has no aging or secure trust. Long-offline replacement, storage rollback, wrap, and identity recycling need separate design. No RF or hardware validation.
