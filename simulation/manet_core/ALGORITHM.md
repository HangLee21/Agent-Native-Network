# AODV 类实验实现与限制

依据：[RFC 3561](https://www.rfc-editor.org/rfc/rfc3561)，Experimental；本实现不是 IPv4/IPv6 AODV 线协议，属于自定义帧适配子集。

已实现：目的序号与有限表；目标序号按 32 位序号空间比较（差值恰为半圈时不认定新旧）；以 origin/boot/RREQ-id 有界去重；由收到的 RREQ 建反向逐跳路由，目的端产生 RREP，反向逐跳送达建立正向路由；可选仅在有新鲜有效路由时中间节点回复；扩环请求 TTL 2/4/8/16、每次至多四轮，源节点每秒最多产生10条 RREQ；数据逐跳 TTL 32；链路最终发送失败后按失效下一跳的路由生成受限 RERR 广播并传播；过期失效，待发现业务有限保存；发送与事件队列、见过的请求、路由和 peer 均有上限。地址、boot、序号、版本和长度在 32 B 自定义头内显式编码，帧总大小最多 192 B（载荷上限 160 B，头 32 B）。协议决策只用本地状态、收帧和发送回调。

未实现或主要偏离：标准 IP/UDP 格式和 IP 生命周期；HELLO/邻居双向性验证；precursor 定向 RERR，当前 RERR 为受限广播；局部修复；RREP-ACK 和单向链路识别；intermediate RREP 的 gratuitous RREP；路由状态持久化、完整 reboot 安全隔离与重放防护；端到端 ACK、业务重传和应用去重；RERR 分组聚合；可配置的 ring 8/16/32 对照；标准推荐时间参数和无线实测标定。路由 boot 复位语义不完整，路由表按 node ID 而非 `(node,boot)` 索引；未达到无人机实际部署条件。端点事件代表真实目的进程收到模拟帧，不等于发送端得到确认。广播物理层 ACK 是发送完成的模型假设，不证明接收。

实验变体独立：policy 0 仅目的节点答复，policy 1 允许中间节点按已知新鲜路由答复，policy 2 为目的节点答复加每秒最多转发 8 条 RREQ，policy 3 为中间答复加同样的转发上限；修正后以 policy 1 和 3 比较节流。源节点发起 RREQ 的另一个每秒10条限制各策略一致。policy 2 超额直接丢弃，而非排队，且见过标识先占去重缓存；固定窗口可能偏向先到达流，不保证公平，应测试公平性和时限敏感性。此策略不是完整的任何现有论文算法，也不声称创新或全局最优。

队列：待发32帧、待发现业务16条（各载荷最多160 B，3秒过期）、事件64条、RREQ seen128条（5秒）、路由40条、peer20条含广播。过载时拒绝而非无界增长。队列/RREQ seen 溢出计数不是独立业务包损失原因。模拟器上报的碰撞、确认、传播、peer API开销和10ms软件服务是未用实际设备标定的假设。目标是定量对比，不允许推断真实RF交付率。

接口见 CONTRACT.md；单场景多种子对照及逐包核对在 outputs/E1-031。目标对象的静态空间、整个固件链接和真正的板上实时堆栈/RF是不同证据层级。


早期快照存在旧 RREP 继续转发与目的节点无条件递增序号问题；当前源码改为仅在路由有更新时转发 RREP，并按 §6.1 将本节点序号更新到与请求中的已知目的序号较新者，不再无条件加一。RFC §6.6.1 对递增情形有更窄描述，二者超出相邻序号的解释仍需独立审查。当前同时丢弃序号更旧的 RERR，并在转发 RREQ 时携带本地较新目的序号。两种源码的结果不能混合；虽然关键偏差已修正，仍有前述未实现项，不能称完整 AODV 或部署就绪。
