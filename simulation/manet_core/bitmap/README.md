# Experimental bounded RREQ bitmap

Policy 5 is the adaptive baseline; policy 13 adds per-(origin,boot) 64-bit serial-number windows in the same bounded 128-entry seen array. Only locally received RREQs are used. Within an unexpired entry, newer serials shift a bitmap, out-of-order IDs up to 63 behind are retained, repeated IDs drop; older IDs outside the window and the half-range ambiguous case are conservatively dropped. Each accepted new request extends entry lifetime by 5 seconds; one busy boot may consequently retain old bits longer than per-request TTL. This differs from RFC duplicate-cache semantics and can drop a legitimately delayed request outside the window; origin 10/s rate cap limits but does not eliminate this risk. Up to 128 concurrent origin+boot identities; when full, new identities are rejected. No authentication/reboot-replay guarantee; old boot is not automatically trusted or retired. This is an exploratory engineering adaptation, not a claim of novelty, RF validation or complete AODV.
