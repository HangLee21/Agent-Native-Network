# E2-034 主动路由消息驱动子集

`proactive_subset.py --seconds 600 --seeds 5 --output NEW_DIRECTORY` 是独立概念验证：HELLO交换一跳观测和听到的邻居，节点本地选MPR；TC根据已收到的选择关系在接收图上传播，节点本地用收到的拓扑运行Dijkstra；业务按各节点本地表逐跳转发，真几何图只供环境判断某次帧是否到达。实际运行15项（3个权值开关×5种子），30节点、单一 crossing/25m/s、600s、150m理想半径与每节点1包/s。交通与链路成功概率使用按seed/时间/帧/发送接收端键控的随机值；各策略相同seed有相同条件事件的抽样。没有实际射频/硬件操作。

此原型 **不是完整 OLSR、ETX 扩展或作者 P-OLSR 复现，也尚未实现 E1 的C ABI**。RFC 3626 定义的信息库、各状态过期、完整链路感知、两跳对称性、MPR唯一覆盖/意愿度、TC序列/重启、分片、完整版本化字节帧等未覆盖；两跳使用收到的邻居列表近似，并将TC链路近似为双向。seen去重未处理boot重启；没有加入/退出、持续流量排队或可靠性验证。所选简化子集需进一步改造与C审查。

`hop` 权值为1；`etx_subset` 用HELLO估计正反向可收概率的简化指数平均，权值为1/max(0.05,q_forward*q_reverse)，含人为上界20，不等于作者链路质量代码；`predictive_subset` 在同一ETX近似上乘exp(0.05*径向相对速度)，指数输入裁到[-2,2]。位置由HELLO发送并经合成95%接收，估计采用本地位置及收到的位置；当前无GPS误差/排队/报文传输延迟。论文来源：[RFC 3626](https://datatracker.ietf.org/doc/html/rfc3626) 与 [Rosati等原文](https://arxiv.org/html/1406.4399)。论文公式的特定参数、原始实现、预测时间对齐和速率质量算法未逐项复现，因此只称 predictive_subset，不称 P-OLSR 成功复现。

控制帧长度为显式估计：HELLO含邻居、MPR、双向质量条目及可选GPS，TC含发布边；估计超过250B的帧明确拒绝、不传播、不计发送airtime。长度并未通过真实序列化检验，也没有针对MTU的分片。单播peer 19项LRU加1项广播，未模拟SDK增删耗时/失败；邻居信息库与路由内存无目标C字节预算。无竞争/隐藏终端/退避、ACK/重试、串行radio队列或传输排期；每跳近似同一秒内完成。`control_airtime_us` 仅按假设1Mbit/s及192us每帧计算的占用账目，不能用来声称业务时延或公平共用信道。数据包估计48B、最多16跳，循环会终止；失败分为本地无路、下一跳不可用或合成链路丢失、环路/超跳限的粗类别。无独立端点ACK；消息字段与固件不兼容。

`20261114-08-proactive-mtu-peer` 保存15份原事件、汇总与source hash；`20261114-10-proactive-audit` 核控制字节/airtime、MTU拒绝计数和业务收件/失败分母；`20261114-09-proactive-fixtures` 核本地HELLO/MPR、TC去重/过期、速度加权与计数守恒。五种子配对差异只能解释这个单一合成环境，不能与E1旧数据比较，也不能据此选择协议。旧03/04/05为演进记录，05尚未实行估计MTU拒绝和peer LRU，不作为最终源版本。

下一步：与E1冻结统一输入/帧ABI对接，独立实现完整OLSR邻居/双向/2-hop/MPR/TC及协议版本，复核作者代码与探测定义，再在同一无线调度/时间/容量约束下与AODV等进行多个运动、密度、速度和至少5配对seed的对照。需要真实序列化、受限队列与邻居容量、端到端身份/期限/右截尾、丢失/过期/启动/重启/环路场景，及目标C内存和编译证据；当前均未完成。
