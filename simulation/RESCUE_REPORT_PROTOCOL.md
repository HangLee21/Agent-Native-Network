# 救灾发现回报先导：运行前方案

2026-10-21。依据[救灾任务筛查](../research/agent_native_network/RESCUE_TASK_SCREENING.md)，只检查自主搜索结果的运行中回报，不模拟火势、救治、LLM或核查派遣。不是SubT/ACHORD复现，不用合成正结果证明现实瓶颈。

## 固定场景与信息边界

两个自主地面搜索节点，各搜索一条12房间走廊；两走廊仅经入口相连。每条走廊每种子均匀无放回放置4个隐藏目标。按房间序号访问是合理预分工，不故意安排重复搜索；策略只能扫描已到达房间。检测/定位先设完美、无运动故障，以隔离通信因素。

每段走廊移动20模拟秒，检查房间10秒；所有方案预留回到入口的时间。预算600/900秒。位置连续沿走廊移动，以1秒步长更新通信。未知目标分布不参与预规划，种子0–23在所有策略中配对。几何为合成树形图，单位和时间均未校准。

通信可达深度3/6/99（99为全连通控制），每条链路同一范围。每个机器人可额外放置一个中继，放在第一次到达的覆盖边界，部署10秒；合计最多2个额外设备。返回策略在存在未交付报告且距上次连接达到120秒时，于下一个房间决策点返回入口同步，再继续；这是预设既有策略近似，不是最优参数。

抽象可靠、可断点续传的字节服务，全队共享4000/64000字节每秒的链路发送预算，多跳每个应用字节按跳数收费。只含入口与本支路中继，没有真实PHY/MAC、随机丢包、ACK和协议头，也不模拟机器人移动中继或机会携带。近似端到端服务，不声称逐跳队列。该模型适合区分断连与积压，不用于无线性能结论。

## 报告与对照

目标报告使用真实JSON编码长度（ID、节点、房间、发现时间和类别）；附加证据0/64KiB/512KiB，仅是负载敏感性，不代表实际摄像头压缩率。先发送每条报告的摘要，再发送其附件，所有策略发现同样目标时产生同样数据。摘要到达即记为正确回报；证据完整到达另行统计，不强制需要图片才能计分。传输按至多1024字节片段轮流服务可达节点，priority可在片段间优先新摘要。

六策略：ideal（发现后立即交付上界）；fifo（缓存与顺序可靠续传）；priority（摘要优先）；return（priority+定期返回）；relay（priority+每节点一个中继）；relay_return（同时使用两种现有措施）。后两者额外设备和部署开销单列，不能当作等资源算法胜利。回传缓存排空后返回节点才继续搜索；完整证据可在继续行动中传，不能故意强制等待证据。

3覆盖×2速率×3附件×2预算×24种子×6策略=5184次执行。按覆盖/速率/附件/预算分层报告，不只展示受压条件。

## 指标与判定

报告发现数、截止已接收数、接收数随时间的归一化面积（AUC）、附件完成数、行程、返回次数、中继数、应用字节和按跳收费字节。AUC以8个真实目标和总预算归一化，未发现目标不获益，返回造成的少搜索计入损失。

对全部已发现目标报告截止截断延迟：未收到者也计入，不能只平均成功交付。用发现后第一次有路径的时刻拆出接触等待与后续服务等待；后者仍可能包含再次断连，不能称为纯队列延迟。单独导出未交付数量，禁止把截断延迟冒称最终交付延迟。

检查同路线的fifo/priority改善，区分队列管理可消除损失与仍需连通性措施的损失；再检查return/relay_return的探索—回报代价。全连通+无附件必须接近ideal。所有节点预算内返回，事件无先交付后发现。若紧凑消息与已有方法足够，不设新协议；如果残差主要是无路径，后续优先校准连通性/移动任务，不跳到LLM消息调度。
