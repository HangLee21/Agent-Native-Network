### C-048-02（P3）：HTTP 错误响应会被归入“未响应”

`sources.py:16-17` 以 `isinstance(exc, OSError)` 判断不可达，而真实 `studio.py:get_json` 使用 `urllib.request`：Python 的 `urllib.error.HTTPError` 也是 `OSError`。因此如果本机接收器实际返回 HTTP 503 等非成功响应，将被标为 `local_receiver_unreachable=true`，前端显示“本机接收服务未响应”；但该 HTTP 端点已经响应，只是未提供成功拓扑。已以本机 Python 类型关系只读核实 `issubclass(urllib.error.HTTPError, OSError) == True`；未启动 HTTP 503 场景。建议区分 HTTP 错误状态与连接拒绝/超时，前者显示“服务返回错误”或“状态未知”，并补充 503、连接拒绝及成功恢复的隔离检查。该口径缺陷不否定 C-048-01 原连接拒绝修复或 ACK/线程恢复证据，但不应把该边界标成已通过。

## C-048-01（P2）：冷启动本机 HTTP 接收器不可用时界面误导为等待网关

`tools/mobile_gateway/sources.py:19-22,111-122`：冷启动从未选中来源且本机 legacy HTTP 一直不可连接时，`AsyncSnapshot` 无缓存，返回 connecting 且无 worker；`Sources.topology()` 返回 `source=unavailable`、`receiver.state=unavailable`、`gateway_observed=false`、`control.reason=没有可用来源`，未提供 worker。`view.js:51-56,67-68` 的未知状态判断只覆盖读取异常、前端数据过期或特定原因“接收来源未响应”，并且只有存在 worker 时才显示“当前状态未知”；因此该成功返回的通用空快照会隐藏线程提示，标题显示“等待网关连接”，而不是指出接收器状态未知/来源不可用。复现：隔离 Studio `legacy_local` 指向未启动的本机 topology HTTP，启动页面且无其他来源、从未收到网关；与本机接收器正常 running 但尚未收到心跳相比较，界面无法正确区分。建议在来源不可用/无缓存且无法确认 worker 时明确显示“接收来源不可用或状态未知”，不要推断线程或网关状态；保留“worker running 但无心跳”的不同提示。补充冷启动 HTTP 失败/无缓存→恢复以及 running 无心跳的 Studio+浏览器联调。此为代码路径分析，未实际启动上述复现，不能称现场实测。
