## C-043-01（P2）：接收器缓存期间稀疏块年龄停滞

`tools/mobile_gateway/sources.py:19-28` 在 HTTP/legacy 异步来源缓存上只累加 `pc_receive_age_ms`，没有同步增加 `status_age_ms` / `gps_age_ms`。复现：缓存的报告年龄和状态块年龄均为 100 ms，停止取得新快照，模拟 5 秒后调用 `AsyncSnapshot.topology()`；得到报告年龄 5100 ms 而状态年龄仍为 100 ms。来源中断时缓存报告可能继续录制，造成旧状态/位置看起来比实际新。建议按缓存经过时间更新块年龄，或根据块接收时间与明确的当前观察时刻重算；补充缓存延迟、来源中断及恢复的回放断言。

## C-043-02（P2）：乱序旧报告覆盖较新快照及块

`tools/mid_baseline/gateway_probe/topology_server.py:98-128,218-230` 验证帧后不核对同一 observer/boot 的报告序号或采样时钟，直接刷新接收时间和覆盖记录。内存复现：同一 observer、boot 依次注入合法 `report_seq=2`、`report_seq=1`，最终快照为 1。重复或延迟帧可使拓扑倒退、刷新旧报告的新鲜度，带块的旧帧还能替换较新稀疏块；不同 boot 的迟到帧同样需要定义处理规则。建议按协议确定序号回绕、重启与迟到帧策略，确保旧帧不覆盖当前观察，并在同 boot 乱序、重复和换 boot 迟到场景验证。

## C-043-03（P2）：直接 UDP 来源未继承稀疏块

`tools/mobile_gateway/sources.py:59-69` 的直接 UDP 来源使用 `tools/flight_link/gateway.py:85-102,116-123`，每次以新 `decode_frame` 完整替换旧报告；未带 status/GPS 的后续同 boot 帧会使先前块变为 null，且不提供块接收时间和年龄。复现条件：使用非 `legacy_local` 的直接 UDP 观测，先输入含状态或 GPS 的合法报告，后输入同节点同 boot、递增序号且不含该块的报告，观察第二个快照。现有 E2 稀疏测试及 M 历史载荷验收走 `topology_server` 的 HTTP 来源，不能证明直接 UDP。建议对支持的 UDP 来源实现一致的同 boot 稀疏保留、时间与换 boot 清空，或者明确限制该来源不提供此能力并避免误称统一支持，再用隔离合成帧验证。
