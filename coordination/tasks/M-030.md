# M-030 移动节点、校园地图和笔记本观测网关

2026-11-09。主交付为持续反映现场 AD-HOC 网络的前端。沿用 M-029 板上源路由，每车一台树莓派、一块 ESP32，Pi 的普通 Wi-Fi 与 PC 的观测服务交换 IP 遥测，板间业务独立走 ESP-NOW。网关关闭时各车仍自行监听、发现、发包。没有 Pi 时，以现有电脑连接实板及各本地服务接入同一接口；GPS、无线观测和业务传输分别标明来源。

本机只读检查：Realtek 8852BE Wireless LAN WiFi 6 PCI-E NIC，2.4/5 GHz；Windows WinRT GetTetheringCapabilityFromConnectionProfile 对活动配置返回 Enabled，TetheringOperationalState 为 Off。未开启热点，也未验证 Pi 接入距离或直接通过 Windows 网卡读写 ESP-NOW。可复用双方互通的普通局域网；热点只供遥测。

## 第一版跨窗口接口与交付

- 节点向网关 POST /api/v1/reports，地图 GET /api/v1/state；静态首页 /。默认网关端口 8790 可覆盖。H/D 如需增量事件接口自行在卡登记。E2/H 对齐 JSON v1：schema_version=1、node_id（规范 MAC）、boot_id（板启动标识）、session_id（报告进程实例）、seq（实例内递增）、label、position（null 或 lat/lon/source/age_ms，可附精度）、neighbors（每项 peer_id/state/rssi_dbm/sample_age_ms，射频来源 rf_source 区分 measured/simulated/unavailable）、events（发送/中继/接收独立，原始包身份 origin/boot/seq/dst）。均以报告节点为观测者；peer→reporter 才是该接收 RSSI 的方向。到达时间由网关记录，处理重启、乱序、重复和重连旧缓存，不用多机单调时钟直接相减。报告失联与无线邻居失效分别显示。
- 板持续监听，沿用 HELLO 2–3 秒的基线；10 秒是第一版遥测全量快照的可调初值。加入、确认、失效、显著位移/质量变化可提前限速通知。GPS 来自节点程序；协议支持本地注入带年龄的定位、板间低频位置通告、网关状态摘要。GPS 仅用于定位展示，实测边由无线确认产生。避免在每个业务包塞整张邻居表。真实定位丢失时标未知/过期；模拟位置、模型质量和实测 RSSI 分开。裸板只提供收到的无线观测与其已有的定位信息。
- GPS 函数可替换（WGS84、精度、有效性、采样时间）。可选假定位提供器默认约 600×400 米虚构校园，独立起点、连续轨迹，中心、尺寸、速度和种子可配。模拟坐标可以配真实无线板，定位本身不给出任何射频边。
- 每车可单独启动 fake_agent_function，默认持续循环到主动停止。CLI 与 Python 使用同一入口。每轮从配置的最短与最长间隔之间重新随机等待，选择其他目的并生成随机可读英文、随机字节长度（不超过160），经本地板端 API 发出。无候选、暂时无路或发送失败要记录并继续下一轮；持续接收独立于发送。保留时刻、目的、原包身份与收件字节，用多轮日志验收。可显式限时运行测试。
- 首页打开即观测真实网关，初始无报告为空；按实际节点标识、每个接收端的无线观测、消息及时间构图。运行中节点数量、名称、加入次序和离开时间均由现场决定；可手动停，页面离开释放观察。失联标注最后观测时刻。软件场景仅作隔离测试输入，不能自动填入现场图。
- 以真实上报链路、正常浏览器和实板业务多轮收发为交付证据。关掉网关期间，在目的板核对新业务收件，再恢复遥测；分别记录同机实板、多 Pi、真/假GPS等条件。启动和停止命令以实际测试为准。H 独占实板，M 按阶段交接验收。
