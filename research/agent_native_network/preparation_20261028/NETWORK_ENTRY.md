# E2-011：ns-3.46 动态两跳网络入口

2026-10-28，E2实际独立窗口 `01a16824-3f4e-7e61-8a83-08d2dd8c82f6`。本卡只实现和核验有限B0：成熟无线/AODV栈的两跳连通—中继移动分区—恢复。没有运行模型推理、训练、正式B1/B2/C矩阵，也没有将009旧结果改称动态网络证据。

## 实现与场景合同

代码、冻结配置、启动器和日志核验器位于[dynamic_network_entry](../../../simulation/dynamic_network_entry/README.md)。C++入口使用原生ns-3.46 `AdhocWifiMac`、802.11a DCF、6Mbps数据/控制模式、20MHz/信道36、16dBm，以及AODV路由；不注入静态/全局真值路由，不在脚本里直接安排交付。Python只控制执行预算和事后分析，不模拟无线。

3个节点：源0=(0,0)，目的2=(200,0)，中继1初始=(100,0)。ns-3 Friis损耗叠加125米硬截止；19–21秒中继连续移动到(100,400)，39–41秒返回。端点不能直达，两段初始各100米；安全分区检查窗[22,38]无物理可用路径。硬截止是明确的工程连通性约束，不是测得的无线覆盖或现实衰落。链路变化来自中继位置，应用一直发送，不能将其解释成“停止应用模拟设备退出”。

探测由源0在5.0–59.5秒每0.5秒生成，共110个512字节UDP正文；12字节SeqTs头包含在512字节内。它是合成工程探测，不是LLM流量、真实传感数据或应用任务结果。UDP没有额外应用重传；MAC重试和AODV控制由原栈执行。AODV排队最长3秒。这个B0不实现Agent请求修订、消费、DTN、租约、可靠RPC或OFDMA。

另有同栈单跳smoke：目的端改在100米，中继50米且静止。仅用于区分入口连通与两跳机制，不改变正式动态场景参数。

## 如何核对

逐运行`manifest.json`沿用[公共模板](../../../coordination/templates/RUN_MANIFEST.json)，保留Git/dirty范围hash、命令、解释器、来源、配置、预算、退出和输出hash。来源原包和原始运行输出保留；历史manifest不改。所有新输出在`simulation/outputs/E2-011/<run-id>/`，C可独立读取，不需再次运行策略或模拟。

真实模拟的`raw/events.jsonl`与pcap包含：

- 源应用签发、socket接受/拒绝、目的端接收及生成时刻；完整110个序号，不从分母删掉分区期间消息。
- IPv4 `UnicastForward`与`LocalDeliver`的节点/TTL。成功两跳需TTL与实际中继转发共同支持，离线几何只用于否定分区穿透，不向协议喂路由。
- 每次PHY发射和对应TX状态区间。802.11a无聚合/MU，按节点/开始时刻配对；AODV、应用、ARP、MAC控制、其他/未知分类互斥。每次重试付费，ACK单列为MAC控制。发射时间裁到60秒观察边界；完整MPDU尝试字节与实际已发时间口径分开。
- 中继位置和只读检查标记；分区窗不得收到，恢复检查点42秒后至少三份新生成消息实际收到。标记不重启AODV或清空路由表。

检查器收支式为：签发=socket拒绝+唯一收到+接受但窗末未收到。未收到保持原序号/截止，区分迟到与窗末未终结；这不是所有内部MAC/IP队列及丢失原因的完整守恒重建。PHY发送尝试不是下一跳交付；端到端路径结论还需目的端和IP事件证据。缺少原始事件、空结果或缺恢复一律不能仅因部分计数相等而通过。

Python合成fixture仅用于核验器单测。其分区“穿透”等负例不计为无线模拟或网络现象，不能把12项单测通过当成成熟栈已跑通。
