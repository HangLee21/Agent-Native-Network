## 后续技术备选的使用边界

以下第 1 节起是早期保留的工程与机制参考，**不是已选实施路线，也不在本轮执行**。其中模型、平台、MAC 控制和原型顺序均须在任务问题确认后重新筛选；不以这些方案倒推任务需求。

## 1. 最小原型

先在一台现有计算机上用 3–5 个独立进程建立独立上下文，运行容量适配的开源 Qwen 小模型或同类模型。每节点持有独立请求、版本、状态和通信套接字；共享模型权重服务需显式记录，不能称为独立硬件推理。先用文本形式的局部传感观察，随后接入图片或真实传感数据。模型权重、量化、上下文长度与设备内存适配在后续运行前检查，本轮不指定未经验证的吞吐能力。

原先建议的“多区域发现—确认—撤销”暂只作为协议功能测试案例，不能证明真实业务中频繁撤销或严重失效。用于论文测量的任务必须来自实际应用，并保留自然消息分布和真值约束；只有自然观察到该行为后才比较固定 DAG、周期遥测等对照。

网络原型用 Linux namespace、veth、路由和 tc/netem；当前工作区是 Windows，下一阶段应优先选择已有 Linux 主机/虚拟机，容器自身不等价于完整无线仿真。所有数据包经过网络路径；不允许在 Python 全局对象中旁路交换正文或版本。

## 2. 平台选择与时间同步

| 方案 | 接口与能力 | 同步与可重复性 | 复杂度 / 用途 |
|---|---|---|---|
| 独立进程 + Linux namespace + netem | 真 UDP/TCP、限速、延迟、丢包、路由隔离 | 壁钟；固定随机种子仍受 OS/GPU 抖动影响 | 低至中；功能与拥塞测量 |
| 记录流 + ns-3离散事件 | 请求事件经 socket/文件适配，逐包无线模型 | 仿真时钟；保存 seed/run、版本和拓扑 | 中；可重复无线比较，但固定回放不构成闭环 |
| 真实推理 + ns-3事件桥 | 推理完成触发消息，仿真到达触发上下文更新 | 事件屏障或协同调度；实测推理耗时作为延迟注入 | 高；主要闭环验证 |
| ns-3实时仿真 + TAP/FdNetDevice | Linux应用流量接入模拟设备 | 必须监测壁钟滞后；超预算实验作废或降速 | 高；真协议路径测试 |
| ROS 2 + Gazebo / Isaac Sim | 感知、执行、任务事件通过适配层 | 仿真 /clock 与网络时钟明确映射 | 高；网络原型稳定后接入 |
| 实体设备/SDR | 实际队列、驱动或可编程 PHY/MAC | 时钟校准、环境记录，多次重复 | 很高；后期验证可实现性 |

推荐次序是功能原型 → 记录流无线回放 → 事件驱动闭环 → 实时桥接。离散事件执行时若暂停仿真等待推理，必须把推理耗时记入模拟时间，并继续正确处理其他节点/链路的期间事件；不能把模型计算当作零延迟。共享 GPU 的排队要单独建模，不能原样当作多个端侧设备的独立计算耗时。

事件桥以 `episode_id/node_id/request_id/epoch/event_time` 为关联键。只在消息真正到达事件后更新对端上下文。网络随机数与模型随机数分离；记录所有输入、模型版本、采样参数、种子及环境初始状态。闭环随机生成难以逐 token 重现时，保存原始轨迹并分别报告重放稳定性与多种子闭环变异。

官方能力依据：[ns-3 Wi-Fi user documentation](https://www.nsnam.org/docs/models/html/wifi-user.html)。该文档列出 AP 上 MultiUserScheduler 与 UL/DL OFDMA 支持。具体安装版的支持范围和 TAP/实时模式组合须在下一阶段锁定版本后做轻量可行性检查，不能将最新在线文档直接当作本机能力。

## 3. 普通 Wi-Fi 的控制边界

Wi-Fi 6 支持 OFDMA 不意味着用户程序可以逐帧指定 RU。普通网卡开放能力随驱动、固件和 AP/STA 模式变化。Linux mac80211 的注入接口文档列出速率、重试等字段，但不能据此推出通用 RU 调度接口存在：[Linux 官方文档](https://docs.kernel.org/networking/mac80211-injection.html)。本项目暂不假定商用网卡支持所需 OFDMA 控制。

下一阶段建立能力表：芯片/驱动/固件、支持模式、信道/功率/MCS接口、队列可见性、RU可控性、TXOP可控性、时间戳精度。只有验证可执行并可回读的变量才进入真机动作空间。

ns-3 中先使用 AP 域内 RU 调度，再研究多簇干扰与骨干转发。纯去中心化 OFDMA 需要额外同步、资源协商和冲突恢复机制；不将其声称为现成 802.11s 能力。SDR 后续用于验证关键机制，需预算和工程条件，当前不采购。

## 4. 行为测量与日志

每个事件至少记录：wall_time、sim_time、clock_error、node/device/model_id、request/epoch/version、生成/接纳/首发/重传/接收/消费/取消时间、payload/wire bytes、parent_ids、reason_code、队列长度、链路、MCS/RU（可得时）、推理耗时、共享资源等待和任务真值。

测量区分 TTFT、生成耗时、总推理耗时；记录输入/输出 token、上下文长度和冷热启动。消息记录正文大小分布、轮次数、依赖入度/深度、阻塞持续时间、到达间隔、取消率、过期率和交互图。取消须区分业务取消、网络超时和模型错误；模型不可靠的自报重要性需人工审核子集。

在无拥塞、带宽受限、随机延迟、突发丢包、分区恢复五类条件下采集。不得只记录成功 episode；失败和空消息保留，人工修复另作标注。先小样本估计方差再制定重复次数；报告置信区间和随机种子，不预设必有显著提升。

## 5. 网络指标及测量口径

| 指标 | 定义 / 单位 | 测量方法与注意事项 |
|---|---|---|
| Effective Goodput | 窗口内及时、有效且首次被消费的独特 payload bit / 秒 | 消费日志与分片去重；压缩前后口径分开，内容质量另测 |
| 吞吐量 | 接收端独特 payload bit / 秒 | socket计数；另报逐跳 wire throughput，不混用 |
| 端到端时延 | 完整接收时间−生成时间，ms | p50/p95/p99；另报生成前推理与消费等待 |
| 截止违约率 | 未按期有效交付请求数 / 固定纳入请求数，% | 标明取消处理规则，并补报所有请求结果 |
| 队列/拥塞 | 时均和p95队列 bit；占满时间比 | 每节点/业务类采样；报告接纳率防止丢弃伪稳定 |
| 阻塞 | 等待前置消息的时间，ms及episode占比 | Agent阶段事件，区分模型计算等待 |
| 丢包/中断 | 链路尝试失败率、端到端丢失率；失联次数/分钟 | 分母分别为尝试数/独特消息数，二者不能互换 |
| 无效传输 | 过期、撤销、重复或不可用数据的 wire byte及airtime占比 | 应用真值与逐跳日志关联；“未消费”未必无用，保留原因 |
| 控制面开销 | beacon/路由/取消/ACK字节和airtime占比 | 使用统一分类，避免ACK漏计或重复计入 |
| 信道利用率 | 忙时长 / 观测时长，% | MAC/PHY trace或CCA；忙不等于有效工作 |
| 频谱效率 | 独特有效交付 bit / (Hz·s) | 明确域内总带宽、窗口；跨域复用另报空间指标 |
| 公平性 | Jain指数 \((\sum x_i)^2/(N\sum x_i^2)\) | 用需求归一化有效服务比，分母只含有需求节点 |
| 分区恢复 | 重连至版本一致/服务恢复耗时，ms | 两种恢复分别测；另报旧版本误消费次数 |
| 扩展性 | N、跳数、业务强度变化下goodput/延迟/控制开销 | 固定总负载与固定每节点负载两种实验 |
| 能耗 | 总J、J/有效Mbit、J/成功任务 | 功率积分；计算/移动/通信分项，注明估计或实测 |
| 应用结果 | 任务成功率、完成时长、错误动作率 | 固定任务集和真值；不能由LLM自评完全替代 |

广播采用接收者交付计数时必须标记，不能与源端 payload goodput 直接比较。不同模型/压缩设置同时报告字节、语义完整性和任务结果，避免“少发字节”机械降低 goodput 导致错误解释。

## 6. 基线与消融设计

保留普通网络基线：FIFO、EDF、latest-only/AoI、适用时的 AoII、队列 MaxWeight/Backpressure、最短路/ETX、标准竞争接入。OFDMA 域内增加 RR/PF；支持范围在所选 ns-3 版本中核验。逻辑拓扑剪枝和消息压缩单独作为 Agent 侧基线。AoII 实现需要可观测错误状态，不能给新方案真实状态而让基线缺失相同信息。

取消策略比较 TTL、源端取消、有界传播及洪泛；后者不是默认推荐。以网络控制 N 与应用反馈 A 做 2×2 实验，比较 \(Y_{11}-Y_{10}-Y_{01}+Y_{00}\) 的交互项及置信区间，统一选择“越大越好”的指标方向。非线性指标的交互项只作操作性证据，不证明理论协同。

加入：真实/打乱标签、无误/含误标签、不同状态滞后、固定/移动拓扑、单跳/多跳、无分区/分区。所有方法匹配算力、模型、无线预算和控制开销，集中oracle单独标记。
