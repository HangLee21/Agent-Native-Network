# D-022 快速开始所需的发布交接

本文供E1/E2/H在现有任务卡交接时对齐，非用户部署命令。D只消费正式发布字段，不新增网页/串口动作。

## 三设备目标

设备1只接A，设备2只接B，设备3只接C。应用→本机单串口所有者→板，板间ESP-NOW转发；主机之间不搬运业务数据、不共享串口、不依赖8766/8767。A→B→C明确预配置路由，直连另例。动态自动规划单列，不把预配置路径称为动态MID求解。

## 所需发布事实

- E1：有屏/无屏固件或可刷包、SHA256、每板配置文件实际位置；板号与MAC绑定，是否持久化；A/C冷启动、中继B独立重启后的真实恢复步骤；不能把某一次boot_id写死。
- E2：Python/依赖/离线分发范围、Windows与Linux的实际端口列举命令、唯一串口owner启动/停止；每机应用配置/本地接口地址；C先接收、A发送文字及非UTF8字节、B自动转发的发布命令；返回字段及端点身份关联；输出目录与新文件语义；重启后重连/重新配置步骤。
- H：TX接纳/实际TX、relay RX/已转发TX、目的rx_local分别怎样显示；短暂保持和空闲首页；无屏包不初始化I2C且相同API可用的证据范围；真实3主机或同机3进程+实板串口证据边界。

## 快速开始验收口径

C应用取到与A输入逐字节相等的payload，身份沿源MAC/源boot/原包seq匹配；B的接收与转发分开，A的接纳/链路回调不算C收到。OLED只辅助观察，不参与业务成功判据。未接端到端ACK时不得把TX状态称为目的交付确认。两种OLED目标共享收发接口，差异仅显示模块。物理重启证据由H提供，D仅检查命令入口/源码/保存证据。
