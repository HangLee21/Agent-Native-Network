# 首个任务：资源约束下的地表矿物协同勘查

更新：2026-10-20。本文件定义任务和待检验问题。已完成合成场景原型检查及 [Cuprite 航空数据观测代理初查](../../simulation/results/2026-10-20-cuprite-observation-v1/INTERPRETATION.md)；尚无真实地面测量、途中共享收益或新网络瓶颈的确认。

## 1. 任务立足点及证据边界

**任务定义：利用区域遥感先验安排多台地面设备的近距离观测，在有限作业预算内改善地表矿物分布的解释与制图。**

该任务对应找矿前期的地表调查，不将地表光谱异常直接等同于地下矿体、铁矿品位或经济可采储量。无人机提供区域观测，机器狗作为携带近距离科学载荷的候选平台。用户已有设备，但具体载荷和协作流程尚未确定；这些分工是拟议设计。

| 原始研究 | 已支持的任务事实 | 尚不能推出 |
|---|---|---|
| [P30 Otanmäki Fe-Ti-V](https://pub.geus.dk/en/publications/drone-borne-hyperspectral-and-magnetic-data-integration-otanm%C3%A4ki-/)，机构摘要，E1 | 铁钛钒矿区研究结合无人机高光谱、磁测和地面验证；不同观测具有互补性 | 无人机与地面机器人必须边走边通信；仅光谱即可确定铁矿储量 |
| [P31 Spatio-Spectral Exploration](https://publications.ri.cmu.edu/storage/publications/pub_files/2015/0/Thompson_2015_SpatioSpectral.pdf)，方法、实验、Table 1，E2 | 遥感与近距离光谱互补；有限路径预算下的采样选择可用真实区域数据仿真研究 | 单机器人结果证明多机器人通信收益，或自适应收益必然很大 |
| [P32 Legged Scientific Exploration](https://arxiv.org/abs/2307.10079)，系统与实验，E2 | 足式机器人可承载互补科学仪器，完成野外类行星科学勘查 | 已实现自主找铁矿、端侧大模型协作，或地球野外普遍存在其人为注入的控制室延迟 |

P31 的关键反证：相对已有科学目标指导的静态计划，反复重规划的额外收益较小。它支持采样任务本身，却要求本项目认真检验反馈的边际价值。Cuprite 数据也不是铁矿专项数据；可作为方法验证入口，不能替代后期铁矿场景验证。

目前没有一篇上述论文同时证明“无人机—机器狗找矿中的端侧 Agent 网络瓶颈”。这里建立的是有来源的应用任务；多节点实时共享是否必要，仍是下一阶段要检验的问题。

## 2. 最小任务闭环

1. 作业前，各节点获得相同区域遥感先验、可通行范围和资源预算。先验有分辨率、混合像元与噪声限制。
2. 地面节点依照已有采样方法选择位置，移动并取得近距离观测。测量消耗时间，有噪声及失败可能，不能直接读取环境真值。
3. 节点用自身观测更新本地解释；收到其他节点观测后，可更新对剩余采样位置的判断。失联时允许继续本地作业。
4. 预算用尽后汇总所有允许回收的数据，以相同后处理方法生成最终结果，并对独立评价区域核验。

最小多节点实验可从两台地面观测节点和一份预先采集的空中地图开始；这是实验设计，不是对现有设备数量的陈述。无人机在作业中再次观测作为后续扩展，不预设它必须持续在线、中继或频繁接受地面重规划指令。

**真正待检验的问题：其他节点的新观测能否在本节点做出下一次不可回收的移动或测量决定之前，改变采样选择并提高最终结果质量？**

地质场景可保持静态。信息的价值变化来自剩余行动机会和已经获得的证据，不需要假设矿物快速变化，也不人为规定每条消息的毫秒级期限。

## 3. 第一阶段评价对象

应用目标是有限预算下的制图质量。首轮可沿 P31 采用光谱重建误差作为可复现代理指标；它衡量观测对遥感信号的解释能力，不等于矿物类别识别准确率。要宣称地质识别改善，必须另有独立矿物标签或丰度真值。

评价区域、波段处理与误差归一化应在运行前固定，不能只评价算法自己挑选的采样点。记录时间、行程、有效测量数和重复访问，用来解释结果。不同策略保持相同设备、测量能力、起点、总预算与最终融合方式。

尤其允许离线策略在任务结束后汇总所有数据。这样，在线共享的收益只能来自它改变了作业过程，而不是因为故意不给对照组最终数据。

## 4. 初步仿真必须回答的两个问题

| 对照 | 固定条件和差异 | 要检验的命题 |
|---|---|---|
| 科学目标指导的静态分工 | 利用完整初始先验制定合理采样计划，允许终局汇总 | 良好的事前计划能解决多少 |
| 本地独立自适应 | 各节点依据自身新观测调整，允许终局汇总 | 不依靠途中共享，自治能解决多少 |
| 理想共享的自适应 | 保留采样、计算和移动耗时，仅去除交付阻碍；不能共享未来观测 | 跨节点反馈是否存在值得追求的收益上限 |
| 受限共享的自适应 | 与理想共享使用同一决策规则，只改变消息交付；先采用合理现有同步方法 | 通信限制是否实际损害任务收益 |

先比较前三组，再比较后两组。不直接设计新算法与弱 FIFO 对照。静态分工和本地自治需要合理调参；不能只采用随机巡游或强制节点等待来放大共享优势。

通信侧先检查紧凑观测共享、周期同步和机会同步；需要事件可靠性时再引入可靠事件传递。P28 MOCHA 与 P29 ACHORD 是设计依据，简化实现必须明确写成近似基线，不能冒称复现原系统。

初步仿真应覆盖“先验已足够好”和“新观测确实减少歧义”两类条件，以及网络几乎不影响结果的负对照。参数来自数据、论文或明确标注的敏感性范围；未有实测依据的带宽和中断参数只能说明条件性结果。

## 5. 数据、消息和模拟器的最低要求

下一阶段先核实公开遥感数据的下载可用性、许可、波段与空间配准。P31 给出了数据驱动仿真的先例，不代表我们已取得其全部数据或代码。

- 环境：可访问的区域观测数据、隐藏评价真值、可通行范围、节点位置和剩余预算。
- 观测：区分区域先验与近距离测量，包含采样成本和误差；避免向决策节点泄漏隐藏高分辨率真值。
- 信息：观测 ID、位置及误差、采集时间、仪器/校准标识、结果与质量；确有需要才请求光谱或图像附件，不预设全量广播。
- 因果：消息到达后才能更新接收端认知；更新可以改变后续行动，因此必须允许闭环轨迹分叉。
- 记录：产生、入队、交付、消费和后续决策时间，计算/测量耗时，任务质量与实际传输字节。

这些要求现已用于选择 Python/SimPy 并搭建初步任务级原型，不要求先取得大量现场轨迹。原型采用清楚标注的合成数据和简化通信条件；涉及具体无线协议结论时再增加相应网络保真度。

## 6. 阶段验收及停止条件

**文献确定任务 → 选模拟器并做初步仿真 → 确认条件性问题及边界 → 搭建理论模型和算法 → 更高保真及实机验证。**

本轮已给出任务对象、证据、流程、评价口径和反证对照，可以进入数据与模拟器选型。初步仿真必须允许以下结果：

1. 理想共享相对合理静态计划和本地自治都无实质收益：停止以此任务支撑在线协作网络选题。
2. 理想共享有收益，但合理现有通信方案已接近它：任务成立，新的网络机制依据不足。
3. 存在稳定、可解释的剩余差距：定位是断连、传输服务、同步机制还是计算/感知所致，再决定理论模型的变量和研究层次。

“实质收益”阈值应在试验前按应用目标确定，同时报告效应大小、变异与开销；不在看到结果后挑阈值。仿真只能证明其建模条件下的问题存在，后期实机检验这些条件的代表性。

初期任务执行器可采用已有采样规则。只有证据显示模型推理产生了额外且重要的通信需求，才进一步主张 Agent 特有问题；不把大模型、多跳或跨层优化作为预设答案。
