# 救灾任务问题筛查

2026-10-21。用户提出从找矿转向救灾。本轮只完成问题层面核查，不宣称已验证新网络机制。相比此前光谱覆盖代理，建筑内搜索结果向外部接收者交付有更直接的任务定义与通信证据。

## 原始证据及限制

- [NIST TN1545](https://www.nist.gov/publications/attenuation-radio-wave-signals-coupled-twelve-large-building-structures)：12座大型建筑内外传播实验，报告材料和结构造成的衰减及空间变化。本轮核实官方摘要；不是燃烧中火场测量，不将烟雾直接设为无线衰减原因。
- [NIST IR8243](https://nvlpubs.nist.gov/nistpubs/ir/2019/NIST.IR.8243.pdf)：核查摘要、引言和测试框架，研究受控衰减下应急机器人的任务能力；主要面向遥操作，不能转为端侧自主Agent必然受相同影响的证据，也不直接代表现场性能。
- [DARPA SubT官方任务](https://www.darpa.mil/research/programs/darpa-subterranean-challenge)：目标发现、分类定位及回报指挥点构成明确任务链。它是竞赛代理，场景含城市地下结构；不能把竞赛截止时间当作伤员生存期限，或把赛场等同真实火灾。
- [P29 ACHORD §V](https://arxiv.org/html/2206.02245)：现场多机器人存在失联与积压，并已有分层传输、中继和通信感知移动；记录利用另一机器人救回受困节点数据的案例。最长1058秒是无法向基站传数据的时段，不是包时延；跨天策略比较非严格因果对照。它支持问题真实，也构成必须认真比较的已有方案。

NIST与DARPA材料作为报告/任务证据单列，此次未扩充论文主表，维持35篇。现阶段不能声称真实火灾中的发生率、收益幅度或Agent特有瓶颈已获证实。

## 推荐先收敛的任务

**受限连通建筑中的多机器人搜索、发现回报与核查协同。** 以建筑火灾/倒塌后的应急搜索为应用动机，第一轮仅模拟搜索和信息交付，不模拟救治效果或要求普通设备进入高温区。

无人机可承担可进入空间的快速侦察或外部覆盖，地面机器人检查其可通行区域；两者的进入、视野、续航和通过性必须分别建模。不预设无人机能穿透楼板看见室内人员，也不强制任何平台一直充当中继。先保留双地面节点基线，只有异构能力真实改变任务时再加入空地分工。

最小任务有两层，不能混为同一证据：

1. 发现回报：机器人发现候选目标，生成类别/位置/不确定性/时间及可选证据；接收端在运行中接收有效报告。发现时间和接收时间分开，结束后回收不能追溯成早期回报。此层主要验证交付，是普通机器人网络问题。
2. 协同核查：有权限的接收节点基于已收到报告选择核查目标，或调整尚未完成的搜索。此层是否优于独立搜索需要单独证明；不人为强迫另一节点等待，不假设每次发现都必须跨模态二次确认。

与找矿的关键差异是任务产品包含“他方知道了什么、何时知道”，不是只在结束后统一重建一张地图。这样的交付目标可由实际任务流程约束；不能仅通过给离线基线判零分来证明在线机制新颖。

## 初步仿真的必要对照

- 所有方案均保持失联自主搜索、记录和最终回收能力，分别报告最终发现总量与运行中有效回报曲线。
- 同一任务执行器比较理想交付、立即发送加缓存重试、定期返回/机会同步、紧凑摘要优先及按需证据、固定或可部署中继。预算同时计入中继数量、移动、能量和计算。
- 先固定或控制感知与移动失败，隔离通信影响；再独立加入假阳性、定位误差和节点失效。不能把识别失败、摔倒丢数据一律计为网络问题。
- 断连与拥塞分开：无链路时换队列调度无法凭空传输；链路可用时才检验队列与证据传输是否造成额外损失。
- 保留几乎全连通、短报文即可充分决策、静态合理分工已足够等负对照。允许既有方法消除差距。

先报告发现→有效接收延迟分布、随时间变化的正确独特目标回报数、重复/误报、核查到达时间（若有）、探索覆盖、通信/移动/中继开销。若需要期限，先用任务时间窗扫描并标为敏感性值，不预设毫秒级时限或伤员死亡模型。

## 模拟器与研究边界

[OSRF SubT](https://github.com/osrf/subt)公开Gazebo资产、ROS接口和通信插件，可作为已定义搜索任务的后续仿真入口。官方[通信配置源码](https://github.com/osrf/subt/blob/master/subt_ign/launch/cloudsim_sim.ign)包含visibility_range模型；其参数是仿真配置，不是火灾现场校准值。本轮未安装、未验证当前依赖兼容性，也没有宣称具备燃烧/烟流/热安全模型。

第一步仍可用任务级离散事件模型排查因果关系，再按需要接入建筑几何、机器人感知运动和无线传播。不要同时建立火灾流体、导航、识别、大模型和网络全栈后才问问题是否存在。

立项判断分三层：灾害搜索与交付任务真实；具体已有通信方案后的剩余损失待测；Agent-Native特有需求尚未成立。有现场指挥点不妨碍机器人间去中心化转发，但必须分别标注通信架构与任务指挥架构，不能把存在接收端自动称作完全去中心化。

**当前选择：救灾搜索回报比继续光谱覆盖调参更值得进入任务定义。** 这是基于已读证据的研究优先级判断，不是已证实的论文创新或火灾现场效果。
