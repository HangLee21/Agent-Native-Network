AD-HOC · 本机板端自动路由

尚未接入本板接口。

这一步打开每台车自己的单板服务。8767不代发、不算路，不会改用台架或模拟发送。

打开本机 AD-HOC 工作台
服务离线：启动本机服务

已安装Ubuntu车机：在这份项目根目录执行下面一条命令，按已登记的本机配置更新并启动服务；板须接在已登记的USB插槽。

sudo python3 deploy/ubuntu/install.py install --config /etc/mid-edge/config.json --activate

临时本地启动（Windows或Linux）：填写本机端口和本板STA MAC，生成一条命令。它只连接本机一块板，不配置路由或启动射频；同一串口先关闭其他客户端。

填写本机串口与本板MAC后生成。
首次安装 / 当前模式未就绪
  1. 新车先按Ubuntu一车一板指南登记精确USB ID_PATH、接口和本板STA；首次用observe策略。
  2. 自主固件正式包：.local/mid/E1-025/oled-package-01/HANDOFF.json。由设备持有者按实际MAC核对；旧固件不能靠改网页选项变成自主路由。
  3. 已装自主固件但仍为旧模式时，先由设备持有者显式stop/清相应旧profile；再仅配置共同组/信道/自启，不能装远端路径。
配置成功、原生模式为autonomous后，页面才开放最终目的MAC发送。源端接纳、板端选路、本板提交和目的本地收到分开显示。配置/刷写步骤不会由这个入口自动执行。
