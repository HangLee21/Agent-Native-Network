## 0. 问题存在性审查：先证明损失，再讨论机制

**本轮修正：存在真实的机器人通信约束，也存在特定端侧 Agent 负载的网络瓶颈；尚无充分证据证明本项目设想的“多设备独立推理、多跳无线、动态依赖失效”组合构成普遍且严重的未解决问题。** 下面的判断优先于后文 H1–H6 和架构草案。文献未覆盖八个条件，不是问题存在的证据。

### 0.1 判定标准

“强存在”至少需要回答：谁在什么实际任务中受损；在什么部署与负载范围出现；损失是否可归因于网络；合理的现有方法之后还剩多少损失。现场报告支持发生过，受控实验支持特定条件下的因果机制，二者都不能单独证明普遍发生率。愿景、模拟注入的严重故障、论文展望和缺少指标只产生待检验问题。

本轮进行定向问题审查，新增五篇原始系统/实验报告 P23–P27，分别覆盖两个 SubT 团队、ROS 2 传输、端侧 Agent RTC 和语言驱动空地协作。未运行实验，未获得本项目真实业务轨迹；这不是穷尽式检索。

### 0.3 哪些问题可以立足

| 问题陈述 | 存在性判断 | 对当前选题的意义 |
|---|---|---|
| 野外移动机器人无法始终保持信息交换，必须在离线自治和获取他端信息间取舍 | **现场证据较强**，P23/P24/P27；发生率和任务损失仍依场景 | 最贴近原始机器人方向的事实基础；中继、机会通信、缓存、紧凑表示已是强先例 |
| 大消息在有损无线上的分片、重传和恢复积压导致交付退化 | **实验条件内证据较强**，P25 | 属于已有网络/中间件问题；默认配置差不能直接作为新协议动机 |
| 端侧推理优化引入的大上下文流挤压实时业务 | **特定工作负载下直接证据较强**，P26 | Agent 关联最直接；已有实现和解决方案，必须证明目标部署存在额外限制 |
| 普通文本 Agent 交互天然构成带宽瓶颈 | **证据不足** | 不得作为论文前提；必须测量消息率、实际线上字节和竞争关系 |
| 重规划使大量在途消息失效并显著损害任务 | **证据不足** | 有重规划不等于有可观的空口浪费；H1/H2 暂不能作为研究动机 |
| 依赖信息比期限、优先级、AoI/AoII、限速更有价值 | **未验证的机制假设** | 需要应用自然产生的依赖及强基线后的剩余收益 |
| 必须同时改路由与 OFDMA 才能解决 Agent 协作 | **证据不足** | 不能预先锁定跨层解法；从问题损失反推最小必要改动 |

### 0.4 当前建议的问题表述及边界

优先继续核查：**在真实存在连接间歇的移动协作任务中，机器人何时确实必须获得其他节点的信息；已有紧凑表示、机会通信和本地自治之后，信息不可达或交付不及时仍造成哪些可测量的任务损失？**

这是调查问题，不是已经成立的创新结论。首先核实 P27/MOCHA 类系统的故障记录、同步策略和任务等待，再判断“多个端侧模型”是否改变信息需求。不能用云 API 断连损失替代本地模型的节点间通信损失。

若选择 P26 类型业务，则问题应限定为“上下文传输与实时业务共享链路的冲突”。必须比较原始文本、本地 prefill、压缩和已有 HAFS/FSE；不能为了产生通信压力而强制所有节点传 KV cache。该路线的问题证据更直接，但与野外去中心化机器人目标有明显距离，不默认转题。

### 0.5 必须先通过的证据门槛

1. **真实需求。** 固定一个有来源的任务及部署，保留正常成功、失败和低流量样本。截止期来自任务约束，消息取消来自任务事件；不人为增加取消率、对话轮数或载荷以凸显方案。
2. **因果拆分。** 同步记录采集、推理排队/执行、发送排队、交付、接收消费与动作。按关键路径分析重叠阶段；总完成时间减去推理时间不能直接视作网络时间。配对比较改善网络、改善算力、改变通信表示，区分网络、模型错误和感知/控制失败。
3. **合理基线。** 包括适配配置的 DDS/传输、限速/优先级/期限、紧凑表示、本地自治和适用的机会通信；缓存策略遵守应用可靠性要求，不能以丢弃必要数据换“低延迟”。
4. **剩余损失。** 先按任务容忍度定义值得解决的影响，再测量重复性、尾部与区间；不任意规定“提升 20%”作为问题存在标准。无残余损失，或只在刻意过载下出现，则停止该机制方向。
5. **Agent 的额外作用。** 在字节量、消息率、截止期相当时，与普通 RPC/遥测比较；若结果仅由这些传统属性解释，应如实定位为通用网络研究。测得额外属性后才重启 H1–H6。

**推进决定：保留应用方向，暂缓机制立项。** 当前最值得投入的是任务与网络损失的证据核查；还不能给出“Agent-native 全栈协议已经具有充分问题基础”的结论。

### 0.6 第二轮：沿现场失败和现有实现追踪

**P27 的因果核查。** §5.2/Table 5 中，S1 的三次任务有两次失败：里程计漂移与无法执行云端 LLM 查询各一次。它支持云依赖的可用性问题，不能转记为端侧节点间协作失败。§7.1 明确把可通行性估计列为主要瓶颈。§5.3 的“空地协作优于无地图单车”同时改变了可用信息和系统组成，并非网络协议消融；不能把成功率差全部归因于通信优化。

**P28 MOCHA 的既有解决能力。** [原文](https://arxiv.org/html/2309.15975) §III–IV 报告 1720 次现场交互中 99.5% 完成，返回通信范围后未观察到网络堵塞。该分母是已发起的同步交互，不是全部消息需求或任务，不能推出信息一直及时可用。现场禁用了 Rajant 的 Mesh 转发、采用单跳接触；数据可通过后续接触携带传播，不能等同于同时连通的无线多跳路由。拥塞影响任务的规模实验采用简化信道模型，尚非大规模真机证明。

**P29 ACHORD 的损失与缓解。** [原文](https://arxiv.org/html/2206.02245) §V/Table I 的最大无法向基站传数据时段达到 1058 秒，属于失联区间，不是数据包时延。Fig.8 报告重连后积压及数据分层后的改善；两图来自不同天、机器人数量也不同，不能当严格配对因果实验。系统已有按数据类别保证、限速、队列反馈和通信感知移动，并记录其他机器人中继救回受困节点数据的案例。

### 0.7 现在可以收窄到什么程度

最有依据的应用问题是：**节点离线探索时，任务相关信息暂时无法交付；恢复接触后，必须在有限通信机会内兼顾不能遗漏的事件和可被新状态替代的数据。** 该问题在传统机器人网络已存在并有系统解决方案，Agent 并非其存在的必要条件。

目前仅保留两个待核查分支，不把它们写成既成研究空缺：

| 分支 | 必须取得的自然业务证据 | 现有强基线与否定条件 |
|---|---|---|
| 有限接触中关键事件是否被挤压或遗漏 | 真实任务的消息类别、产生时刻、接触窗口、确认/消费记录；事件是否真的不能被最新快照替代 | ACHORD 数据分层与限速；MOCHA 最新状态及应用层事件聚合。若合理分类后损失消失，停止 |
| 已有优先级是否仍使必要信息晚于任务需要到达 | 任务等待关联到具体消息，期限来自实际动作；有空口/队列证据而非模型自述 | 固定优先级、期限、最新状态、压缩和机会转发。若损失主要来自失去连接、算力或感知，不能靠调度论文解释 |

先排除“根本没有传输机会”的损失，再研究有接触时如何分配资源。没有端到端连通路径时，队列调度不能凭空交付；数据携带、增加中继或改变移动行为是不同干预，须分别报告代价。

**本轮判断：一般问题存在性加强，Agent 特有性及现有方法后的剩余损失仍未证实。** 当前按用户确定的仿真优先顺序推进：[TASK_DEFINITION.md](TASK_DEFINITION.md) 给出有文献依据的任务，随后通过闭环初步仿真取得逐事件证据；现场测量留到后期校准。初期结论只适用于所建模条件，不以愿景文献替代因果验证。

### 0.8 找矿应用审查：互补观测成立，实时联网尚待证明

**实验室事实边界（用户确认）：** 无人机、机器狗平台已具备；协作流程、光谱类型、地面载荷、端侧算力和通信链路尚未确定，可考虑后续改装。本文提出的流程均是待验证方案，不是已有项目事实。火灾保留为对照方向；找矿因具备实验平台而优先核查，不代表其网络问题已被证实。

| 证据 | 已经支持什么 | 不支持什么 |
|---|---|---|
| P30 Otanmäki Fe–Ti–V，[研究机构记录](https://pub.geus.dk/en/publications/drone-borne-hyperspectral-and-magnetic-data-integration-otanm%C3%A4ki-/) | 无人机光谱/磁测与地面光谱、pXRF、磁化率及地质调查共同验证矿化信息；空地观测互补有实际基础 | 本轮取得机构摘要及元数据，尚未核查全文流程；不能确认实时反馈，不能把光谱代理异常等同地下矿体或品位 |
| P31 Spatio-Spectral Exploration，[原文](https://ojs.aaai.org/index.php/AAAI/article/view/9673/9532)，Approach/Experiments | 用现场光谱改善遥感解释并选择采样位置，形成资源约束下的自适应勘查问题 | 实验用 AVIRIS 数据代理原位观测，结合 ASTER 做仿真；不是实地无人机—机器狗网络实验 |
| P32 Legged scientific exploration，[原文](https://arxiv.org/html/2307.10079)，Results/Autonomy/Communication | 多台 ANYmal 配置互补科学载荷并完成模拟地外勘查；科学家在任务中选择目标，机器人自主执行 | 5秒 RTT 在控制室链路人为注入，机器人间为低毫秒；未证明地球找矿通信普遍严重受限。失联时 Scientist 等待也与无法自主选新目标有关 |

因此，应拆开三条证据链：**观测互补 → 同次作业反馈有价值 → 网络限制损害该价值。** 当前第一条有直接应用依据，第二条有自适应勘查先例但尚未针对本项目确认，第三条尚缺本地业务及链路测量。LLM 不是上述任一条成立的必需条件。

暂定任务为“地表含铁矿物/矿化指示区的候选筛查与核查”，具体对象和地面判据仍待确定，不承诺发现经济矿体。应先确认实验室能够取得何种矿物/成分真值，再决定地面仪器；仅有 RGB 图片不自动构成矿物确认。

可检验的工作流为：无人机形成带位置与不确定性的候选点 → 地面机器人取得独立证据 → 更新候选区解释或核查顺序。**地面反馈是否还要改变无人机航线是额外假设**，不能为了制造双向通信而强制重飞。如果航空数据已覆盖全区且质量足够，反馈仅影响地面后续取样也可能是更合理的流程。

网络时效应来自“下一次不可轻易撤销的行动决策”：反馈若在设备离开候选区、确定下一个核查点或结束可用作业窗口之后才到达，可能错失调整机会。这是拟测的机会损失，不是已知事实；地质目标相对静态时，消息价值也不必随时间快速衰减。不要套用火灾式统一紧急期限。

首要排除项：离线流程已足够；空地时间尺度不匹配导致无人机早已返航；小型摘要在现有链路上毫无压力；主要误差来自校准/定位/矿物判别；只有强制传完整光谱数据才出现瓶颈。出现这些结果应降低或停止该网络选题，而非继续放大载荷。

### 0.9 具身智能网络扩展性：结合新增综述的核心问题分析

2026-10-23。输入为用户提供的[《任务感知网络调度_新版文献综述_论文原图版.pdf》](../../任务感知网络调度_新版文献综述_论文原图版.pdf)，共19页；重点对应第7–9、14–19页。全文抽取后检查横向对照及研究位置页面，并沿引用核查原始来源。各论文阅读版本、证据位置和机制见[综述补查表](RELATED_WORK.md#survey-network-screen)。本节的模型、研究取舍和实验方案是本项目的综合分析。

首轮实验入口及评价见[研究方案](AGENT_COLLAB_BASELINES.md#first-study)：先研究分布式状态交换与消息发送调度，联合更新触发和队列服务。该入口用于建立可归因的对照，保留MAC、PHY、路由及跨层优化的研究空间。MOCHA是直接协议对照，AutoCast提供任务价值发送对照，HeteroMRTA为固定任务执行器。

#### 核心判断：扩展团队时，维持协作的网络成本也在增长

建议把核心问题表述为：

> **在节点规模、协作关系和接触关系持续变化的具身集群中，如何在有限共享无线资源下维护足以支持决策的协作状态，并及时交付任务所需信息，使团队扩展仍能带来协作收益？**

这里有一个具体矛盾：节点要选择合适的合作方、决定传什么，需要先知道对方的需求、能力、负载和已有信息；取得这些状态又消耗与任务数据相同的网络资源。同步不足会导致决策依据过时，同步过多会挤压实际观测、请求与结果。移动和任务变化同时改变需要维护哪些状态、这些状态能维持多久，以及有哪些传输机会。

这使用户提出的“网络资源不能一直作为固定输入”有了更精确的落点：**分布式决策所依赖的信息和服务预算，都需要由正在被控制的网络提供。** ARMA/CORA已处理动态资源协调，C-MASS显式允许时变带宽和信道，CoSMO已有带状态缓存的决策闭环；我们应沿这些机制继续研究共享竞争域、多个自主决策者和规模增长。

#### 文献提供的三个关键支点

1. **资源同比增长与固定无线资源下的扩展，是两个实验问题。** Co-Scheduling v1 §V-B Definition 2将任务数、各源计算预算和共享信道数同时乘以扩展因子。其MGF结论给出可借鉴的调度效率分析。我们的重点是节点或协作需求增长时，频谱、局部空口和接触机会没有同比扩张的情形。[原文](https://arxiv.org/html/2501.04231v1)
2. **协调开销随规模增长已有具体案例。** CC-OPI补充材料Table S4中，固定场地从10节点/30任务扩展到128节点/384任务，每完成任务广播数从54.7增至99.1。该指标是应用层广播统计，可据此追踪状态大小、拓扑事件和协商次数如何转化为空口占用；其任务发现信息的全局公告假设也提供了明确的观测接口。[原文](https://arxiv.org/html/2609.19208v1)
3. **任务价值与信息维护之间已有强baseline。** AutoCast依靠单跳域内共同控制消息构造分布式发送计划；C-MASS在接收者给定带宽预算下处理动态互补观测；CoSMO联合学习状态更新与任务卸载，并用ns-3模拟共享回传。下一层问题是多个这样的决策域共用无线介质时，预算和调度依据如何形成。[AutoCast](https://arxiv.org/html/2112.14947)、[C-MASS v1](https://arxiv.org/html/2407.00412v1)、[CoSMO](https://arxiv.org/html/2609.01082v1)

#### 救灾场景如何承载这一问题

以“无人机提供外部观测、地面机器人执行搜索或核查”为任务链：一台地面机器人需要决定向谁请求视角、是否已有同伴处理目标、结果能否赶上下一次行动。相关信息包括紧凑的任务/能力/负载状态和较大的观测内容。增加机器人后，需要交换的状态及并发请求可能增加；移动又使原合作方与接触机会变化。可测的损失是重复派遣、等待无效合作方、必要观测迟到和任务完成时间增长。每一项都应由原任务策略与送达事件产生，并关联到具体决策日志。

这一工作流承接[救灾实际任务证据](RESCUE_OPERATIONAL_EVIDENCE.md)和已有任务调度复现。先固定端侧任务策略，通过网络到达更新其信息缓存；Agent-Native接口表达本地任务需求、信息用途、接收对象及消费结果，网络向节点反馈交付、积压和可达性。后续可以替换任务策略或端侧模型，网络机制仍是研究主体。

#### 三个相连、可以分别验证的研究问题

| 问题 | 可观察的失效过程 | 对应网络控制 |
|---|---|---|
| 维护哪些协作状态，何时更新？ | 消息变旧→选错伙伴或重复执行；频繁同步→任务数据排队 | 邻居/订阅范围、事件触发、更新频率、状态聚合与控制流预算 |
| 已有信息是否仍对当前接收者有用？ | 对方已完成、已有同类观测或已改变任务；单条信息到达而互补信息缺失 | 接收者感知的内容选择、广播/单播、组合信息发送次序 |
| 各节点的发送计划如何共享实际无线服务？ | 多个局部计划争用同一冲突域；跨跳与重连积压使预算失准 | 接入与队列服务、拥塞反馈、逐跳转发及接触预算 |

第一项作为首轮主问题，第三项提供实际资源约束；第二项通过AutoCast/C-MASS提供更强的信息价值对照。综述第19页的三个候选方向据此有了主次：优先共享介质中的状态维护与任务数据调度，再扩展多视角组合收益和多跳接触控制。

#### 最小数学骨架

区分物理通信图 $G_t$、无线干扰关系 $H_t$ 和任务协作图 $D_t$。节点 $i$ 的远端知识 $\mathcal I_i(t)$ 只能由实际到达的消息更新。给定任务策略 $\pi_i^{\rm task}$，

$$
a_i(t)=\pi_i^{\rm task}(o_i(t),\mathcal I_i(t)),\qquad
A_{i,\mathrm{local}}^{c,d}(t)=\Lambda_i^{c,d}(a_i(t),o_i(t),\mathcal I_i(t),u_i^{\mathrm{update}}(t)).
$$

$c$ 表示协作状态/控制流，$d$ 表示任务数据流；$u_i^{\mathrm{update}}$ 为更新触发动作。一个时间槽内的到达字节为 $A_i^k=A_{i,\mathrm{local}}^k+A_{i,\mathrm{relay}}^k$，逐跳转入量由邻居发送、路由与实际交付事件产生。任务动作改变后续位置、任务关系与信息需求，因此未来 $G,D,A$ 与任务执行有关。

$$
Q_i^k(t+1)=Q_i^k(t)-\mu_i^k(t)+A_i^k(t)-R_i^k(t),\quad k\in\{c,d\}.
$$

$\mu$ 是实际成功出队量，满足 $0\leq\mu_i^k(t)\leq Q_i^k(t)$。$R$ 为本槽服务与到达后，由旧版本替换等消息生命周期规则移除的字节，满足 $0\leq R_i^k(t)\leq Q_i^k(t)-\mu_i^k(t)+A_i^k(t)$；必要事件按其可靠交付语义处理。保留的本槽到达供下一槽服务。可行服务集合由链路、干扰、MAC与编码开销共同约束。初步采用单个冲突域内的无冲突调度模型，用空口时间表示为

$$
\sum_{\ell\in\mathcal C}
\left(\tau_\ell^c(t)+\tau_\ell^d(t)+\tau_\ell^{\rm frame}(t)\right)
+\tau_{\mathcal C}^{\rm idle}(t)
\leq\Delta t.
$$

这里帧级开销包括相应的帧头、ACK等；信道空闲/退避时间在域内只计一次。广播一次发送的空口成本与多个接收者的收益分别计数。接入竞争模型后，碰撞及重传由MAC事件产生，重叠发送按信道占用时间的并集计量；多冲突域由可并发链路集合扩展。

首轮对照采用的局部网络策略动作为

$$
\pi_i^{\rm net}(o_i,\mathcal I_i,Q_i,\widehat G_i)
\longrightarrow (\text{更新触发、队列次序、发送预算}),
\qquad
\max_{\pi^{\rm net}}\mathbb E[U_{\rm task}].
$$

首轮接收/传播集合固定，后续作为扩展控制量。$U_{\rm task}$ 按被复现任务定义：完成比例或感知效用采用原方向；全部任务完成时的makespan采用 $U_{\rm task}=-T_{\rm finish}$，等价于最小化完成时间。有限实验预算下同时记录未完成比例。通信受硬预算约束，同时单列能耗与控制开销。消息收益写为 $\Delta U(m\mid\mathcal I_i,t)$，强调其依赖当前已知信息；互补任务用集合收益 $U(S)$。这两者用于定义/估计价值，策略不能直接读取模拟器中的未来真实收益。

求解难点由此具体化：信息价值部分可观测，状态获取本身是控制动作；无线可行集合随移动和干扰变化；组合信息收益可能非可加。MGF、事件触发和贪心提供可解释起点，CoSMO提供学习更新策略的对照。先用复现定位主要损失，再决定哪部分需要学习或优化求解。

#### 用baseline把问题测出来

保持HeteroMRTA/原Greedy的复现作为任务执行器入口，同时提取AutoCast的分布式调度机制。MGF先在其原推理模型验证，C-MASS先在其互补感知条件验证；迁移到同一救灾任务后明确标为机制适配。ARMA/CORA用于任务—网络服务接口设计，MOCHA/ACHORD继续承担机会同步、分层与流控对照。具体角色见[baseline表](AGENT_COLLAB_BASELINES.md)。

原始表现复现之后，进行三组配对诊断：

1. **状态成本与可得性。** 原信息条件 → 状态消息占用无线预算 → 仅到达后更新缓存。额外设置及时状态但计费、免费状态但延迟等诊断参考，区分资源挤占与过时决策，并报告二者交互。策略输入及动作mask一同审计。
2. **共享竞争。** 单局部域 → 多个请求者共享介质 → 部分可互闻与跨域竞争。保持需求轨迹的回放用于网络归因，再接入任务动作会改变后续需求的闭环实验。
3. **规模与动态。** 分别扫描节点数、每节点协作对象数、任务到达和拓扑变化速度。固定区域加密与固定密度扩区域分开；固定总任务量与固定每节点任务量分开；固定频谱与资源同比扩展分开。

主要输出为任务完成比例与完成时间随规模的曲线、控制空口成本、有效信息交付及尾时延。记录过时状态相关的决策差异，并另外测量其任务后果。HeteroMRTA能力互补任务采用同策略即时信息作为诊断参考；支持独立执行的任务才增加相对本地执行的净收益指标。新增节点的边际收益与收益饱和位置按场景报告。计算耗时、存储、应用层字节和空口占用分别记录，尤其不把全连接关系数 $O(N^2)$ 直接当作广播网络的字节增长律。

**本阶段产出：** 核心问题已收敛到“有成本的协作状态维护与任务数据服务”。接下来的复现围绕这条因果链展开，使具体算法建立在已定位的规模退化机制上。

后续每个baseline记录四项：①原条件下能达到的结果；②主要限制及机制解释；③拟改变的模型/算法/协议；④同等条件下的效果、成本和适用范围。允许以更低资源达到同等任务性能，也允许改善理论保证或在线复杂度。模型分析、机制设计和复现实验迭代推进。

## 3. 研究假设及证伪路径

所有假设均为本项目提出的待验证问题，排序表示测量优先级，不代表已经选定唯一论文方向。

| 假设 | 先例与具体证据边界 | 可证伪实验 | 比较重点 / 实现难度 |
|---|---|---|---|
| H1：依赖与版本信息在相同 QoS/龄期/队列下仍有额外预测价值 | P05 已提出标签；P15/P17 已利用时效/错误。缺少本项目业务下“条件额外价值”的证据 | 固定大小、期限、AoI、队列分布，加入真实/打乱/错误标签，比较有效交付和阻塞；若真实标签无稳定净收益则否定 | 与AoII比较建模、估计和决策效果；低至中 |
| H2：有界传播取消比源端 TTL 更节约多跳 airtime | P05 过时抑制、P16 时效传播；尚未核实其断续多跳撤销实现 | 比较 TTL、仅源取消、全网洪泛、本地有界 tombstone；计入控制重传。低取消率或长分区下净开销增加则限定适用域 | 与DTN/数据库机制比较传播代价、恢复与可靠性；中 |
| H3：依赖阻塞反馈改善路由与队列联合决策 | P01 拓扑联合、P21 队列；P06 有等待释放负载。现有两者不等于已验证的依赖感知多跳策略 | 对比最短路、ETX、Backpressure、EDF及相同元数据增强基线；若只靠期限即可取得同等效果则否定 | 比较期限路由与反馈机制的性能、成本及复杂度；高 |
| H4：慢推理—中速路由—快速 MAC 的分离控制产生净协同增益 | P01/P05 有多层架构，缺少本项目局部状态与开销约束下的闭环结果 | 网络侧 N、Agent反馈 A 的 2×2 消融；统一信息预算，测交互项、延迟、控制占比；若协同不超过最佳单侧则否定 | 比较跨层耦合方式、时间尺度、稳定性及净收益；高 |
| H5：阶段/依赖状态帮助 OFDMA 分配，但增益仅在拥塞与准确标签下存在 | P02 保护、P05 loop-aware radio 提供相近机制 | 同一 AP域对比 RR、PF、EDF、AoI/AoII、队列MaxWeight；标签年龄与误差扫参；若收益来自更多总资源则无效 | 比较任务效果、资源效率、标签误差敏感性和求解成本；高 |
| H6：按消息存活时间约束缓存/中继移动能改善分区恢复 | P16 时效、P05 移动连续性；多跳缓存/移动组合待查 DTN 先例 | 外生轨迹先比存储携带转发、周期复制，再加入移动中继；扣除移动能耗与任务偏离，若净收益消失则否定 | 以DTN为对照比较恢复时延、交付、复制及移动成本；很高 |

H1 首先检验信息是否有价值，H2 检验能否转成协议收益，H3–H6 检验跨层耦合。H1 被否定时，应保留普通 QoS/时效机制并重评其他假设，不能强行用复杂模型维持选题。

## 4. 判别场景与必要负对照

静态地图交换、无取消且低负载的消息流是负对照：预计普通可靠传输已足够。高频观测更新可能适合 latest-only/AoI，只有同一观测对应不同依赖分支时才可能需要额外结构。长分区场景中，再准确的语义标签也不能创造物理容量，应比较本地自主降级与延迟交付。

例如两条消息生成时间相同、长度相同、截止期相同，一条解除三台节点的等待，另一条属于已撤销分支。若网络仅使用前述 QoS 无法区分，依赖标签可能有价值；但网络获取标签和传播取消也需要 airtime。其**净**收益必须连同误判成本一起计量。

公平比较时所有算法共享可取得的元数据；另设剥夺元数据实验衡量信息贡献。集中 oracle 只能作为上界，不可与局部控制算法混为同等基线。固定轨迹回放用于隔离网络因素，真实闭环用于检查到达反馈改变未来需求，两种结果分别报告。

## 5. 统一系统候选而非单层收敛

接口定义对象 → 控制面传播局部状态 → 生命周期减少失效占用 → 路由选择服务路径 → MAC/PHY实际服务 → 到达/消费反馈更新请求。各模块共享 request/epoch/version，不要求共享完整模型状态。

保留三个整体验证配置：竞争式 Mesh 基线、弱中心 OFDMA 簇加多跳骨干、后续可编程无线实验。只有当模块交互产生超过单模块增益且开销可接受时，才主张跨层协同。若各模块可独立获得同等收益，应如实采用更简单实现。
