## 0. 问题存在性审查：先证明损失，再讨论机制

**本轮修正：存在真实的机器人通信约束，也存在特定端侧 Agent 负载的网络瓶颈；尚无充分证据证明本项目设想的“多设备独立推理、多跳无线、动态依赖失效”组合构成普遍且严重的未解决问题。** 下面的判断优先于后文 H1–H6 和架构草案。文献未覆盖八个条件，不是问题存在的证据。

### 0.1 判定标准

“强存在”至少需要回答：谁在什么实际任务中受损；在什么部署与负载范围出现；损失是否可归因于网络；合理的现有方法之后还剩多少损失。现场报告支持发生过，受控实验支持特定条件下的因果机制，二者都不能单独证明普遍发生率。愿景、模拟注入的严重故障、论文展望和缺少指标只产生待检验问题。

本轮进行定向问题审查，新增五篇原始系统/实验报告 P23–P27，分别覆盖两个 SubT 团队、ROS 2 传输、端侧 Agent RTC 和语言驱动空地协作。未运行实验，未获得本项目真实业务轨迹；这不是穷尽式检索。

### 0.3 哪些问题可以立足

| 问题陈述 | 存在性判断 | 对当前选题的意义 |
|---|---|---|
| 野外移动机器人无法始终保持信息交换，必须在离线自治和获取他端信息间取舍 | **现场证据较强**，P23/P24/P27；发生率和任务损失仍依场景 | 最贴近原始机器人方向的事实基础；中继、机会通信、缓存、紧凑表示已是强先例 |
| 大消息在有损无线上的分片、重传和恢复积压导致交付退化 | **实验条件内证据较强**，P25 | 属于已有网络/中间件问题；默认配置差不能直接作为新协议动机 |
| 端侧推理优化引入的大上下文流挤压实时业务 | **特定工作负载下直接证据较强**，P26 | Agent 关联最直接；已有实现和解决方案，必须证明目标部署存在额外限制 |
| 普通文本 Agent 交互天然构成带宽瓶颈 | **证据不足** | 不得作为论文前提；必须测量消息率、实际线上字节和竞争关系 |
| 重规划使大量在途消息失效并显著损害任务 | **证据不足** | 有重规划不等于有可观的空口浪费；H1/H2 暂不能作为研究动机 |
| 依赖信息比期限、优先级、AoI/AoII、限速更有价值 | **未验证的机制假设** | 需要应用自然产生的依赖及强基线后的剩余收益 |
| 必须同时改路由与 OFDMA 才能解决 Agent 协作 | **证据不足** | 不能预先锁定跨层解法；从问题损失反推最小必要改动 |

### 0.4 当前建议的问题表述及边界

优先继续核查：**在真实存在连接间歇的移动协作任务中，机器人何时确实必须获得其他节点的信息；已有紧凑表示、机会通信和本地自治之后，信息不可达或交付不及时仍造成哪些可测量的任务损失？**

这是调查问题，不是已经成立的创新结论。首先核实 P27/MOCHA 类系统的故障记录、同步策略和任务等待，再判断“多个端侧模型”是否改变信息需求。不能用云 API 断连损失替代本地模型的节点间通信损失。

若选择 P26 类型业务，则问题应限定为“上下文传输与实时业务共享链路的冲突”。必须比较原始文本、本地 prefill、压缩和已有 HAFS/FSE；不能为了产生通信压力而强制所有节点传 KV cache。该路线的问题证据更直接，但与野外去中心化机器人目标有明显距离，不默认转题。

### 0.5 必须先通过的证据门槛

1. **真实需求。** 固定一个有来源的任务及部署，保留正常成功、失败和低流量样本。截止期来自任务约束，消息取消来自任务事件；不人为增加取消率、对话轮数或载荷以凸显方案。
2. **因果拆分。** 同步记录采集、推理排队/执行、发送排队、交付、接收消费与动作。按关键路径分析重叠阶段；总完成时间减去推理时间不能直接视作网络时间。配对比较改善网络、改善算力、改变通信表示，区分网络、模型错误和感知/控制失败。
3. **合理基线。** 包括适配配置的 DDS/传输、限速/优先级/期限、紧凑表示、本地自治和适用的机会通信；缓存策略遵守应用可靠性要求，不能以丢弃必要数据换“低延迟”。
4. **剩余损失。** 先按任务容忍度定义值得解决的影响，再测量重复性、尾部与区间；不任意规定“提升 20%”作为问题存在标准。无残余损失，或只在刻意过载下出现，则停止该机制方向。
5. **Agent 的额外作用。** 在字节量、消息率、截止期相当时，与普通 RPC/遥测比较；若结果仅由这些传统属性解释，应如实定位为通用网络研究。测得额外属性后才重启 H1–H6。

**推进决定：保留应用方向，暂缓机制立项。** 当前最值得投入的是任务与网络损失的证据核查；还不能给出“Agent-native 全栈协议已经具有充分问题基础”的结论。

### 0.6 第二轮：沿现场失败和现有实现追踪

**P27 的因果核查。** §5.2/Table 5 中，S1 的三次任务有两次失败：里程计漂移与无法执行云端 LLM 查询各一次。它支持云依赖的可用性问题，不能转记为端侧节点间协作失败。§7.1 明确把可通行性估计列为主要瓶颈。§5.3 的“空地协作优于无地图单车”同时改变了可用信息和系统组成，并非网络协议消融；不能把成功率差全部归因于通信优化。

**P28 MOCHA 的既有解决能力。** [原文](https://arxiv.org/html/2309.15975) §III–IV 报告 1720 次现场交互中 99.5% 完成，返回通信范围后未观察到网络堵塞。该分母是已发起的同步交互，不是全部消息需求或任务，不能推出信息一直及时可用。现场禁用了 Rajant 的 Mesh 转发、采用单跳接触；数据可通过后续接触携带传播，不能等同于同时连通的无线多跳路由。拥塞影响任务的规模实验采用简化信道模型，尚非大规模真机证明。

**P29 ACHORD 的损失与缓解。** [原文](https://arxiv.org/html/2206.02245) §V/Table I 的最大无法向基站传数据时段达到 1058 秒，属于失联区间，不是数据包时延。Fig.8 报告重连后积压及数据分层后的改善；两图来自不同天、机器人数量也不同，不能当严格配对因果实验。系统已有按数据类别保证、限速、队列反馈和通信感知移动，并记录其他机器人中继救回受困节点数据的案例。

### 0.7 现在可以收窄到什么程度

最有依据的应用问题是：**节点离线探索时，任务相关信息暂时无法交付；恢复接触后，必须在有限通信机会内兼顾不能遗漏的事件和可被新状态替代的数据。** 该问题在传统机器人网络已存在并有系统解决方案，Agent 并非其存在的必要条件。

目前仅保留两个待核查分支，不把它们写成既成研究空缺：

| 分支 | 必须取得的自然业务证据 | 现有强基线与否定条件 |
|---|---|---|
| 有限接触中关键事件是否被挤压或遗漏 | 真实任务的消息类别、产生时刻、接触窗口、确认/消费记录；事件是否真的不能被最新快照替代 | ACHORD 数据分层与限速；MOCHA 最新状态及应用层事件聚合。若合理分类后损失消失，停止 |
| 已有优先级是否仍使必要信息晚于任务需要到达 | 任务等待关联到具体消息，期限来自实际动作；有空口/队列证据而非模型自述 | 固定优先级、期限、最新状态、压缩和机会转发。若损失主要来自失去连接、算力或感知，不能靠调度论文解释 |

先排除“根本没有传输机会”的损失，再研究有接触时如何分配资源。没有端到端连通路径时，队列调度不能凭空交付；数据携带、增加中继或改变移动行为是不同干预，须分别报告代价。

**本轮判断：一般问题存在性加强，Agent 特有性及现有方法后的剩余损失仍未证实。** 当前按用户确定的仿真优先顺序推进：[TASK_DEFINITION.md](TASK_DEFINITION.md) 给出有文献依据的任务，随后通过闭环初步仿真取得逐事件证据；现场测量留到后期校准。初期结论只适用于所建模条件，不以愿景文献替代因果验证。

### 0.8 找矿应用审查：互补观测成立，实时联网尚待证明

**实验室事实边界（用户确认）：** 无人机、机器狗平台已具备；协作流程、光谱类型、地面载荷、端侧算力和通信链路尚未确定，可考虑后续改装。本文提出的流程均是待验证方案，不是已有项目事实。火灾保留为对照方向；找矿因具备实验平台而优先核查，不代表其网络问题已被证实。

| 证据 | 已经支持什么 | 不支持什么 |
|---|---|---|
| P30 Otanmäki Fe–Ti–V，[研究机构记录](https://pub.geus.dk/en/publications/drone-borne-hyperspectral-and-magnetic-data-integration-otanm%C3%A4ki-/) | 无人机光谱/磁测与地面光谱、pXRF、磁化率及地质调查共同验证矿化信息；空地观测互补有实际基础 | 本轮取得机构摘要及元数据，尚未核查全文流程；不能确认实时反馈，不能把光谱代理异常等同地下矿体或品位 |
| P31 Spatio-Spectral Exploration，[原文](https://ojs.aaai.org/index.php/AAAI/article/view/9673/9532)，Approach/Experiments | 用现场光谱改善遥感解释并选择采样位置，形成资源约束下的自适应勘查问题 | 实验用 AVIRIS 数据代理原位观测，结合 ASTER 做仿真；不是实地无人机—机器狗网络实验 |
| P32 Legged scientific exploration，[原文](https://arxiv.org/html/2307.10079)，Results/Autonomy/Communication | 多台 ANYmal 配置互补科学载荷并完成模拟地外勘查；科学家在任务中选择目标，机器人自主执行 | 5秒 RTT 在控制室链路人为注入，机器人间为低毫秒；未证明地球找矿通信普遍严重受限。失联时 Scientist 等待也与无法自主选新目标有关 |

因此，应拆开三条证据链：**观测互补 → 同次作业反馈有价值 → 网络限制损害该价值。** 当前第一条有直接应用依据，第二条有自适应勘查先例但尚未针对本项目确认，第三条尚缺本地业务及链路测量。LLM 不是上述任一条成立的必需条件。

暂定任务为“地表含铁矿物/矿化指示区的候选筛查与核查”，具体对象和地面判据仍待确定，不承诺发现经济矿体。应先确认实验室能够取得何种矿物/成分真值，再决定地面仪器；仅有 RGB 图片不自动构成矿物确认。

可检验的工作流为：无人机形成带位置与不确定性的候选点 → 地面机器人取得独立证据 → 更新候选区解释或核查顺序。**地面反馈是否还要改变无人机航线是额外假设**，不能为了制造双向通信而强制重飞。如果航空数据已覆盖全区且质量足够，反馈仅影响地面后续取样也可能是更合理的流程。

网络时效应来自“下一次不可轻易撤销的行动决策”：反馈若在设备离开候选区、确定下一个核查点或结束可用作业窗口之后才到达，可能错失调整机会。这是拟测的机会损失，不是已知事实；地质目标相对静态时，消息价值也不必随时间快速衰减。不要套用火灾式统一紧急期限。

首要排除项：离线流程已足够；空地时间尺度不匹配导致无人机早已返航；小型摘要在现有链路上毫无压力；主要误差来自校准/定位/矿物判别；只有强制传完整光谱数据才出现瓶颈。出现这些结果应降低或停止该网络选题，而非继续放大载荷。

## 3. 研究假设及证伪路径

所有假设均为本项目提出的待验证问题，排序表示测量优先级，不代表已经选定唯一论文方向。

| 假设 | 先例与具体证据边界 | 可证伪实验 | 创新风险 / 难度 |
|---|---|---|---|
| H1：依赖与版本信息在相同 QoS/龄期/队列下仍有额外预测价值 | P05 已提出标签；P15/P17 已利用时效/错误。缺少本项目业务下“条件额外价值”的证据 | 固定大小、期限、AoI、队列分布，加入真实/打乱/错误标签，比较有效交付和阻塞；若真实标签无稳定净收益则否定 | 高：可能只是 AoII 的实例；低至中 |
| H2：有界传播取消比源端 TTL 更节约多跳 airtime | P05 过时抑制、P16 时效传播；尚未核实其断续多跳撤销实现 | 比较 TTL、仅源取消、全网洪泛、本地有界 tombstone；计入控制重传。低取消率或长分区下净开销增加则限定适用域 | 中高：DTN/数据库已有类似机制；中 |
| H3：依赖阻塞反馈改善路由与队列联合决策 | P01 拓扑联合、P21 队列；P06 有等待释放负载。现有两者不等于已验证的依赖感知多跳策略 | 对比最短路、ETX、Backpressure、EDF及相同元数据增强基线；若只靠期限即可取得同等效果则否定 | 高：可能归约为截止时间路由；高 |
| H4：慢推理—中速路由—快速 MAC 的分离控制产生净协同增益 | P01/P05 有多层架构，缺少本项目局部状态与开销约束下的闭环结果 | 网络侧 N、Agent反馈 A 的 2×2 消融；统一信息预算，测交互项、延迟、控制占比；若协同不超过最佳单侧则否定 | 高：跨层本身不新；高 |
| H5：阶段/依赖状态帮助 OFDMA 分配，但增益仅在拥塞与准确标签下存在 | P02 保护、P05 loop-aware radio 已覆盖方向 | 同一 AP域对比 RR、PF、EDF、AoI/AoII、队列MaxWeight；标签年龄与误差扫参；若收益来自更多总资源则无效 | 高：调度特征增量可能很小；高 |
| H6：按消息存活时间约束缓存/中继移动能改善分区恢复 | P16 时效、P05 移动连续性；多跳缓存/移动组合待查 DTN 先例 | 外生轨迹先比存储携带转发、周期复制，再加入移动中继；扣除移动能耗与任务偏离，若净收益消失则否定 | 高：既有DTN覆盖多；很高 |

H1 首先检验信息是否有价值，H2 检验能否转成协议收益，H3–H6 检验跨层耦合。H1 被否定时，应保留普通 QoS/时效机制并重评其他假设，不能强行用复杂模型维持选题。

## 4. 判别场景与必要负对照

静态地图交换、无取消且低负载的消息流是负对照：预计普通可靠传输已足够。高频观测更新可能适合 latest-only/AoI，只有同一观测对应不同依赖分支时才可能需要额外结构。长分区场景中，再准确的语义标签也不能创造物理容量，应比较本地自主降级与延迟交付。

例如两条消息生成时间相同、长度相同、截止期相同，一条解除三台节点的等待，另一条属于已撤销分支。若网络仅使用前述 QoS 无法区分，依赖标签可能有价值；但网络获取标签和传播取消也需要 airtime。其**净**收益必须连同误判成本一起计量。

公平比较时所有算法共享可取得的元数据；另设剥夺元数据实验衡量信息贡献。集中 oracle 只能作为上界，不可与局部控制算法混为同等基线。固定轨迹回放用于隔离网络因素，真实闭环用于检查到达反馈改变未来需求，两种结果分别报告。

## 5. 统一系统候选而非单层收敛

接口定义对象 → 控制面传播局部状态 → 生命周期减少失效占用 → 路由选择服务路径 → MAC/PHY实际服务 → 到达/消费反馈更新请求。各模块共享 request/epoch/version，不要求共享完整模型状态。

保留三个整体验证配置：竞争式 Mesh 基线、弱中心 OFDMA 簇加多跳骨干、后续可编程无线实验。只有当模块交互产生超过单模块增益且开销可接受时，才主张跨层协同。若各模块可独立获得同等收益，应如实采用更简单实现。
