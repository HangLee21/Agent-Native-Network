# 需求执行链条、共同恢复与首轮规模实验

2026-10-26，M-008。研究核心继续是**多态自主设备团队的可扩展协作网络**。本阶段把[需求驱动研究链条](DEMAND_DRIVEN_RESEARCH_CHAIN.md)的运行时记录和规模入口落实为代码与30个完整任务回合：先确认团队增加后确实能执行任务，再测量这一执行过程产生的通信业务。

## 本轮完成了什么

新增[执行入口](../../simulation/heteromrta_demand_execution.py)复用固定任务策略、因果执行器和消息服务。每次信息取得均区分初始目录、本地事实和网络到达，再关联观测/mask咨询、决策和行动。初始目录、未知现场状态及未调用策略的分支分别记录。账本能够回答某次行动使用了哪一版已获信息；某条信息是否真正改善任务，还需后续反事实或干预对照。

公共执行条件新增错相启动、等待超时取消和本地冷却重试。启动U[0,1]，等待20+U[0,5]，空闲重试1+U[0,1]；随机量由实例seed、节点和本地事件次数确定，不读取网络条件。收到消息可更新缓存，但不能提前解除启动/冷却门控；行进与工作保持物理约束，取消意图通过同一消息服务发送。参数和30回合矩阵均在正式结果前冻结，见[验收口径](../../coordination/reviews/M-008-acceptance.md)。

新增[扩展目录生成器](../../simulation/heteromrta_scale_catalog.py)，以seed5/6各自的作者9节点/60任务主目录构造任务前缀，并复制完整9节点配置至18/36。两族共享9节点/15任务起点：固定总任务15，以及固定每节点5/3任务。能力、驻地、任务位置和任务ID均可配对。20次初始策略前向检查通过后，再运行10个完整任务回合。构造与单步证据见[规模入口报告](SCALE_ENTRY_PREFLIGHT.md)。

## 共同执行条件的配对结果

15任务、9节点、seed0–4，H=200。旧条件与恢复条件分别使用相同任务目录和权重，下面时间为模拟时间、包含返回驻地。

| 配对条件 | 旧执行规则 | 共同恢复规则 |
|---|---|---|
| instant，5实例 | 5/5全部完成并返回 | 5/5全部完成并返回 |
| delay0.5，5实例 | 3/5全部完成；seed2/3到H仍未完成任务 | 5/5全部完成并返回 |
| seed2，delay0.5 | 到H未完成 | 32.13返回 |
| seed3，delay0.5 | 到H未完成 | 54.09返回 |

关闭恢复时，10回合的物理事件、决策、消息、交付和视图证据共50组日志与旧归档完全一致。恢复组合改善了此前两个停滞实例；seed2没有实际触发等待取消，seed3有9次，因此当前只能归因于组合执行规则，尚未分离错相启动、冷却和取消各自作用。即时信息下的时间与通信成本有升有降，公共规则应统一用于后续各网络方法，而不单独包装为网络算法收益。

## 任务扩展实际产生了多少业务

新规模10回合均采用共同恢复与instant，全部完成任务并返回；没有墙时、事件预算截断或异常。面积固定为作者坐标范围。每格按seed5 / seed6给出，保留配对差异。

| 节点/任务 | 返回时间 | 广播条数 | 发布应用字节 |
|---|---|---|---|
| 9/15 | 21.68 / 25.07 | 143 / 174 | 44,942 / 54,500 |
| 18/15 | 15.24 / 17.21 | 171 / 196 | 54,181 / 61,903 |
| 36/15 | 14.14 / 14.51 | 197 / 211 | 62,820 / 67,089 |
| 18/30 | 22.76 / 24.62 | 328 / 344 | 103,646 / 108,594 |
| 36/60 | 23.54 / 23.41 | 650 / 677 | 206,054 / 214,269 |

**固定总任务：** 9→36节点后，两个实例返回时间分别缩短约35%和42%，发布字节增加约40%和23%。团队扩展带来执行收益，同时现有全体状态维护也增加了业务。这为研究任务收益与维护成本的折中提供了直接样本。

**固定每节点任务：** 节点与任务均增至4倍，返回时间大致保持在原水平，总发布字节分别增至4.58倍和3.93倍。每完成任务约3.00/3.63 kB增至3.43/3.57 kB，当前样本没有显示每任务发布成本随规模急剧增长。网络需要承载增长后的总体业务；是否触及资源边界，要由具体无线配置与实际竞争决定。

广播发布和接收副本分别计数。36节点/60任务的650/677条广播，对应22,750/23,695份接收副本；后者反映接收、状态缓存和处理负担，不能直接乘成单跳广播空口成本。本轮字节为实际序列化应用正文，不含无线帧头、重传、竞争与转发费用。

## 对科研主线的判断

这一阶段获得了从**任务扩展到业务生成**的可运行证据。当前结果支持继续研究：团队增大可以提高执行效率，但维护业务总量也随实际行动与任务增长；网络机制需要让这部分协作收益在共同资源条件下保留下来。

现阶段重点可落在两个可测的问题。第一，若旧状态排队时被新状态替代，是否能通过更新合并和发送触发减少无效维护，同时保留对当前决策有用的信息。第二，现场任务进度与节点意图对不同消费者的作用不同，能否联合决定更新时机、服务顺序与同步范围，在相同资源下改善完成比例与每任务成本。信息账本提供了设计和核验这些机制的接口；改进是否成立，由强基础对照和任务结果决定。

当前规模入口固定能力构成、免费静态目录，复制节点不增加平台类型。多态设备的观测正文、动态任务发现和作业区域扩展仍须按[应用合同](demand_20261026/WORKLOAD_CONTRACT.json)接入。新规模仅两种子，适合检验入口和提出机制问题，不足以估计普遍收益。

## 下一轮具体实验链条

1. **固定无线条件与物理时间映射。** 明确无线制式、频段/信道、帧开销、竞争及重传方式、节点几何与模拟时间对应关系。保持这些配置不随节点数人为改变，先用已记录业务检查成本，再回接任务执行闭环。当前作者时间单位尚未标定为秒，不能直接用应用字节除以该时间推实网bit/s。
2. **接入同一执行基础下的网络对照。** 周期错峰、事件更新、latest-state、FIFO和合理限速共用上述恢复规则。MOCHA同步与AutoCast任务价值机制沿已审计入口接入适配；原任务复现与本任务适配分别报告。先验证交付、mask、计费和执行一致，再扩大矩阵。
3. **分别扩需求和空间。** 复用本轮配对目录，增加独立种子，并分别运行固定总任务/固定每节点任务、固定区域加密/固定密度扩区域。观测正文从应用工作流单独加入，保存生产者、消费者、生成条件和数据大小来源。
4. **由失效机制选择改进。** 同时记录全部实例完成比例、失败/超时、makespan、每完成任务空口成本、控制开销、有效交付及尾时延。若出现维护排队、过时信息或协作关系切换损失，用逐项消融确定改进来自更新、队列、同步范围还是路由/MAC，再建立相应模型和理论分析。

这四步承接现有研究目标，具体运行配置与预算在下一任务卡中冻结。本轮已完成预定实现与验证，不自动开启后台实验。
