## 1. 运行时信息账本

新入口继承旧`CausalWorld`，使用`TrackedView`记录每次实际取得的信息。账本ID由`case_id + i序号`唯一标识，序号保留同一模拟时刻内的真实执行顺序；原物理事件ID保持不变。

| 记录 | 内容及连接 |
|---|---|
| `information_acquired` | `initial/local/network`来源、接收节点、版本、是否应用、原始事件或消息ID、正文hash |
| `information_consulted` | 一次观测/mask/分支构造的`demand_id`、`decision_id`、实际缓存版本及来源fact ID；尚无现场事实的任务记为unknown |
| `decision` | 连接consultation和原物理决策事件，记录是否实际调用原策略、选中动作 |
| `action_intent/action_result` | 连接决策与行动，区分真正出发和驻地无位移/空闲计时，保存route索引 |
| 本地计时/物理调度 | 记录到期时刻及本地参数；同步由行动产生的记录带`parent_action_id` |

`information_consulted`记录程序实际查询的缓存项。`demand_type`明确为`policy_consultation_not_minimum_task_requirement`，`causal_value`保留null；没有把读取次数称作有效消费或因果收益。当前观测仍遍历全体状态和任务，这是固定策略的输入要求。目录及初始空闲状态标为免费共同初始化条件；没有通过账本虚构发现、请求/回复或额外网络流量。

正文到达后才记录network取得；同一事实在现场先被观察、随后又通过网络收到，保留两次取得记录及`applied`结果，缓存来源只在实际应用时更新。unknown场景既不含远端真值，也不自动成为带截止时间的网络请求。全部记录可连接到消息正文、局部证据前缀、决策及行动。

30回合共3127次决策、6460条广播、107748份实际交付副本，信息账本133647条、108421304字节。信息账本是实验观测产物，不计入模拟网络业务；网络仍只传输执行器发布的状态和现场事件。账本字节也不是端侧协议开销。

## 2. 结果前固定的共同恢复规则

恢复模式采用下列全条件共用配置，未按结果修改：

- 启动错相：每节点在0至1模拟时间内启动。
- 等待重评估：等待20加0至5的抖动；超时仅释放仍在该次等待的节点。
- 空闲/恢复冷却：1加0至1的抖动，再由本地计时器唤醒。
- 抖动由`SHA256([seed, actor, event_kind, local_count])`生成，不使用网络条件名。
- startup和冷却未结束时，收到消息只更新缓存；`flush`和`decide`均检查门控，不能提前行动。行进和工作不中断。
- 取消等待以`mode=idle`的自身快照发布，经共同消息服务送达后远端才撤销活跃参与状态。保留机器人当前任务现场target，避免把现场误判为驻地。随后执行同一空闲冷却。

恢复关闭时仍使用startup0、wait200、idle1。所有回合H=200，CPU单线程、内部墙时70秒、外部90秒。C在结果前指出36节点/60任务的逐接收者账本可自然超过20000记录，M在首次任务运行前将所有条件的物理trace加service ledger上限统一设为100000；新增信息账本另计。最大实际计数27825，没有计算截断。时间保持作者模拟单位。

这一配置是共同执行基础的开发版本。各组件没有分别消融，效果解释为恢复组合的结果。
