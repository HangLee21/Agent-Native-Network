# 救灾任务中的实际通信需求与问题收敛

2026-10-22。当前目标：沿现场任务找到明确的信息接收者、后续动作与通信障碍，再据此构造仿真。

## 已找到的现场依据

**埃森住宅火灾后勘察：外部视角辅助地面机器人通过复杂区域。** DRZ部署报告§IV-C记载：二楼无法安排人员近距离观察，遂用无人机向地面机器人操作员提供外部实时视角。钢筋混凝土造成Wi-Fi间歇中断，点云等辅助功能受到影响；作者估计足够质量的Wi-Fi约占作业时间70%，备用专用无线链路更可靠。这里有完整的任务依赖：辅助观测→传输→操作员判断→机器人动作。出处：[P36 原文§IV-C](https://arxiv.org/html/2212.09354)。70%是该次作业估计，仿真将覆盖率作为扫描变量。

**灾情变化影响行动部署。** 同一报告§IV-B记载Erftstadt洪灾任务包含对坍塌边缘的实时观察和变化告警；跨日地形模型对比随后用于调整救援人员的安全位置。由此得到另一条明确链路：变化观测→态势更新→调整作业区域。研究中分别记录实时告警和批次建模的时序。出处：[P36 §IV-B、Fig.7](https://arxiv.org/html/2212.09354)。

**Amatrice震后勘察：异构平台的观测互补已经用于现场协作。** 项目数据说明记录了无人机给地面机器人操作员提供全局视角；另一处建筑地面机器人无法进入，空中平台进入内部，外部无人机给内部无人机驾驶员提供视觉反馈。可用数据入口包含ROS bag和任务说明。[TRADR项目原始记录](https://www.tradr-project.eu/resources/datasets/amatrice-datasets/)。

## 收敛为三个可检验问题

|任务问题|信息从哪里来、给谁用|影响的动作|首要测量量|
|---|---|---|---|
|跨机器人辅助观测的连续可用性|外部无人机的视角/局部几何→执行机器人或操作员|通过窄口、绕障、进入或退出结构|需要辅助的动作完成时间、辅助信息缺口、接触恢复开销|
|灾情变化到作业区域更新|侦察节点的变化观测→指挥端及相关执行节点|改派路线、调整重点区域、暂停当前区域作业|变化发现到相关节点收到更新的时间、旧任务持续执行时长|
|勘察结果驱动下一轮部署|先遣平台地图/入口观测→任务分配端和后续平台|选择入口、选择详细检查区域|有效信息到达至新任务开始的时间、重复勘察和移动代价|

**下一轮主任务选第一项：受限连通条件下，空地机器人协同勘察中的辅助观测交付与接触恢复。** 它同时对应用户已有空地设备、现场实际协作和具体通信故障。第二项作为后续任务扩展，第三项提供较慢时间尺度的对照。

## 与已完成搜索回报仿真的衔接

原仿真已经有移动图、可达关系、搜索、报告产生和回传。下一步增加“收到信息后做什么”：

1. 执行节点到达待检查位置，根据本地视野能否完成动作，选择本地执行、补充观测或请求辅助。只有任务几何要求额外视角时产生辅助需求。
2. 观测节点到达能看到该位置的观察点，生成带位置、时间和任务标识的观测；消息通过当前连接或存储携带到达接收者。
3. 接收者使用对应任务的有效观测开始动作；场景发生变化后，重新观测或采用本地保守执行方式。
4. 对比继续搜索、观测节点调整位置、执行节点恢复接触、固定中继四类行动的时间与任务完成量。

观测可用性与无线可达性分别建图：能看见执行点的地方未必有通信，通信好的地方也未必能提供所需视角。这个交集及其随机器人运动的变化，是下一轮首先测量的对象。

## 执行安排

下一完整实验阶段先实现独立的辅助观测事件模型：保留8张城市图，增加平台可达区域和观察点集合；将任务几何、链路和消息状态分别记录。对比本地独立执行、机会交付、请求触发接触、固定中继，以及接触途中顺路完成观察的基线。输出请求—观测—接收—动作完成全链路，主要比较作业完成时间与完成量，报告时效作为解释量。

平台通过性、观察点集合、观测有效期及局部保守执行成本属于这一阶段的模型输入，按预先固定范围扫描；现场文献用于确定任务关系。先检查“有无跨平台观测需求”“可达集与可视集重合程度”“接触恢复距离”三个变量，判断任务损失集中在哪里，再选理论模型。
