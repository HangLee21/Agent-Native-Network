# 实验设计：从原任务到协作网络机制

更新：2026-10-25。C-003；接手提交`dde4cff6aa4194ae5d1c10a8c2a4935c89a8ef05`。本文给出后续实施方案，本轮未运行新实验。现有结果来自[E1评估报告](../HETEROMRTA_REPRODUCTION.md)、[D通信接口报告](../NETWORK_BASELINE_RUNTIME.md)及[C-002审查](../../../coordination/reviews/C-002.md)。

首轮要检验的问题是：在同一任务执行器、同一物理网络和同一信息来源下，联合调整状态更新与消息服务，能否用更少的通信成本维持任务表现，或在同等通信资源下改善任务表现。节点规模、任务负载和网络动态分别改变，先定位有效条件，再讨论适用范围。

## 3. 从数据到可得信息

任务世界、通信执行器和每个节点的接收缓存分开。任务世界负责真实位置、能力和完成事件；节点只能读取自身可观测信息、预先公开的静态任务说明及已送达缓存。任务请求、状态正文、版本头部、确认和反馈都经过明确的传输过程。

初态可以统一提供任务静态描述和机器人已知初态，但必须把它列为共同假设；运行中新增或改变的信息按消息到达更新。更新触发只使用本地观测、已有缓存和实际反馈，不能读取未来链路、远端真实剩余能力或任务完成标志。

HeteroMRTA适配逐项覆盖`agent_observe`、任务剩余需求、同伴状态及mask，也检查Worker中直接访问全局字典的分支。物理世界可以依据真值判定组队是否真的可执行；拒绝、完成或冲突结果何时被某机器人获知，要遵守本地感知或反馈到达条件。否则即使观测被延迟，mask或失败反馈仍会成为即时信息通道。

网络几何还需单独重建：原环境在分配任务时把agent.location直接写为目的地，未来到达时间保存在arrival_time；这个位置字段不能直接作为无线测距坐标。保留原策略观测语义，按出发点、出发时刻、速度和到达时刻重建连续运动，再核对轨迹端点与任务时间。原env/task_env.py还可能以早于当前决策的previous_task.time_finish作为下一段出发时间；消息延迟后不能用新收到的信息决定过去动作。S1须检查决策、信息到达、出发、到达的因果次序。原条件回归保留原轨迹；若网络闭环触发回溯，建立另名的因果执行适配，并让所有通信方法及其即时信息参照共用该适配。原入口等价与因果适配验证分列，不把修正任务执行的收益算作网络收益。

原HeteroMRTA同一物理时刻的多个agent按既定次序决策，前一agent_step会立即改变下一agent看到的任务状态。因此零延迟等价模式必须保持相同同刻顺序，并在每次动作后排空零延迟交付再进入下一决策；正延迟消息只能在其实际到达后进入缓存。直接把全部agent决策合并成一批再统一发消息，属于事件语义变化，应与网络延迟分开核查。

验收包括三个可执行检查：零延迟全交付与原轨迹一致；阻断某条远端消息后，仅接收节点的对应字段保持旧值；延迟正文但先送达头部时，任务执行器不得提前使用正文内容。所有方法采用同一启动、事件排序和去重规则。

## 4. 对照和公平比较

| 角色 | 对照 | 比较时固定什么 |
|---|---|---|
| 任务策略参照 | 同一策略、同一规模的即时信息运行 | 实例、权重、动作/运动规则和任务截止；用于分离任务策略规模效应，不作最优解 |
| 基础网络 | 调参后的周期更新/错峰＋latest-state＋统一队列/限速 | 缓冲容量、消息类别、传输资源、广播和可靠事件语义；另加“提交时才取最新快照”的简单对照，分离JIT快照收益与价值评分收益 |
| 更新触发 | 状态变化阈值、年龄阈值，使用相同服务策略 | 只改变更新动作，沿相同预算比较任务表现 |
| 发送调度 | 同一更新流下的FIFO、类别优先/任务相关服务 | 只改变服务顺序；控制消息和正文都入队并计费 |
| 联合方法与消融 | 基础、只改更新、只改服务、同时改变二者的2×2对照 | 参数搜索次数与开发实例一致；报告交互项及其置信区间 |
| MOCHA | 原ROS2协议复现；共同执行器上的MOCHA机制适配 | 两类分别命名。适配保留头部比较、正文请求、latest-state和topic优先级；逐项列协议差异 |
| AutoCast | 原CARLA协同感知；兼容对象价值的发送机制适配 | 接收相关性和价值估计必须由相同可得信息生成；HeteroMRTA没有同类对象用途时不强行移植其奖励 |
| 后续候选 | CoSMO、MGF、C-MASS、CommHG、AC-DMTA | 先核对任务、信息和动作兼容，再进入同预算比较；C-MASS需要可定义的互补对象效用；CommHG/AC-DMTA的原任务及资源接口按[文献核查](LITERATURE_FRONTIER.md)细化 |

控制成本按实际编码字节测量。D-002已发现AutoCast Beacon可包含点云，且发送循环可能跨越100ms边界；复现保留这些行为，严格预算变体另名。不能给拟议方法省略元数据而让对照支付全部控制成本，也不能把默认直接缓存写入当作无线交付。

PHY、MAC、路由、发射功率、带宽、重传规则和接收范围先固定一致。理想服务模型可检查算法逻辑，结论以它的假设为限；无线结果须经过会产生排队/竞争/丢失的共同执行器。后续更换MAC或路由时成为单独实验因子。

## 5. 指标与原始事件

令每个回合有J个要求完成的任务，统一任务预算H。成功要求J个任务完成且全部应返回机器人在H前回站。有限任务实验主结果同时给出以下量。

| 指标 | 定义与分母 | 必须保存的原始证据 |
|---|---|---|
| 完成比例、成功率 | `completed(H)/J`；成功回合数/全部尝试数 | 任务完成时间、返回时间、未完成原因、run状态；崩溃且无有效终态记unknown并单列，不能删掉尝试 |
| 返回makespan | 仅成功回合的`T_return`，配合成功率及分布；两策略共同成功子集的配对差另报其数量 | 最后任务完成时间、每机器人回站时间、H；不把条件成功均值单独用于方法排名 |
| 包含失败的时间分数 | 任务未完成或未回站取H，成功取`T_return`；称“截断预算分数”，与完成比例一起报告 | 成功/失败标签及H；纯软件错误不伪装任务超时，另报unknown并作敏感性处理 |
| 空口发送成本/完成任务 | 全部实际发送尝试占用时间总和除完成任务数；含控制、正文、重传与可归属的MAC开销 | 发送节点、消息类、长度、MCS、开始/结束时间、重传、ACK；零完成时比值NA，仍报总成本和零完成数 |
| 信道忙时与空间复用 | 每冲突域的占用时间并集/H；另列节点发送时间之和 | 冲突域、并发发送与忙时记录；碰撞的两个发送分别计入发送负载，但忙时并集不重复相加 |
| 控制开销 | 控制发送字节/时间及其占总发送比例，绝对量并列 | 版本头、请求、确认、邻居发现、调度协调等消息类别；应用层字节与链路层字节分列 |
| 有效及时交付 | 给定信息需求在消费窗口前获得可用版本的比例；需求按“信息项、接收者、窗口”定义 | 需求产生/截止、版本、正文到达和实际消费；广播发送成本计一次，各接收者是否满足需求分别计 |
| 尾时延与未交付 | 已交付消息的产生至到达P50/P95/P99及样本数，另报未交付/过期/被覆盖数量 | 产生、入队、开始发送、到达、过期、覆盖时间；不能靠丢弃慢消息获得低P95 |
| 决策信息质量 | 消费时版本龄期、与即时影子决策的动作差异、可追溯的重复投入/等待 | 实际缓存、mask、决策时刻及影子输入；动作差异本身不等于错误 |
| 算法代价 | 单节点决策时间/内存、调度控制消息和随节点/队列规模的增长 | 单独计时、线程/硬件、队列长度；训练、初始化、日志开销分列 |

有限任务的网络积分区间统一记录为`[0,min(T_return,H)]`，未成功回合截至H；同时报告区间长度和总发送成本。持续业务实验另用共同固定H，避免运行越久自然积累越多消息造成解释混乱。原HeteroMRTA的时间单位按原代码报告；接无线执行器前将位置、速度和时间明确换算成米与秒，不能直接把原数值当作实机秒数。

及时交付率尤其容易受分母影响：方法改变更新频率后，不能把自身产生的消息数直接当共同需求数。固定消息回放阶段采用相同外生需求轨迹；闭环阶段另外记录每次实际决策的消费需求、满足率和需求总数，不把两者合成一个公平性排名。真实交付收益由任务完成结果验证。

E1的即时/计费格需要显式信息诊断通道和共同计费负载；延迟/免费格需要冻结延迟核。固定回放先校准这些干预，闭环运行报告各干预总效应及交互，不将它们称为唯一的机制损失分解。

2×2交互项用于检查组合效应，但联合方案更好并不自动意味着交互显著。即使交互接近零，若同成本表现或实现复杂度有优势，仍可据实评价；若优势在公平调参后消失，就调整机制或研究条件。

## 7. 规模与动态的分离

规模候选为`N={9,18,36,72}`，保持3类机器人及能力组成比例；每个规模先验证策略输入维度、能力可行性和即时信息表现。超出已验证的规模均属计划，不能把输入兼容或学习泛化预设为通过。

面积和任务量做四个独立分组：固定面积A0/固定密度`A=A0*N/9`，分别配固定总任务20/固定每节点任务`J=20*N/9`。保持任务能力与作业时长分布一致；扩区域时路径长度增加是实验的一部分，另报距离与即时信息表现。主实验使用固定物理资源；增加资源的对照单列，展示网络扩容能否补偿负载增长。固定频谱和功率并不保证扩区域后的全网总服务量不变：固定密度扩区域允许空间复用随几何自然增加，按共同干扰图和每冲突域统计；单冲突域与多冲突域规模曲线分列。

动态不能只写成一个“强度”参数。连接过程先固定平均可用率，改变开关切换速度与连续断联时长；任务过程先固定节点和网络，改变任务到达、取消或协作需求变化率。HeteroMRTA原静态任务与这些新增动态任务分别命名。有限批次仍用makespan，持续到达业务改报窗口完成量/到达量和未完成积压，不强求无限业务的最终makespan。

移动由任务策略决定时，改通信会反过来改变路径和拓扑。机制归因先用固定轨迹/接触回放保持网络输入一致，再用闭环移动运行验证总效应。闭环各方法共享地图、初态和外生随机场，允许轨迹自然分化；不要强行复用依赖旧路径的包级成败序列。

## 8. 种子、调参与阶段预算

后续建议先以已存种子0–4做接口回归；它们已用于观察和诊断，不再充当盲测。开发集建议10个新任务种子，每个配3个独立网络过程种子；锁定测试集建议30个未见任务种子，各配3个网络种子。具体编号、生成器版本和实例哈希在运行前写配置。两任务规模使用相同种子编号并不表示同一个任务实例，配对键必须包含规模和实例哈希。

每个方法最多20组超参数配置，在相同开发实例和服务预算上选择；选择规则预先固定，例如在成功率达到共同门槛的配置中最小化空口成本，若全部未达门槛则先最大化成功率再比较时间分数。报告全部开发曲线，保留调参较充分的周期/latest-state强基线。不同复杂度的搜索空间可异，但评估预算一致，必要时增加统一预算敏感性。

任务实例、网络过程、算法内部随机流分别播种。所有方法配对同实例与外生随机过程；事件顺序变化不应挪用同一全局RNG导致后续随机场错位。统计以任务实例为独立单元：先在实例内汇总网络种子，再对实例重采样得到配对差区间；包数不能当作独立实验样本数。成功率与完成比例、配对差分布同时给出，探索性多条件结果与预注册主比较分列。

顺序按E0→E1→E2→E3推进。只有零延迟等价和消息可得性检查通过、已有固定冻结策略的结果，才扩大E4/E5；原协议与原任务E6a可作为独立环境恢复线并行推进。每批任务设实例数、墙钟上限、输出目录和停止条件；本文件不授权自动启动无限队列。

## 9. 产物和接受标准

每次运行保存任务实例、配置、源码/权重哈希、系统版本、三个随机流、全部尝试状态、任务轨迹和消息事件。消息事件至少包括`message_id,source,destination_or_group,class,version,bytes,generated_at,enqueued_at,tx_start,tx_end,arrived_at,consumed_at,drop_or_replace_reason`；广播接收记录与发送记录用同一消息ID关联，重传另带attempt编号。

输出沿用`simulation/outputs/<任务ID>/<run-id>/`，只用新目录。阶段采纳后归档至`simulation/results/<日期>-<任务ID>-<主题>/`，同时保存分析脚本与图表的输入路径。最终图表必须能回到逐回合/逐消息证据；NA、unknown、timeout和实现错误保留独立含义。

下一阶段的最小可交付物是E0等价记录、完整消息可见性检查、一个固定规模下的E1延迟曲线，以及清楚标明原Greedy行为的任务对照。随后用E2锁定工作区间、用E3判断联合控制是否形成可重复的性能—通信成本改善。
