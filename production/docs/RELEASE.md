# 发布同步与回滚

由 M 选择冻结的研发提交，按 `production/DEPLOYMENT_CONTRACT.md` 制作发布清单和包：记录 source commit、协议/配置 schema、服务版本与文件来源、目标镜像 SHA-256、build ID、偏移与分区布局、验证状态和上一个回滚发布。先完成受影响的离线检查；标记 candidate。之后用户通知设备连接时，由 H 核验目标身份、版本与板端功能，实际通过后才记 validated。

生产程序不得自动抓取移动的研发 HEAD 并刷板。保留上一个已验证发布与其 manifest、镜像及验证记录；回退必须显式选定已验证版本，核分区和适配性，默认 app-only 并保留 NVS。分区、bootloader 迁移或全片擦除需要另行明确流程，不能作为自动回滚。回滚前备份适用配置，日志说明每块板的身份、版本和读回；如果分区或数字 ID 命令无法核验则停止。

现阶段包/入口和板端命令仍在开发，不能把模板或离线测试记成已完成设备发布。服务端通过 `/api/v1/fleet` 向 UI 提供所选 fleet 与注册表的合并结果，且报文身份仍是 MAC/boot；界面自动读取标签不能替代设备写入及读回。
