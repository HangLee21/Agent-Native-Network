# Production deployment contract v1

Branch: codex/production-deployment. Development remains on codex/baseline-reproduction-20261023. Live task cards reside at D:/Multi-Agent Network/coordination/tasks, not this worktree's historical copies.

Root entry points: FLASH_NODES.cmd (H), START_STUDIO.cmd (E2). Both support offline --dry-run / --self-test and explicit --config PATH / --release PATH. No hardware operations are performed during today's implementation tests.

Recovery requirement (2026-11-14): normal startup, transient disconnection, stale locks and failed owned child services must recover automatically, with bounded retries/backoff and visible progress. Operator recovery is replug/power-cycle or double-clicking the same entry point; manual lock deletion, COM selection, JSON edits and NVS clearing are not a delivery workflow. Validate lock ownership/liveness and PID reuse; never terminate unrelated processes. Preserve node identity, provisioning and command-execution uncertainty across restarts. Last-known-good configuration recovery requires validated copies, not guessed defaults. Interrupted app flashing may require the same launcher to recover through ROM with verified identity/layout/image; power cycling alone cannot restore a damaged app. A/B firmware rollback requires a separate explicit partition migration proposal, never a silent full erase. Acceptance includes process termination, dropped callbacks, unplug/replug models, config-write interruption and repeated recovery, followed by hardware power-cycle verification when boards are connected. Live role assignments and detailed checks are in main M-039.

D owns production/config/fleet.example.json. Schema version 1: schema_version, nodes (array of {node_id: positive integer, mac: normalized MAC}), gateway ({eui, candidate_hosts, udp_port:1680}), services ({topology_port:8780, studio_port:8794}), release_manifest (relative path). No credentials. Local user config defaults to production/local/fleet.json; absent config may use example for known MAC mapping but must not guess new board identities. Duplicate IDs/MACs are rejected, COM numbers are ephemeral. Display IDs are not routing identities. Unknown boards remain UNSET until provisioned. A–E maps to1–5 as defined in M-039.

H owns production/release/manifest.example.json and package validation. Manifest fields: schema_version, release_id, status(candidate|validated), source_commit, protocol_version, config_schema_version, firmware ({path,sha256,build_id,chip,flash_offset,partition_layout_id}), services ({gateway_module,studio_module}), rollback_release, validation_evidence. Unknown values null; null required flash identity/hash must fail flashing, not be guessed. Service paths resolve inside the selected frozen release. Package creation must not pull/flash moving research HEAD automatically. Bootloader/partition changes require explicit migration, no default full erase.

Runtime and logs: production/local/ is untracked. Scripts report requested/succeeded/failed steps, identified node/MAC, selected firmware version, and exact logs. TX callback / gateway TX_ACK is not destination receipt. Gateway discovery is bounded and configurable; verify the reported EUI and current valid packets; don't silently change network settings. If unavailable, offer an explicit offline UI state without historical replay.

2026-11-14 integration fields: services.gateway_args and services.studio_args are arrays of command-line argument strings, passed without shell interpolation. Top-level service_files_sha256 maps release-relative service file paths to SHA-256 values. firmware.partition_table_path resolves inside the release and firmware.partition_table_sha256 covers the complete 4096-byte padded partition-table image, checked against the board read before app-only flashing. H owns manifest generation/validation; E2 consumes these exact fields. Unknown required values remain null and block the affected operation with a clear reason; they must not be synthesized. Existing incomplete examples are not usable releases. New-board group/channel/autostart provisioning must use explicit deployment configuration; absence requires delivery-personnel action, not guessed radio settings.

M coordinates source synchronization: freeze selected development commit and tests, assemble candidate with hashes and source map, check affected offline tests, push production candidate, H validates connected devices after user notification, then record validated release plus rollback. Raw research outputs and credentials are not copied by default. Until actual release artifacts exist, entrypoints must say unavailable rather than claim ready.

Node registry integration: H is the sole writer of production/local/registry.json, using atomic replacement and schema_version=1 with nodes[{mac,node_id}]. E2 reads it alongside the selected fleet, normalizes MACs and validates both inputs before merging. An identical MAC/ID pair across the two inputs is allowed; conflicting assignments, invalid values or duplicated identities within an input are rejected visibly, never silently overwritten. Missing registry means use the valid fleet alone; malformed registry is an error, not a fallback. Studio /api/v1/fleet exposes only the validated merged schema_version/nodes mapping. Registry reservations establish display assignments only, not successful board provisioning or online status; those require device readback/telemetry. Refresh after successful atomic updates without overwriting the registry, and clear configuration-health errors only after a valid reload. H/E2 tests must cover IDs above26, conflicting assignments and a reserved but unsuccessfully provisioned board.
