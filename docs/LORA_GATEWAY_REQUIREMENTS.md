# 八通道 LoRa 网关采购规格（待采购）

目的：把「8 路上行 + 1 路下行」从**规划**变成**可用硬件**。
现状：板载单颗 LR1121，收发互斥、单天线组，**8 路并行接收不可能**（`lora_ref/port.c` 已核实）。
在下单前，以下参数必须逐项确认，否则买回来仍然只能用 1 路。

## 1 必须满足（硬性）

| # | 要求 | 为什么 |
|---|---|---|
| 1 | **≥8 个独立 LoRa 解调器**，可**同时**接收 8 个不同频点 | 这是整个架构的前提；"8 信道"若指时分复用则等于没有 |
| 2 | 8 路上行可配置在 **470 MHz 附近**（410–493 MHz） | 与现有节点一致；频点需软件可设 |
| 3 | 至少 **1 路独立下行发射**，可与上行同时工作（或明确给出切换开销） | LRC1 命令与调度 beacon |
| 4 | 支持 **SF7–SF12 / BW125–500 / CR4-5**，前导与 sync word 可配 | 与现有 LRN1 参数对齐（SF7/BW125/CR4-5/sync 18/preamble 8） |
| 5 | 单帧 **≥255 B** 载荷 | LRN2 分片上限按 200 B 设计，需留余量 |
| 6 | 时间戳精度 **≤1 ms**，且 8 路共用同一时基 | 调度与 AoI 计算依赖它 |
| 7 | 主机接口：**USB-CDC 或千兆网口**，提供**每帧元数据**（频点、RSSI、SNR、到达时刻、CRC 状态） | 没有每帧元数据就无法做拓扑与 AoI |
| 8 | 连续工作 24 h 不重启、不丢流 | 现场观测网关 |

## 2 强烈建议

| # | 建议 | 理由 |
|---|---|---|
| 9 | 片上或主机侧 **时间同步（PPS/PTP）** | 跨节点比较到达时刻 |
| 10 | 硬件 **LBT/CAD**（先听后发） | 下行与前导冲突规避 |
| 11 | 每路独立 **RSSI/SNR 校准** | 跨信道比较需要 |
| 12 | 开源或可审计的固件 / 明确的串口协议文档 | 我们要写解析器，不能靠猜 |
| 13 | 支持 **raw 模式**（只上报原始字节 + 元数据） | 解码放在主机侧，便于升级 |

## 3 明确可接受 / 不可接受

| 说法 | 判定 |
|---|---|
| "8 通道" = 8 路并行解调 | ✅ 需要的 |
| "8 通道" = 8 个可配置频点，但一次只能收 1 个 | ❌ 等价于现状 |
| "8 通道" = 网关轮询 8 个信道 | ❌ 会丢帧，不满足 |
| 多片 SX1262 + 8 天线 + MCU 汇聚 | ✅ 可接受 |
| 单 SX1302/SX1303 类集中器（8 信道） | ✅ 可接受，但需确认频段为 470 MHz 版本 |

## 4 交付时必须一并提供

1. 串口/网络协议文档（帧格式、元数据字段、错误码）。
2. 每路频点与带宽的配置接口（命令行或配置文��均可）。
3. 一份 **8 路同时收发的实测演示**（不是规格书），最好带抓包日志。
4. 射频指标：灵敏度、邻道抑制、最大输入电平（有则更好）。

## 5 到货后的接入计划（对应本仓库）

```
gateway(8ch) ──USB/网口──► tools/mobile_gateway/lora_reader.py 的"来源适配器"
                              │  （当前只认 lora.ref.v1 JSON 信封）
                              ▼
                       /api/v1/lora/topology  → Studio 页面
```

- 适配器为新增模块，**不改现有 `lora_reader` 的默认行为**（保持单 LR1121 可用）。
- 适配器需输出与现有等价的结构：`{gateway_id, gateway_boot, report:{observer_id,…neighbors[]}, lora:{rssi_dbm,snr_db,frequency_hz}}`。
- 8 路带来的**新信息**是每帧的**信道号**——拓扑页面可直接展示每信道占用率与冲突率。

## 6 到货前的过渡方案（已可用）

- 单信道 **TDMA**：`T ≥ N·(τ+guard) + τ_beacon`，30 节点约 **10.2 s** 完成一轮快照。
- 仿真已验证：ALOHA 0.67 → 调度 0.95（`simulation/outputs/DENSE-SIM/20261112-06-gateway-scheduled`）。
- 因此**不需要等硬件**就能开始 LRN2/LRC1 的帧格式与调度逻辑开发，只是容量按单信道验收。
