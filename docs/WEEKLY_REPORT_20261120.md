# 一、内容总结

## 1. 网关：三代设备全部打通，最终换成八通道

| 阶段 | 设备 | 结果 |
|---|---|---|
| 起点 | RisingHF RHF2S008（树莓派 + Raspbian 8） | 识别、提取参数、打通 LRN1 接收 |
| 过渡 | 同上，接入前端 | 前端能显示真实拓扑，但只有单通道 |
| 现在 | **亿佰特 E870-L470LG11-S** | **端到端打通，八通道** |

**新网关的关键参数**（逆向其 Web 接口得到，官方文档未提供）：

```
型号   E870-L470LG11-S      固件 FW-9252-0-10
MAC    a4:f0:0f:e5:7b:83    SN S5203996S
射频   radio0 470.6 MHz / radio1 471.4 MHz
       → 八信道 470.3 / 470.5 / 470.7 / 470.9 / 471.1 / 471.3 / 471.5 / 471.7
实际   ch1 = 470.5 MHz，与五块节点一致，SF7 BW125
网络   静态 192.168.137.11/24，转发到 192.168.137.10:1680
```

**踩到的两个坑**（都写进文档了）：
1. 只改配置不提交 `parameter send completed`，**重启后会回滚**；
2. 网页重启指令有效，但**恢复转发要 90 秒以上**，观察窗口太短会误判"指令无效"。

## 2. 前端：两条线合并，并修掉三个"看起来正常"的缺陷

合并了 deploy 分支的网关源解耦与布局能力，和本分支的数字标签、网关身份自适应。
现在**换网关不用改代码**——网关身份从数据包头里学，旧网关依然可用。

同时修掉三个会静默出错的显示缺陷：

| 缺陷 | 症状 | 根因 |
|---|---|---|
| 节点年龄用全局时间 | **停机的节点永远显示"最新"** | `now - last_rx` 里的 last_rx 是所有帧共用的 |
| `state` 字段类型不匹配 | **"双方互证""失效"从未出现过** | 解码器约定字符串，我输出的是数字 |
| 手写标签冒充设备编号 | 在线的板子被标成别人的编号 | 标签表里有从未被设备验证的映射 |

修复后实测：绿色「双方互证」出现 4 次、红色「采样时已失效」出现 5 次，
未上电的板子会如实显示「采样已失效」。

## 3. 固件与协议：节点编号进帧，新增状态块

- **LRN1 组帧容量修复**：208 字节上限，行选择改为「非双向优先 + 游标轮转」，
  邻居再多也不会写越界，且每个邻居最终都会被报一次。
- **节点编号写入帧头第 35 字节**：地面端从空口直接解出编号，
  **不再依赖任何预置名单**。
- **新增状态块 24 字节**：复位原因、空闲内存等，**GPS 块 20 字节预留**。
- **邻居淘汰**：静默 10 分钟的邻居移出表，避免"死邻居"长期占用发送名额。
- 五台节点固件统一为 `0c116de32812`。

## 4. 机群：五台树莓派按名管理，一条命令刷全部


- 全部通过 Tailscale 按**设备名**访问，IP 变了也不影响；
- 远程刷写流程：预检 → 推送镜像 → 刷写 → **校验 build_id** → 失败自动回滚；
- **esptool 统一到 5.6.0**（4.x 与 5.x 的 CLI 拼写完全不同，混装必然有一台刷不上）。

## 5. 做卡：一次写卡，插电自配置

以前每台 Pi 都要插网线、手工配 WiFi 和 Tailscale。现在写一张卡，插电自动完成。
过程中定位到三个根因，每一个都表现为"什么都没发生"：

| 根因 | 现象 |
|---|---|
| cloud-init 的实例身份由 `cmdline.txt` 的 `i=` 决定，优先于 `meta-data` | 改了配置也不执行 |
| 802.1X 网络被 Imager 写成普通密码型 | WiFi 永远认证不上 |
| **树莓派没有 RTC，首启时钟落后于仓库签名时间** | apt 拒绝验证 → Tailscale 装不上 |

第三条是最后一张卡（05）失败的真正原因，日志里写着 `Not live until ...`。

## 6. 网络管理：一个网口三种用途

```
campus   正常上网（默认）
lab      接 LoRa 网关，192.168.137.10/24，故意不给默认路由
pi       接新树莓派，纯链路本地
```

lab 模式**不带默认路由和 DNS**，所以接网关时不影响正常上网。

## 7. 实验设计：稳定性测试有了判据

产出 `LINK_STABILITY_TEST_DESIGN.md`：指标（RDR、AoI、重启原因、网格完整度）、
**跑之前定死的判据**（RDR ≥ 99%、零未解释重启、AoI P95 ≤ 15 s）、
八个单因子场景（基线 / 距离扫描 / 断电 / 网关静默 / 24 小时长稳 / 同时重启 / 2.4G 干扰 / Pi 满载）。

## 8. 并行推进的两条线

- **仿真**：30 节点高速移动、MANET 基线对比、LET 链路预测模块。


## 9. 补充：下行通道与信道字段（11-20 下午）

**下行（网关 → 节点）已接入**：协议层（LRC2/LRA2）与节点侧原本就已实现，
本次把它接进了当前运行的接收服务：

- 复用同一 UDP socket，网关地址从它发来的数据里学习，回发 PULL_RESP(txpk)
- 新增 POST /api/v1/lora/command 与 GET /api/v1/lora/commands
- 命令带目标 boot、**报告锚点**、8 字节命令 ID、TTL（1–60 秒）；
  节点对重复命令重发缓存回执，**幂等**
- 收到节点回执（LRA2）后按命令 ID 匹配，状态更新为 executed / rejected

当前支持两种操作：echo（回环验证）与 status（查询）。

**上行新增信道字段**：状态块第 19 字节改为上报**节点自身工作的 WiFi 信道**。
原先邻居行里也有信道字段，但依赖驱动上报，实测一直为空；改报本节点信道后，
可以直接解释为什么两块板互相收不到。

> 我们先后用了三代设备，最后换成亿佰特的八通道网关。

> **第二件事是前端。**
> 我们把两条开发线合并了，现在换网关不需要改代码——网关身份是从数据里学的，不是写死的。
