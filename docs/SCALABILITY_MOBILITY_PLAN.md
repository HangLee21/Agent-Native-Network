# 面向高速移动无人机集群的可扩展自组网：总体计划

版本：2026-11-13。适用对象：`firmware/mid_baseline/field_agent`（ESP32-S3 + LR1121）。
本文件是总纲，具体推导见同目录其余六份文档。

## 1 目标

把现有 **5 节点、静态为主、单跳为主的通信原型**，推进到 **20–30+ 节点、高速移动、
多跳、全局状态感知、双向可管** 的异构自组网。

两个维度必须同时成立，缺一不可：

- **Scalability**：N 从 5 → 10 → 20 → 30+，同时约束邻居表、路由表、泛洪、跳数、
  无线竞争、队列、内存与 LoRa 通道容量。
- **Mobility**：把静态图 `G=(V,E)` 扩展为 `G(t)=(V,E(t))`，覆盖相对运动、编队分裂/汇合、
  链路快速失效，并建立"预测—验证—再控制"的闭环。

## 2 必须继承的既有结论（不得推翻）

| # | 结论 | 出处 |
|---|---|---|
| 1 | 固定 RREQ 转发上限（8 帧）使 PDR 0.909→0.642，**已否定** | `DENSE-SIM/20261112-05/06` |
| 2 | Gratuitous RREP 降 RREQ 32% 但 PDR 0.911→0.836，**暂不采用** | 同上 |
| 3 | RREQ 三次广播重传对长链 0.054→0.062，**无实质收益** | `20261112-08-hop-limit` |
| 4 | 长链瓶颈是**发现时延 vs 250 ms 待发窗口**与逐跳损耗累积 | 同上 |
| 5 | 单靠扩大 TTL 不能解决长链 | 同上 |
| 6 | 交付判据只有 `rx_local` + 载荷字节一致 | `ALGORITHM.md` §5 |

## 3 四层逻辑架构

```
┌ 第 4 层 全局遥测与协调 ─────────────────────────────────────────────┐
│ LoRa LRN2 上行遥测 / LRC1 下行控制 / 全局拓扑 / AoI / 时隙调度      │
│ 时间尺度：秒级。慢速、可丢、可重发。                                  │
└───────────────────────────▲──────────────────────────────────────────┘
                            │ 汇总（有年龄，非实时）
┌ 第 3 层 路由与数据转发 ────┴──────────────────────────────────────────┐
│ 源路由 RREQ/RREP/RERR、主备路径、预热、局部修复、DATA、队列调度       │
│ 时间尺度：百毫秒级。本地决策，不依赖网关。                            │
└───────────────────────────▲──────────────────────────────────────────┘
                            │ 邻居状态 + 链路质量 + 移动状态
┌ 第 2 层 局部网络状态管理 ──┴──────────────────────────────────────────┐
│ ND 三态、RSSI/PDR/ETX、LET 预测、链路风险 GOOD/DEGRADING/AT_RISK      │
│ 时间尺度：亚秒到秒级。纯本地。                                        │
└───────────────────────────▲──────────────────────────────────────────┘
                            │ 位置/速度/航向/精度/时效
┌ 第 1 层 移动状态感知 ──────┴──────────────────────────────────────────┐
│ GNSS / 飞控输入、相对位置与相对速度、位置/速度精度、AoI               │
└──────────────────────────────────────────────────────────────────────┘
```

**两种控制时间尺度必须分离**：本地快速控制（邻居维护、路由修复、业务转发）由节点自主完成；
全局慢速控制（网关汇总、策略下发）只能作为**建议**输入，且必须携带信息年龄。
**网关不得成为业务数据的必经中继**（否则是单点瓶颈与单点失效）。

## 4 分阶段路线

| 阶段 | 内容 | 交付判据 | 风险 |
|---|---|---|---|
| **P0** 基线核查 | 代码级审计、硬件能力核实、文档差异清单 | 本目录 `IMPLEMENTATION_STATUS.md` 逐项标状态 | 低 |
| **P1** 移动状态与 LET（本轮） | Mobility State、相对运动、LET、风险状态、Shadow 日志与评估工具 | 主机测试通过 + 固件可编译；**不接路由** | 低 |
| **P2** 自适应 ND | Hello 周期随相对速度/链路风险调整；ND01 格式不变 | 同负载下 RREQ 与丢包下降，PDR 不劣于基线 | 中 |
| **P3** LET 感知选路 | RREP 候选打分引入 ETX/LET；主备路径 | 对照实验显著优于最短路径 | 中 |
| **P4** 预热与局部修复 | 预测失效前预热、中继局部修复 | 切换中断时间下降，控制开销不失控 | 中高 |
| **P5** LRN2/LRC1 | 全局遥测与下行控制、超帧调度 | 上报送达率、命令执行率、AoI 达标 | 高（见 §6） |

每一阶段都必须：**独立开关 + 可回退 + 消融对照**。

## 5 主要技术瓶颈（按优先级）

| 优先级 | 瓶颈 | 现状证据 | 处理阶段 |
|---|---|---|---|
| P0 | **ESP-NOW 注册 peer 上限 20** | IDF `ESP_NOW_MAX_TOTAL_PEER_NUM=20`；固件每发送前 `esp_now_add_peer` | P2（表管理策略） |
| P0 | **LR1121 单收发器，8 信道并行不可能** | `port.c` `set_rx`/`set_tx` 互斥，rfswitch 单组 | P5（改硬件或改架构） |
| P1 | flash 配置 2 MB 而器件 4 MB，app 仅 1 MiB | `sdkconfig.defaults` 与 `esptool flash_id` 实测 | P1（改分区） |
| P1 | 邻居/路由表 32 对 30 节点足够，但**去重与待发**在长链下不足 | `SR_SEEN 128 / SR_PENDING 16` | P2 |
| P2 | RREQ 泛洪在密集 30 节点仍达 300+/s | 仿真 `20261112-07` | P2/P3 |
| P2 | 待发窗口 250 ms < 远距离发现时延 | `20261112-08` | P2（可配置） |
| P3 | 无相对运动信息，无法预测链路寿命 | 代码审计：`mt_position` 只有位置 | **P1（本轮）** |

## 6 硬件未确认事项（不得假设）

1. **8 路上行 + 1 路下行**：当前板卡只有一颗 LR1121，**物理上无法并行 8 路接收**。
   若确需 8 信道，必须更换网关硬件（多片 SX126x/LR1121 或专用 8 通道集中器）。
2. GNSS / 飞控接口：固件只有 `position_set` 注入命令与 `MT01` 单跳位置广播，
   **没有真实 GNSS 驱动、没有速度/航向/加速度来源**。
3. 真实飞行轨迹：仓库内无实测轨迹，所有移动场景均为合成轨迹。

## 7 本轮边界

允许：审计、规划、Mobility State 抽象实现、LET 计算、Shadow 日志与评估工具、编译验证。
禁止：修改 ND01/SR01/LRN1 线上格式、改路由决策、动自启动与基础通信。
