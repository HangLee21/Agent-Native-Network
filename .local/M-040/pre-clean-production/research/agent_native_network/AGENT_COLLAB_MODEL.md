# Agent-Native分布式协作网络：初步模型 V0

2026-10-23更新入口：[具身网络扩展性的最小数学骨架](RESEARCH_GAPS.md#scalability-core)。该扩展显式区分协作状态与任务数据、信息缓存与真实状态、通信图与任务图。以下V0保留为已运行的4节点执行器说明。

2026-10-22。目标是支撑端侧智能体协作的去中心化无线网络。以救灾辅助观测为任务，先固定运动与感知能力，测量通信对协作动作的影响。

## 系统与局部状态

节点集合V包含执行节点、观测节点和可承担转发的节点。节点i的状态为 x_i=(本地观测、任务状态、已接收信息、邻居状态、消息缓存)。状态更新只使用本地事件与已送达消息。环境真值仅由模拟器用于产生观测和评分。

任务k有产生时间r_k、执行节点、能力需求和动作代价。执行端可独立执行，或请求另一端的辅助能力。协作链为请求送达→观测排队→观测完成→结果送达→动作完成。每个阶段保留时间戳。规则智能体提供首个可复现执行器，随后以同一接口接入端侧模型的任务判断。

消息m=(id, task_id, source, destination, kind, created, size)。首轮kind为request/result/map。节点收到完整request后才安排观测，收到对应result后才推进任务。后续任务变化自然产生版本、改派与取消事件，再扩充消息类型。

## 网络与控制变量

G(t)表示实际可用链路，C(t)表示共享容量预算。每节点缓存Q_i，调度只读本地消息类型、大小和队列年龄。逐跳缓存转发，未来链路状态只存在于环境，不提供给节点决策。首轮静态目的路径使路由因素固定；传输次序与推送方式为实验变量。

容量约束为每步所有链路发送字节之和≤C(t)；不可达链路发送量为0。消息必须完整到达下一节点才能转发。首轮提供可靠暂停/恢复服务，之后增加帧损失、确认与重传开销。

## 任务目标与归因

第一目标为给定任务集的平均完成时间 L=Σ(c_k−r_k)/K，并同时报告独立/合作完成量、回退比例、通信字节。有限预算时另记未完成任务。不给任务人为设置死亡概率。

协作任务时延分为请求网络等待、辅助端排队、观测服务、结果网络等待和末端动作；独立执行记录本地代价。比较网络策略时保持任务种子、感知时间、消息必要内容和链路时序相同。on_demand另控制背景推送，因此其收益单独归因为业务流量调整。

这一模型保留最初目标的三个关键接口：端侧节点独立状态、由任务进展产生的交互、应用状态驱动的网络服务。下一步以任务收益定位值得优化的通信变量，再引入更复杂端侧决策。
