## 3. 已冻结的算法取舍与核对项

来源表已给出依据。冻结说明应把“作者原行为”“本项目决定”“验证证据”写在同一行：

1. 正文SOCP的源/转发约束与目的吸收节点处理；标准差系数及ε取值域；共同非负slack；availability按二维行/列双向约束。候选`axis=2`缺陷和现代运行失败保留，不能悄悄改后声称原代码通过。

3. 保留完整`(source,destination,executor)`；源相同、目的不同的两个流必须独立，超过实现容量明确拒绝。
4. 过滤阈值、归一化、u16量化及全零行规则；记录从时间份额到条件下一跳权重的差异。每周期选择并保持，不改成逐包分流。
5. 原缺break循环的多次命令尝试和首次成功条件；本项目一次选择应有独立验证，不能用作者日志次数推断实际路径。
6. 控制原发送者/序号去重、转播、重启边界、seq耗尽、最大整帧和超界拒绝。周期广播、接受配置和所有节点安装成功是不同事件。

## 4. 静态台架的最小证据

下表是用例设计，次数/发包量须由E2和H主卡冻结，不表示已执行。

| 目的 | 配置/触发 | 保留的原始证据 | 判定限制 |
|---|---|---|---|
| 真实身份 | 逐块核USB/芯片/MAC/boot/build；绑定A–E | H绑定记录、启动行、固件hash及分区 | COM号或合成02:00地址不能代替实物身份 |
| 配置去重转播 | 一个新序号、相同序号重送、旧序号；经中继观测 | 每节点原发送者/boot/seq、接受/去重/转播事件 | 单节点接收不代表全网一致；本轮不新增安装ACK |
| 对等单流 | 轮换源/目的/中继，含入口不在业务路径的场景 | source序号、选路周期、实际下一跳、源提交、目的本地RX | 链路回调只算链路；中继RX不算交付 |
| 同源双目的 | 同源分别发向两个目的 | 两个流的独立表、选路和目的接收 | 明确两流上限；第三流拒绝证据 |
| 周期保持/切表 | 在一个500ms周期内发多包，再变配置 | 周期标识、配置seq、route_selected、包序号 | 主机时间与设备时间不混算；实际调度抖动单列 |
| 错误和OLED | 无路由、非法/超大配置、链路失败或显示故障 | 原错误、返回结果、计数与快照；实物屏幕记录 | CMD OK≠交付；源“未确认”不能显示成目的成功 |

无线全互达时，指定经中继的流只验证转发功能；软件屏蔽直达不支持覆盖范围收益。源端缺目的反馈时，由目的本地唯一接收日志统计交付；监测若占用串口/无线，记录带宽及开启方式。RTT需要真实往返关联，不能由双机时钟差或TX callback推算。
