# 随机接入回放

在[8767工作台](http://127.0.0.1:8767/)选择“链路仿真 → 接入回放”。它使用现有网络图和已服务的workbench.js，纯浏览器生成、推进模拟事件，不创建求解job、不读真实邻居或发RF。原“路由仿真与保存包”仍可选择；从旧快捷场景进入会自动选该旧视图。

“示例 C→B→A→D→E”载入一组固定设置；“打乱五板顺序”只换上电顺序，不改方向掩码、成功率和单次覆盖。“下一事件”逐条推进；“播放”加速播放并自动结束；“重置位置”停在开始前；“重播同一组”用同一配置和完全相同事件序列重新播放。组ID、顺序和当前位置在图上显示，没有持续后台任务。

初始五个灰节点、零接收边。C先上电并自启HELLO，B随后上线，其首个HELLO被C收到，画B→C蓝箭头；A再上线，其首个HELLO被B收到。示例A↔C两个方向屏蔽，不画AC直边。D/E使用另设的方向关系，包含单向接收和双向关系，不强制全图互通。

## 接收与互证

只有发送方已上线、接收方在该包发送时已上线、方向允许、在该HELLO覆盖集合内且本包成功，才生成hello_rx并画发送→接收边。ACK同样受反向可达与本包成功约束。上电、自启、广播本身都不等于对方收到。

蓝箭头表示已有HELLO或ACK接收记录。一个节点收到对自己HELLO挑战的有效ACK，只更新该节点的确认；观察合图中的绿色要求两端各有有效挑战ACK，不能因两条相反箭头就标两端互证。单板视角绿色仅表示本板已确认对方。确认窗口9秒、接收记录12秒后按模型超时显示；缺一包不会改掉方向掩码，后续HELLO继续。

“观察合图”合并全部模拟接收记录，属于模拟观察者的汇总，不代表某块板知道全网。“单板A–E”只显示该板可见的上电/发送/接收日志与入向接收边；其他板只有被本板听到后才标已知，否则显示“本板未知”。图下最近事件也按同一视角过滤，不显示远端独有事件。

## 方向与每次广播

展开“方向与单次广播设置”。可逐方向设置是否允许和每包成功率；可“采用当前草稿方向”，只复制20方向的连接/成功率，原路由草稿和故障窗口不变。即使采用全连通掩码，开始前仍没有接收边。恢复示例方向不改当前上电顺序。

单次HELLO按`发送节点:序号`选择，可勾本次覆盖接收方，也可指定仅本包漏收。覆盖仍受方向和上线时间限制；ACK是回应，不属于这个广播覆盖集合。比如让B:1对C漏收、B:2覆盖为空，B后续HELLO仍可被C收到；它们不使BC永久不可达。重新构建设置会停回开始前，生成新的冻结事件组。

## 模型与绘制分开

workbench.js中的`JOIN_REPLAY_MODEL_BEGIN/END`段提供`window.JoinReplayModel`：

- `example()`：返回可复制的示例配置。
- `shuffle(seed)`：五节点全排列；顺序seed与packet_seed分开。
- `create(config)`：生成可序列化组ID、上电时刻及有序事件。
- `stateAt(replay, count)`：归约指定前缀，返回在线、接收边和本地确认记录。

该段没有DOM、fetch或计时器，可单独在Node VM使用。`JOIN_REPLAY_VIEW_BEGIN/END`段负责现有SVG、控件、视角过滤、日志与有界播放。route-view.js在接入视图让出图和状态文字；旧规划响应不能把接入图覆盖成满图。离开视图或页面会停播放。

本模型用字母节点、每3秒上电一节点、持续2.2–2.7秒抖动HELLO、固定20ms传播与10ms回应处理、独立确定性包成功抽样；未建模真实RF竞争、空口帧时长、USB、组认证或完整固件。它是因果接收过程的演示，不是RF测量、论文性能或固件逐指令复现。真实发现实现和实板记录分别见E1-024/H-014。
