# 共同消息服务与固定业务回放

2026-10-25，E2-005。已实现供因果执行器共用的应用字节服务，完成10项标准库测试和6次固定消息目录回放。当前结果显示：这个9节点、15任务样本的突发会使接近平均生成负载的FIFO产生明显等待。任务是否因此受损，需要使用E1闭环结果判断。

## 1. 接口与记账

入口为[message_service.py](../../simulation/message_service.py)，仅依赖Python标准库。

```python
service = MessageService(mode="fifo", delay=0.0,
                         rate_bytes_per_time=4096,
                         capacity_bytes=65536, overhead_bytes=0)
message_id = service.submit(now, source, recipients, kind, payload_bytes, key=None)
next_time = service.next_event_time()
deliveries = service.pop_due(now)
stats = service.stats(now)
```

`submit`提交不可变`bytes`，在容量不足时仍返回ID。`ledger`保留生成需求、完整正文的hex及SHA256、接纳/拒绝、服务开始/完成和逐接收者交付。`key`目前只作元数据，不替换消息。重复接收者去重；空接收集合报错。E1将来源节点自身状态直接写入本地缓存，接收集合排除来源；服务若收到显式自发自收请求，仍正常计费。

FIFO只有一个共享服务器。对接纳的消息j，正文与配置开销合计为b_j，生成时刻g_j、开始时刻s_j、结束时刻f_j满足`s_j=max(g_j,f_previous)`、`f_j=s_j+b_j/r`，交付时刻为`f_j+delay`。同刻按提交调用顺序排队。新提交先处理该时刻及以前的服务事件，因此先释放已完成消息，再判断接纳。调用`pop_due`的频率不改变服务结果；它仅返回已完整到达、尚未取出的正文。`next_event_time`也可能指向内部服务事件，此时`pop_due`可返回空列表。同刻新提交的instant消息可以再次取出。

| 对象 | 本次实现口径 |
|---|---|
| 缓冲容量 | 等待消息与正在发送消息的**完整**b_j之和；部分发送不释放存储，发送完成才释放；传播阶段不占该容量 |
| 溢出 | 完整消息尾丢弃，原需求、拒绝原因和未满足接收集合均保留；没有自动重试 |
| 广播 | 一条无ACK广播只计一次b_j，各接收者的正文可见分别记录；不把接收份数乘作发送字节 |
| 截止H的费用 | 完成消息的全部字节，加正在服务消息截至H已发送的部分；已排程但尚未服务的字节不预收费 |
| 库存 | 等待、在服完整缓冲、在服剩余工作、传播和未取交付分列；拒绝不算pending |
| 交付 | 正文已在接收者可见；不自动等于被任务消费、及时有效信息或任务完成 |
| 单位 | 实际序列化应用字节加显式配置开销；时间沿用作者模拟单位，没有秒/米校准；不是MAC字节或无线空口时间 |

`stats`包含`demanded/accepted/dropped/pending/delivered`消息数、`recipient_demand/recipient_delivered/recipient_unmet`接收需求，以及需求、接纳、拒绝、已完成服务和截至H已服务字节。`by_kind`分列`self_state`与`task_scene`等类型。已交付延迟的均值/p95按每发布消息一票计算，本样本每条均有8个接收者，因此与按接收份数加权等价；变化接收集合的后续实验须另报告接收者口径。

`instant`和`fixed_delay`忽略容量与串行服务约束，所有提交都接纳；前者即时交付，后者只增加固定传播时间。它们是资源放宽的信息归因参照。当前FIFO属于显式应用服务诊断，未实现同授权容量的L0、碰撞/重传/多跳的L2或接收者异质丢失。

## 2. 解析检查

[test_message_service.py](../../simulation/test_message_service.py)的10项测试全部通过，其中5个解析例为：

1. 两个10字节消息在0同时生成，服务率10、传播0.5：完整到达时刻分别为1.5和2.5，发送总量20字节。
2. 8字节正文加2字节开销、两个接收者：发送10字节，接收应用字节16；重复接收者不重复交付。
3. 容量10、服务率10：首个10字节消息在0.9已发送9字节但仍占完整10字节，后续1字节被拒；在1恰好完成后可接纳新10字节，传播不占缓冲。
4. 两个10字节消息、服务率10，在H=0.5只计已服务5字节；在服剩余5、排队10，尚未交付的3份接收需求仍在账。
5. instant在同刻先取出再提交仍可再次取出；fixed_delay=3的消息在2生成，必须等到5可见，容量0不改变这两个资源放宽参照。

其他检查覆盖取消息频率不变性、同键事件不覆盖、无效输入与零字节、自发自收、未取交付及100次固定随机输入的需求/服务/库存守恒。原始日志和源码快照在[验证目录](../../simulation/results/2026-10-25-E2-005-service/20261025-01-verification/manifest.json)，测试退出码为0。
