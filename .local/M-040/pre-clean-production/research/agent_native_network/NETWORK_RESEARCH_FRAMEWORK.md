# 动态多跳网络服务与扩展成本研究框架

2026-10-29。研究目标是在固定业务与计算条件下，提高移动无线网络的及时多跳交付能力，并量出为此付出的维护、竞争和状态成本。近期先做网络损失诊断，再比较一项可执行协议改变；模型业务验证与网络机制研究并行推进。

## 1. 研究问题与固定条件

移动、加入退出和局部分区会改变可用路径。即便物理接触允许传送，节点也可能因路由记录陈旧而等待或反复发送；即便下一跳可用，队列热点和共享信道竞争仍可能使消息过期。提高维护频率可以缩短部分等待，也会占用业务所需空口。需要回答的问题是：**利用局部且有年龄的网络信息，怎样以有限控制费用维持及时交付，收益在什么负载、密度和变化速率下消失？**

每条输入消息固定源、目的、签发时刻、正文byte、有效期、优先级和类别；请求与回复分别记账。各方法使用相同轨迹、加入退出、计算时延、模型/提示和消息生成记录。首轮用一个预定汇聚目的、多源消息检验恢复与竞争，之后再扩展固定多目的业务。源目的选择、正文压缩、推理加速、卸载和机器人任务路线不作为首轮优化量。

网络在线策略读取本地队列、发送/接收反馈及实际到达的邻居公告，决定路径维护、下一跳和入队服务。真实全图、未来接触及全局队列只供离线诊断。业务图说明消息关系，物理图说明无线机会；成功服务还取决于半双工、干扰、争用、重试和接收缓存。

## 3. 网络服务与费用模型

完整状态及ACK边界见[网络模型](network_focus_20261029/NETWORK_MODEL.md)。消息在源/中继保留尚未交付的唯一正文职责Q，成功转移S减少上游并增加下游，删除X按到期、溢出、故障等互斥原因记账。目的端吸收交付D，不继续积累转发队列：

\[
Q_i^k(t+1)=Q_i^k(t)-\sum_j S_{ij}^k(t)-X_i^k(t)+\sum_j S_{ji}^k(t)+A_i^k(t),\quad i\ne d_k.
\]

内部转移求和后消去；初始职责加累计接纳应等于剩余职责、交付与删除之和。离线但存储保留的设备仍在记账域。已交付分片不等于完整消息成功，整条消息须在有效期内完成重组；窗口末未决单列。

Q是唯一正文职责，不是所有实际缓存。ACK丢失时，接收可能已成功，发送方仍持有未确认副本Z；重传去重后不再增加唯一交付，发送尝试继续付费。缓存约束包含Q、Z、去重/重组和待发帧；首轮未确认分片固定下一跳，若以后跨下一跳复制，则补显式副本状态。线上策略不读取离线唯一职责标签。

普通Wi-Fi的DCF/EDCA执行争用、退避和重试；上层选择入队和下一跳，不免费决定全局并发链路集。数据、路由/探测、ACK和所有失败重试按实际attempt计空口，捎带控制字段计帧长增量。控制消息也占用同一信道和队列。全网发射时长之和与局部CCA busy区间并集分别报告，空间复用时前者可超过实验时长。byte、byte/s、秒、byte·s和焦耳分别使用。

## 4. 先诊断，再选择一项候选

首先固定业务/轨迹/无线栈，记录消息签发、队列、路由状态及年龄、公告、每次发射/ACK、唯一接收和到期。离线可行时空路径只作受有效期与链路服务约束的诊断上界；拓扑图连通不足以判断截止前可交付。损失重叠时使用预定主分类顺序，并另给多标签结果。

| 诊断证据 | 下一项机制比较 | 决策依据 |
|---|---|---|
| 可服务路径存在，但本地路径未知/陈旧，错误下一跳重试与修复等待明显 | 候选A：有控制预算的局部路由探测与修复 | 在同成本下缩短中断，或在同交付要求下少维护；和CTP式自适应维护、周期/事件维护比较 |
| 下一跳持续可用，队列/热点及拥塞丢弃主导，可用替代路径闲置 | 候选B：BCP启发的拥塞感知转发与服务 | 固定维护方式及付费邻居状态，检查热点缓解、低负载等待和弱流代价 |
| 有效期内无可服务接触路径，或所有替代共享同一饱和瓶颈 | 先报告物理/服务边界，检查存储转发适用性 | 不以更频繁维护解释全部损失，不在没有机制作用空间时扩大候选 |

A是首个设计原型，尚未由实验选定。它沿同一ETX策略和固定队列规则，使用连续失败、梯度不一致及有业务时的状态老化合并触发局部ADV；邻居表/反馈条目和每节点待发ADV均有上限。无反向样本时链路代价保留unknown，不能用全图真值补全。

每节点用容量σ_i秒、补充率β_i秒/秒的令牌桶门控ADV发射。固定长度的无MAC ACK广播先预留有界空口成本，再实际发送结算；无令牌时合并等待。对登记节点，候选ADV的累计发射满足`C_ADV(T) ≤ Σ_i(σ_i+β_iT)`，动态加入及重启初始额度一起计费。该性质来自令牌记账，是可检验的预算约束；交付、恢复时延和数据稳定仍需另测。

候选A的失败条件是：同控制成本下没有改善服务—成本曲线，或少维护换来更长尾部中断/更多过期；B则检查拥塞收益是否抵不过状态传播和低负载等待。参数扫描给所有方法相同开发预算。原CTP/BCP跨平台移植未完成时标“启发实现”；完整系统比较保留ACHORD/MOCHA的可靠、限速和机会交换能力。

## 5. 实验顺序与下一有限步骤

下一步是[有限网络诊断合同](network_focus_20261029/NETWORK_EXPERIMENTS.md)的实现检查：复用ns-3.46入口，核本地路由/队列反馈接口，补逐包Drop/Queue、CCA和控制费用事件。AODV原入口已运行，OLSRv1模块与新增追踪仍需新任务适配、构建及核对。对照按固定版本实现命名；其缺失的可选能力不等于原协议没有该能力。

建议下一执行任务采用以下有限合同，当前实验数仍为0：

| 合同项 | 建议内容 |
|---|---|
| 规模/业务 | 8无线节点，实际模型端点N_A=0，业务源S=2；两行四列梯形布局，0→3和4→7两流。固定512B应用报文，正文与元数据分别记，2秒期限；每流2或200对象/s，额外相同1Hz恢复探测计费 |
| 无线 | 单信道36/20MHz、16dBm、802.11a DCF、数据/控制6Mbps；Friis+125m工程截止，后续另做无硬截止/遮挡敏感性。MAC实际决定竞争与交付 |
| 三种场景 | T0静态；T1单中继离开后返回以观察替代路径；T2两中继同时离开再返回以形成工程分区。轨迹和时刻详见实验合同；不模拟设备加入退出 |
| 方法与重复 | 原生AODV、OLSRv1各自完整默认维护，共同有界FIFO/源pacing；3场景×2路由×2负载×3网络seed，共建议36次启动，失败占名额，无额外smoke/补跑 |
| 首两项门槛 | T0低负载seed0先做两路由；每法至少一次完整交付有实际多跳证据，费用和终态可重建，才进入剩余34项 |
| 资源/停止 | 每次90秒模拟、≤60秒墙时，累计≤2160秒；一次增量构建≤600秒、≤4编译作业，模拟串行；每run≤512MiB、总≤8GiB。任一构建、超时、核验或资源上限失败即留证停止，未执行项明确标记 |

36次是下一任务建议上限，需要新执行卡明确授权、路径与资源；本轮没有启动或消耗其中任何一次。两个负载档未实测标定，不保证高档拥塞。3个seed只表示固定几何内的无线随机重复，首轮报告逐run值、差异及失败，正式统计另按独立拓扑/轨迹块设计。不同协议同seed也不保证逐包经历相同随机事件。

这一步只诊断成熟协议，不实现候选、不判新方法获胜。两固定目的与候选A的首轮单汇聚是不同合同：若维护损失支持A，下一卡将两源改为0→3、4→3，所有基线与候选在新业务上重新配对，不能把36次诊断的旧分母直接用于宣称候选增益。若拥塞主导则转B；未发现稳定损失也是可接受输出。

诊断后只实现A或B一个候选。网络比较固定消息源、轨迹、PHY/MAC、缓存及重试；先做小型多跳恢复/拥塞，再分开固定面积加密和固定密度扩区。控制量、端点数与纯中继数、总/每端点到达率分别冻结；计算不随方法增加。未来真实模型轨迹作为共同输入验证外部适用性，随后才研究消息到达改变应用行为的反馈。

主指标为全部签发消息的及时完整交付率、有效goodput=`8×唯一有效正文byte/T`（bit/s）、恢复空窗与控制/总空口；同时给拒绝、丢弃、到期、窗末未决、成功包尾时延、每节点缓存和状态条目。模型内部byte/byte·s口径保持，图表转换显式乘8。恢复持续服务预定为连续3个1Hz探测均按期到达，首次成功另报。单位有效服务费用为发射空口秒/有效bit；零服务报告无有效服务及总费用，不记费用0。独立拓扑/轨迹块重复，给不确定性及未恢复场景。经验服务域由固定质量、成本、中断阈值定义；到期清队列不能当稳定性证明。
