# 可扩展性主问题的证据与研究位置

2026-10-25，D-005。输入为用户[19页综述](../../../任务感知网络调度_新版文献综述_论文原图版.pdf)、[前轮原文核查](../framework_20261025/LITERATURE_FRONTIER.md)及定向复核的原论文。本轮只做分析，未运行实验、修改代码或历史结果。

## 1. 从信息延迟诊断转向网络扩展性

主问题是：**节点、协作关系和数据负载增长时，怎样通过网络机制维持有效交付，使增加团队能力仍能带来相称的任务收益？** 状态更新触发与消息发送调度是当前可实施入口；MAC、PHY、路由及跨层联合优化仍可根据瓶颈进入。

研究模型应让网络服务随共同负载和控制动作变化：产生/请求消息改变队列；并发发送和链路条件改变可用服务；退避、重传、路由与过期处理改变交付时刻和成本；已送达信息再影响任务动作及后续流量。固定延迟或独立丢包可以作为归因对照，不能独自支撑这条规模—服务—任务链条。采用有限共享队列时，至少已内生化排队；若争用和重传仍未建模，应继续注明服务模型的这一层范围，而非把所有时延都称为无线拥塞。

规模应分开描述为节点数、实际信息依赖关系数、状态变化率、每次更新字节、观测/结果请求率及通信资源。全互联单播可能使关系与发送量接近平方增长；有界邻域、广播复用和空间复用会改变该关系，不能先写成普遍的 $O(N^2)$ 通信结论。固定区域加密、固定密度扩区，以及固定总任务、固定每节点任务必须分别比较。

这是本项目的模型与评价要求，不是对全领域的缺失判断。现有工作已经包含排队、竞争、失联、反馈和资源调度，新的贡献需要落在明确机制、算法、理论性质或性能—成本折中上。

## 3. 真实需求、自治部署与网络问题的证据层次

| 证据 | 可以支持的需求/能力 | 在本项目中怎样使用 |
|---|---|---|
| **实际救灾：DRZ 埃森住宅火灾**，[2022报告 §IV-C、§V](https://arxiv.org/html/2212.09354v1) | 无人机外部视角辅助地面机器人操作员；点云辅助功能依赖 Wi-Fi，文中估计该次建筑内约70%时间质量足够。现场有人操作，并未部署自主航点导航等更复杂辅助功能。 | 支持“辅助观测到达后改变行动”和复杂建筑通信间歇性。把操作员换成自主决策器是研究设计；该个案不是已证实的大团队负载拥塞曲线。 |
| **自主腿足/空中系统的实地验证：CERBERUS**，[2022技术报告 §3.1、§3.3–3.6、§5.1](https://arxiv.org/html/2207.04914v1) | 腿足与飞行机器人有自主探索、导航和多机器人建图，并在 SubT 实体场地运行；整体采用单人监督自治，离线探索后返回报告。 | 支持自主异构节点和间歇协作的可行性。它是比赛/验证部署，不等同于实际灾害救援；自治可减少持续连接需求，也是网络方法必须纳入的合理基线能力。 |
| **现场网络机制：ACHORD**，[v1，2022-06-05，§III–V](https://arxiv.org/html/2206.02245v1) | 已有数据分层、per-topic 队列/ACK、Selective Repeat ARQ、令牌桶限速、队列反馈、通信感知移动与可投放中继；系统分析覆盖最多6机器人和13中继。 | 可作为重连积压和共享带宽的强系统起点。Fig.8 的跨日比较不是严格配对消融；失联区间不作包时延，已有缓解后尚余多少任务损失需在本项目测量。 |

据此，研究可以围绕异构自主设备的协作网络展开，而无需先宣称“真实灾区已经出现大规模自主机器狗拥塞”。应用证据确定消息的生产者、消费者和任务后果；扩展性结论由受控负载、原协议及后期无线/设备验证共同提供。

## 4. 五项主要研究机会

下表均为待验证方向。相同问题、相同假设下取得更好算法、复杂度或成本折中即可形成贡献；增加模型复杂度本身不是贡献。

| 机会与优先级 | 机制改进及最贴近的对照 | 需要建立的证据 |
|---|---|---|
| **1. 负载反馈下的更新准入与消息服务（主线）** | 在决策触发之外，用本地积压、已获服务和过期风险调节更新/请求强度，并与任务消息服务联合；对照 CoSMO、AC-DMTA、ACHORD 式限速和充分调参的周期/事件触发。 | 相同任务策略及资源下，单独触发、单独服务和联合机制的曲线；更新带来的收益是否超过其挤占成本，队列/丢弃/有效及时交付怎样随节点、关系和负载变化。 |
| **2. 多接收者与互补数据的实际交付价值** | 在 AutoCast 多接收者广播和 C-MASS 集合选择基础上，将接收集合、预计到达时刻与链路/重传代价纳入发送安排；广播一次的资源占用与多个接收者的收益分开计量。 | 共同感知任务中比较原排序、服务感知排序和小规模精确参考；测已到达但无用途、缺少互补数据和有效多接收者交付。组队能力约束不自动等同于感知互补。 |
| **3. 调度依据的取得与维护成本** | 比较按需/增量元数据、证书复用、局部近似估计及反馈周期；直接对照 C-MASS 低开销估计、AC-DMTA 证书、CommHG 缓存和 MOCHA 头部同步。 | 在估计质量、计算时间、控制字节及估计过时之间建立可复核折中；所有方法只能读取已获本地信息，不用免费全局状态给候选方法评分。 |
| **4. 重连时的积压、更新替代与重传安排** | 在 MOCHA 最新状态及 ACHORD 分类/限速/ARQ 基础上，对可替换状态和不可丢失任务事件使用不同恢复规则，联合接触预算、发送顺序及重试。 | 分开测覆盖失联、重连瞬间负载和持续高负载；统计重试服务占用、恢复时间、事件完整性和任务等待。增量预约/撤销不能随意套 latest-state 丢弃。 |
| **5. 规模增长时的求解成本与可证明性能** | 以 Reoptimized MGF 的重优化/简化版本为起点，研究局部价格、有限候选和低成本近似；同原模型先检验改进，再推导含服务约束版本。 | 固定资源与同比资源分别给任务效果、计算/控制成本；理论必须写出容量、信息和随机性条件。全知贪心只作诊断，只有精确最优或方向正确的求解器界才能作为界限。 |

主线优先做 1，并把 3 作为实现成本的一部分；2 需要兼容的感知任务，4 检查动态恢复，5 为算法收敛后的理论与复杂度工作。这样可以集中贡献，同时保留底层机制入口：若主要损失来自争用或重传，就进一步控制接入/重试；若来自空间瓶颈，再研究路由或无线资源分配。

## 5. 现有证据怎样接到下一阶段

E1-003 的固定轨迹延迟诊断说明策略对已获信息敏感，尚未测出网络负载导致的任务损失；D-004 的双进程回环证明原 MOCHA 同步路径可执行，成功应用包字节尚不是空口成本。它们分别支撑因果任务闭环和协议接入。[当前证据与限制](../../../coordination/reviews/M-004-interpretation.md)

下一阶段的证据链应为：在同一因果执行器中增加节点/关系/真实用途数据需求，记录共同网络服务如何变化，检查哪些消息未及时有效送达，再追踪到等待、重复投入、失败/超时或 makespan。可控固定服务作为解释参照；负载驱动服务作为扩展性主实验。排队、接入失败、重传、过期及接收端未消费需分别记录，不能把“已提交发送”合并成“已有效交付”。
