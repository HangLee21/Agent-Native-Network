# 从实际任务到网络实验：多态协作的需求依据

2026-10-26，D-006。当前研究对象是多种设备、能力与协作方式组成的自主团队如何扩展。以下先说明任务需要哪些信息，再给出可执行的测量约定。算法仍按测得的主要成本选择。

配套机器可读约定：[WORKLOAD_CONTRACT.json](WORKLOAD_CONTRACT.json)。本轮核查4项一手来源，未下载ROS bag，未运行新的任务或无线仿真。合同是待实现的工作负载接口，`execution_ready=false`；不是已完成场景或可直接启动的仿真配置。

DRZ §V还直接给出扩展需求：先概览、再多次空地详细勘察的工作流程，需要面向更大区域自动化多个小型无人机的数据采集和处理。这是作者从部署总结的需求与展望，支撑本项目选择“区域和并行任务扩展”作为输入；原文没有给出自主大队的网络失效曲线。

这四项证据分别说明外部视角、地图交接、断连回报和能力分工的用途。设备数、任务量、区域与关系变化的扩展实验属于本项目拟议研究，不作为上述现场已有结果。

## 2. 三条工作流及其可测对象

### W1 空中观察辅助地面核查

**来源事实：** S1、S4的外部视角确实被地面操作方使用。**拟议适配：** 以地面设备上的决策模块替代人工消费者；必须另行规定可读取的观测与回退策略。

- 生产者：能看到目标区域或地面设备周围环境的空中观察者。
- 消费者：正在执行该区域核查的地面设备；原部署中的消费者是其操作员。
- 信息对象：有来源、观测时间、坐标系和区域范围的画面/几何结果；具体编码与字节由选定数据或序列化器实测。
- 消费动作：更新路线、进入选择或核查目标；日志记录使用了哪个信息版本及动作。接收本身不等于消费。
- 需求变化：发现新目标、核查区域切换，或设备因可达性改变而接手。需求由任务和可见性事件产生。
- 扩展问题：同时核查更多区域时，信息应交给谁、关系更新需要多少开销、已有广播/订阅是否仍合算。
- 回退语义：缺外部观测时可继续本地可行行动或等待；由共同任务规则决定，不预设“没有一条消息必然失败”。不人为添加安全期限。

### W2 局部探索成果交接与探索区域重分配

**来源事实：** S2的局部子图先到中央节点，被对齐和合并后用于选择下一探索区域。**拟议适配：** 去中心化接收者可以是邻域协调节点或实际接手区域的机器人；此改变需独立实现并计费。

- 生产者：执行局部探索、得到新地图内容的设备。
- 消费者：原工作流中的中央协调器，以及收到新探索目标的设备；拟议分布式版本按实际消费关系定义。
- 信息对象：子图、坐标变换/版本依赖、前沿摘要与分配结果。摘要不能自动替代地图对齐所需正文。
- 消费动作：合并已知区域、消除已探索前沿、重新选择探索位置。保留持续局部自治能力。
- 需求变化：新区域被观测、地图对齐更新或机器人完成当前区域。相同场景几何下，需求数量由各策略实际探索决定，并与共同区域覆盖目标一起评价。
- 扩展问题：扩大待探索区域或增加并行探索设备时，子图数量、前沿重叠和交接对象如何变化；图维护和实际转发是否仍带来相称任务收益。
- 可用原参数：45秒/20米仅用于明确复现S2生成规则的配置。当前HeteroMRTA时间未映射到秒，不能直接填入其200时间预算。
- 待测量：选定编码的子图字节分布、几何与位姿来源、对齐依赖和处理耗时。不得通过重复填充无用途字节制造负载。

### W3 探索后的接触恢复与发现回报

**来源事实：** S3支持局部探索、离开覆盖、积累业务、返回或经其他机器人回报。**拟议适配：** 在相同探索规则和网络配置下，对比数据分类与恢复策略。

- 生产者：在本地探索期间产生地图、目标发现和状态变化的设备。
- 消费者：需要这些发现的基地/任务管理者，以及承担后续探索或核查的设备。
- 信息对象：可替代状态、需保留的发现事件、带前序依赖的地图增量，分别定义合并和可靠交付规则。
- 消费动作：登记发现、分派后续任务或继续建图；确认包仅表示协议进度，不替代正文消费。
- 需求变化：区域拓展产生新发现；真实轨迹与无线模型产生接触变化。人工规定的断连时间只可用于单独的机制诊断。
- 扩展问题：更多设备从不同区域返回、任务继续推进，历史积压与当前协作需求如何共同获得服务。
- 比较基础：已有分类队列、合理限速、可替代状态合并、事件重传和恢复规则。记录等待及所有发送尝试，再检查主导损失。
- 任务语义：默认无额外消息deadline；报告发现到登记的时间和任务后果。若应用后来明确要求及时报告，单独增加有来源的要求。

## 3. 从需求到实验的固定顺序

1. 固定任务目的、区域/对象与设备能力，列明各业务的生产者、消费者和消费函数。
2. 固定消息语义与编码，先记录实际生成字节和依赖。设备类型数、真实角色分工与信息模态分别记录。
3. 固定无线硬件/频谱、PHY/MAC、重试、路由和基础设施配置。队列、竞争、交付、重连积压由任务和网络执行产生。
4. 分开改变并行任务数、队伍数、探索区域和角色构成。固定区域加密与固定密度扩区，固定总任务与固定每节点任务分组。
5. 在相同任务目标、资源及调参口径下观察完成、等待、维护成本和有效消费。既有机制已满足要求时，比较成本与计算代价；不额外插入失败条件。
6. 由主要成本选择协作关系维护、需求传播、任务事件同步、调度或底层接入方向。AVUS为候选，不决定工作负载内容。

不能同时改变设备数、地图面积、任务量、频谱和截止时间后，把差异统称为“规模效应”。新增设备带来的感知/计算能力和新增通信负担要同时保留。

## 4. 对现有HeteroMRTA适配的映射

静态源码核对基于 `simulation/heteromrta_causal.py`。现阶段可复算的是真实到场组队、意图/现场事件和实际缓存决策；现有原任务不能直接充当W1–W3完整实例。

| 当前实现 | 能复算什么 | 需要后续明确的需求 |
|---|---|---|
| `LocalView.__init__` 向所有节点提供完整catalog及初始状态 | 已知任务/能力下的协作状态维护 | 新任务发现、能力发现或接手协商若进入研究，必须实现消息取得及计费 |
| `publish` 发送给源以外所有节点 | 源广播次数、实际序列化字节、接收副本 | 全体接收是当前协议规则，不能直接当作实际任务都需要这些内容 |
| `observation/planned_tasks` 遍历任务与节点缓存 | 版本进入特征和分支的条件 | 特征读入只能说明读取路径，需消费事件或受控干预才能判断具体作用 |
| `self_state/task_scene` 发布意图和现场任务阶段 | 状态变化与协议流量的来源 | 无地图正文、画面交接或协作请求，不能据此量化感知数据需求 |
| 现场满足能力后开工 | 原任务的能力互补约束 | S1/S4中的视角辅助不等价于多机器人同时到场；应用适配须分别建模信息依赖与物理组队 |

当前最小可执行工作是E1-005对现有归档的需求与成本复算。下一工作负载可先补一个有消费函数的W2或W1适配，再在共同硬件/协议配置下扩需求。参数尚未取得的部分保留空值，不能借用原FIFO档位当作真实无线容量。

## 5. 工作负载合同与数量依据

[JSON合同](WORKLOAD_CONTRACT.json)固定以下记录层次：

- 场景事实：区域、物体、能力、传感器与外生事件来源。
- 信息需求：由谁在何时为哪项动作需要哪个对象；即使没发送或没满足也保留。
- 消息与协议：生成、接收对象、编码字节、依赖、入队、每次发送、正文交付、ACK及移除。
- 消费与任务：接收端实际使用的版本、消费动作、回退行为、任务完成与失败。
- 扩展配置：资源不变项、单一需求变化项、随机种子与调参/留出集合。

节点只读本地观测和实际交付缓存；评估器可以读取场景真值以计算共同目标。固定回放使用共同需求目录；闭环中各方法可产生不同请求和消费时刻，要同时报告共同任务结果与各自需求数量，不通过少请求提高满足率。

本轮没有从文章补齐消息大小、每秒状态率、无线速率或有效期。原文明确的45秒/20米子图规则仅登记在S2原场景。TRADR的ROS bag入口尚未下载验证，后续应读取topic、编码和时间戳后再形成数据负载分布。
