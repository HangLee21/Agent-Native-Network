# M-031 充电宝供电的独立 AD-HOC 节点

## 五块板全部独立供电，笔记本以 Wi-Fi 收发

现场目标是五块板各使用一个充电宝，笔记本到任何板均无 USB 数据连接。USB 仅用于出门前烧写、配置或事后维护。笔记本的 Realtek 热点能力已有系统查询记录，板端普通 Wi-Fi/IP 与 ESP-NOW 同信道共存依据 https://docs.espressif.com/projects/esp-faq/en/latest/application-solution/esp-now.html ；本机双向闭环尚待实测。

- 五板运行同一固件。每块板独立尝试在组内业务信道接入 2.4 GHz 热点，与笔记本应用双向握手后成为有效入口。允许零至五个并发入口，各自维持有期限的注册（gateway_id/PC会话、板MAC/boot），即使一块板掉线也不清除其他注册。固定入口 MAC 和人工切换不作为配置前提。热点重连限速，避免扫描长时间打断 ESP-NOW。
- 上行以稳定的 PC 逻辑 ID 为目的。本板已直连则直接交 PC；否则以有界、去重的服务发现查找可达入口（例如按需请求、有效入口分别应答，数据包只走选定路径）。按证据仍新鲜、路径跳数、稳定平局规则定序，保存短期候选；入口失去 PC 租约与 ESP-NOW 邻居失联分别处理。后续新包改用有效候选或重新发现。没有可用出口明确报告 PC 暂不可达，板间业务继续。
- 下行目的板若已有效注册可直接经 IP 收件。其余情况由 PC 从在线入口取得到该目的的有时效可达证据，缺证据时执行有限路由查询，再选一个有路的入口发送；板端计算各自的多跳路。入站刚走过某入口仅作线索。上下行可经不同入口；保留原逻辑消息标识跨入口/跨尝试，在最终收件处限时去重，交付不明时不得因改入口盲目重复投递。测距用例按 Wi-Fi 直达、ESP-NOW 单跳及多跳分列。
- 区分 PC 业务端地址与入口 STA MAC。PC 有独立发件和收件接口/逻辑身份；经入口发送时板上路由仍以入口 MAC 寻路，记录映射。回程可以由远端主动发给 PC，业务携原始源身份和事务号，入口去重后交 PC；源端受理、目的板实际收件、PC 实际收到分别显示。公共 API 明确跨网封装有效载荷上限；不静默截断、不把整帧通过热点绕送。热点凭据在本机配置，不入仓库或采集日志。
- 网关地图继续使用现有现场图；远板可通过 AD-HOC 路由向当前入口限频发送带来源/年龄的观测摘要，入口交网关；回传受空口预算约束。无线业务、遥测与确认单独计数。断开 PC 热点后，现场图标记过期，五板业务继续；无数据连接的节点不会凭空显示为在线。
- E1-027 补入口双向协议与限频远端报告；E2-029 做 PC 无线终端及与现场网关的适配；D-028 接 PC 发件/收件 UI；H-017 接真实热点/板间双向场测；C-030 核零USB、热点丢失与两端原字节。成功证据包含 PC→远板、远板主动→PC 和 PC 离线期间远板→远板三类，分别记录物理供电和可用板数；单板 IP 回显不计多跳成功。

多入口验收以实际拓扑为准：观测至少两个入口同时注册，远端热点不可达时验证双向多跳，令当时使用的入口单独失去 PC 连接（仍保留板间无线），记录下一个新包经另一个可达入口送达、恢复耗时及最终收件份数。再撤掉全部入口，核板间业务继续。D 展示各入口在线状态、每条消息实际经过的入口及依据、收件端和未确认状态；管理页可提供调试入口指定，但正常发包不需用户选择入口。

用户已明确授权正式多入口固件完成后烧写全部 A–E 并实测。H 独占烧写，按实际芯片 MAC、镜像和回读身份逐板记流水；可先执行已识别板，不因第五块未枚举而搁置其余。当前 M 只读 Windows 枚举见 COM13/8/16/15 均状态 OK；H 上轮相应识别为 B/C/D/E，剩余 A 待接入。E1/E2 发布后请 H 接着执行，完成或需现场插线/供电时一次交接，无需再获烧写许可。

双向测试前后分别提交两个不同方向的新消息，记录断链时刻、入口失效、继任入口、首条目的交付和重复/超时。故障前后记录远板无 IP 直连、仍有 ESP-NOW 邻接、其余入口仍在线；如果两个方向原本使用不同入口，分轮撤各自实际入口，再复测。时间用同一侧时基或报告测量误差。业务消息不得用串口注入代替 PC 无线发件或远板主动上行。

A 重新插拔后，M 只读重新枚举 Windows，COM14 已重新出现，CH340 的 ConfigManagerErrorCode 为 0，与 COM8/13/15/16 合计五口。H 已收到更新，芯片身份由 H 读取后记录；枚举不等于烧写或端点通过。

A/C 互换后的实际读取已确定 A=COM8、B=COM13、C=COM14、D=COM16、E=COM15，五块均成功。上一次 COM14 打开报错31的记录保留，这次互换后两口均成功，无法据此归因于某一板或某个口。身份见 [A/C](../../simulation/outputs/H-017/20261109-02-AC-swap-locations/RESULT.json) 和 [B/D/E](../../simulation/outputs/H-017/20261109-03-BDE-current/RESULT.json)。H 的回退镜像与定向断链采集工具已就绪。
