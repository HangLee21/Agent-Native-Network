# M-034 | 用 LoRa 独立回传 Wi-Fi 邻居表

本轮部署结果（2026-11-10）：A 收、B–E 发，五板同一 6f62fc56 镜像，周期 10000ms、433MHz。H-019/11 实测 B 的 128B LRN1 帧含4个 Wi-Fi 邻居；H-019/13 的35秒串口窗口共有9个唯一报告，来源B/C/D/E均到达。H-019/15 五板硬件复位恢复成功，未实际拔电。工作台恢复结果见14b。树莓派安装包 mid_edge-0.4.0-py3-none-any.whl 在 E2-032/20261110-04-release，安装与 API 见 deploy/ubuntu/RASPBERRY_PI_LORA.md。实测板端与树莓派主机测试分别记录。

阶段：用户已授权实际五板部署。A 暂为 RX，B–E 为 TX；同镜像，角色和周期可持久化，A 后续改 TX。现有 8794、五板 AD-HOC 及板内业务继续使用。目标是在 Wi-Fi 观测入口不可用时，笔记本仍能经 LoRa 得知节点在采样时看到了哪些 Wi-Fi 邻居。

## 台架和数据流

五板都保留 ESP-NOW。首轮用 A 的 LR1121 常收、USB 接笔记本，B 的 LR1121 单跳发；同一配置随后可扩展到 C/D/E。A 自身的 Wi-Fi 邻居记录可本地取得，单列来源。五块移动板都需在空口向独立网关发射时，网关端另接一只兼容 LoRa 接收器。台架使用原始 LoRa 点对点帧，多发一收，无需部署 LoRaWAN 服务。

板上定时复制现有一跳邻居表，经 LR1121 上报，无线接收端附加收报时间、LoRa RSSI/SNR，从 USB 输出至本机。每帧至少可识别报告节点/boot/报告序号、采样时刻、邻居条数；每行可关联 Wi-Fi 邻居身份、方向/确认状态、观察年龄、Wi-Fi RSSI（缺测可表示）。优先单帧全表，截断须显式标记。无邻居也发有序号的空表。复用同一份板内状态；报告不参与业务转发或选路。

运行参数 report_period_ms；首轮建议 10000ms、分散起始相位和小幅抖动，按实际 LoRa 参数、帧长和占空情况调整。调周期/节点角色不需要重编译。PC保留最后收报时间与采样时的状态，漏一报只改变参考通道的可见性。旧快照不续现有9秒Wi-Fi互证；对齐报告者boot/邻居及时间窗再比较。网关侧分开显示 Wi-Fi 邻居信号与节点→网关 LoRa 信号。

## 第一个可验收结果

厂商板手册 PDF 第7页标出 LoRa Sub-GHz 为②号 IPEX‑1；①号接 LoRa 2.4GHz。用户正在确认实际天线。若暂时缺天线，相同镜像的安装、设备身份及配置读回可先做；对未确认天线的发送板保持 off，接好再切 tx 并保存。记录实际配置，不能把写入镜像等同空口发送。

B 实际发、A 空口收、笔记本解出带源序号的邻居表；与同时间窗 B 的板内或现有 Wi-Fi 快照对照。单独停止 PC 的 Wi-Fi 遥测接入而保持板间 ESP-NOW 工作时，LoRa 报告应能继续到达。先记录帧长、实际 LoRa 配置、接收间隔、序号缺口、接收 RSSI/SNR；同一窗口可靠取得板端实际发送数后才算按唯一包计的接收率。远距/不同距离、不同周期的对比留待基础收发成立。
